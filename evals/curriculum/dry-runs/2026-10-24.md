# 課題候補生成の dry run（2026-10-24）

入力: 現在のデータセット索引・該当する各 reference の frontmatter と注意点、既存課題30〜44、課題37・39の報告と実行記録、利用可能な手順の name/description。Geo-Voyager v0.1.0 の curriculum は発想源として参照したが、その Goal 生成器や embedding は使用していない。

exploration と digging の種を合計6件作った。6件を硬い棄却と最も単純な解法で検討し、5件を棄却、1件を proposal として残した。これは候補選別の dry run であり、6件の分析を実行したわけではない。

| 種 | mode | 判定 | 棄却理由または残した理由 |
|---|---|---|---|
| アンダーパス閉鎖を仮定した洪水向け避難経路の悪化 | exploration | proposal 1件 | 5データの結合を要し、通常時の距離と閉鎖による増分は別の問い。形式検査 `critic_review`。実データpilotでは23区内のアンダーパス99点、洪水向け避難場所654点を確認。徒歩網への対応は未確認。 |
| 東京都で病院が最も多い区 | exploration | reject | 1データの件数集計と最大値で終わる。病院の定義を選んでも、この問いだけでは高難易度にならない。形式検査でも `no_integration`、`trivial_solver`。 |
| バス停の運行頻度が移動改善に与えた因果効果 | digging | reject | 手元のバス停データに運行頻度と利用実績がなく、処置時点も反事実も置けない。形式検査では `unsupported_variable`、`causal_design_missing`。 |
| 大阪市の高齢者と駅・バス停の交通空白 | exploration | reject | 既存課題39の地域を変えただけ。交通空白の量と意思決定は同じ。表面類似と `geography_only` で棄却。 |
| SDEを使って何か分析する | exploration | reject | 世界についての対象量と意思決定がなく、手法の使用自体が目的。`method_first` で棄却。 |
| 千葉県で道路量と人口を考慮した事故最多メッシュ | digging | reject | 既存課題31の地名だけを変えた形で、過去の失敗を掘っていない。通常の事故件数との比較も同型。 |

残した候補: [proposal](../proposals/2026-10-24-underpass-evacuation.md)、[機械可読の候補](../proposals/2026-10-24-underpass-evacuation.json)。正式な `hard-tasks.md` と `hard-rubric.md` は変更していない。

この回の批評で最も厳しい点は実行可能性だった。アンダーパス点と歩行区間が十分対応しないなら、閉鎖影響の地区ランキングは作れない。候補文はその可能性を隠しておらず、次の本分析では区間対応率を最初の停止条件にする。
