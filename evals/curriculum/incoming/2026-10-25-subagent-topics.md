# GeoAI 調査研究課題の候補（サブエージェント5体による考案、2026-10-25）

作成方法: サブエージェント5体が並行して1件ずつ考案した。各体とも GeoAI-master-skills の research-question-generation（新ゲート形式: social_problem と working_hypothesis を先に書く）に従い、既存の hard 課題30〜44、medium 課題1〜2、タスクカード10件、前日の候補5件（`geoai-new-topic-2026-10-24.md`）との重複チェックを行い、予測を固定してから小さい pilot を実行した。候補 JSON と要約、再現コードは `~/workspace/.cache-geoai/subagent-candidates/` にある（建物候補のみ `building-census/` サブディレクトリ）。形式検査は各体が validate_candidate.py で実施した。

横断する所見: 5件中3件で、pilot が当初の問いの立て方そのものを組み替えた（候補1、3、4）。いずれも「測った量が対象量とずれていた」ことに pilot が気付かせた例で、組み替えの経緯は各候補 JSON の pilot 欄に残してある。予測の外れは消さずに記録した。

## 候補1: 人口が減っても建物が増える自治体 — 人口と建物ストックの乖離（exploration）

- 社会課題: 人口が減る自治体でも建物ストックとインフラは残り、維持・更新・除却の費用は残った住民と自治体財政にのしかかる。人口減少の地図と建物ストックの地図は別々に作られるため、人は減るのに建物は増え続けている場所が分からず、施設集約・空き家除却・インフラ縮小の優先順位が人口減少率だけに頼っている。判断者は自治体の公共施設等総合管理計画・立地適正化の担当と国・県の縮小支援担当。
- 作業仮説: 人口が減少した自治体でも建物面積は減らず、人口変化率と建物面積変化率の乖離の大きさには体系的なばらつきがある。乖離や一人当たり建物面積の増加で並べると、人口減少率だけの順位とは上位が入れ替わる。乖離がほぼ一様で順位が入れ替わらなければ棄却する。
- pilot（GHSL R2023A、30秒角、タイル R6_C32、GHS-POP E2000/E2020、GHS-BUILT-S E2000/E2010/E2020、自治体は jp-admin-2026-09 の1,160件）:
  - 人口 −10% 以上の自治体206件すべてで建物面積が持続・増加。人口 −20% 以上のセル6,414件の99.8%で建物面積が増加。
  - ただし診断で決定的な事実が判明した: **建物面積が少しでも減ったセルはタイル全体で0件**（2000→2010、2010→2020とも）。GHS-BUILT-S の建物面積は時空間モデルの特性で全セル単調非減少であり、「減らない」こと自体は製品特性で証拠にならない。全自治体の建物面積変化率の最小は +0.44%、中央値 +24.7%。
  - そのため候補の対象量を「減らない場所の特定」から「乖離の大きさと順位の入れ替わり」に組み替えた。組み替えであることは JSON に明記し、元の予測が実証されたとは扱っていない。GHS-POP 2020 と国勢調査2020の比の中央値は1.046だが、小自治体では舟橋村で約29%過小など大きなずれがある。
- 形式検査: critic_review を通過（棄却理由なし）。required_variables はすべて実在列。
- ファイル: `ghsl-shrink-mismatch.json` / `.md`、pilot 一式は `pilot-ghsl/`。

## 候補2: 建物ストックと世帯の分布の食い違い — 空き家現地調査の優先地区（exploration）

- 社会課題: 人口減少が進む地域では、世帯が減っても建物は残り、空き家や低利用の建物が市内の特定地区に集中する。自治体の空き家対策担当は現地調査の人員をどの地区に先に回すか決める必要があるが、市区町村単位でしか得られない空き家率統計では市内の集中が見えず、優先順位を付けられない。
- 作業仮説: 人口減少市では、世帯数30世帯以上の1kmメッシュのうち建物棟数／世帯数の比が1.5以上になるメッシュの割合が2割を超え、人口増加市の同割合の2倍以上になる。減少市でも増加市と同程度なら棄却する。比は空き家率の実測ではなく、非住宅建物と検出漏れを含む代理指標。height・confidence（日本の試読タイルで全件 −1.0）には依存しない。
- pilot（Microsoft 建物フットプリント索引スナップショット 2026-08-13、CDLA Permissive 2.0、該当3タイルから173,373件を保持。国勢調査は `yuiseki/estat-census-mesh-2020` 6c486c8）:
  - 銚子市（減少市）: 建物32,966棟、比の中央値2.32、比≥1.5のメッシュ割合 **66.1%**（該当人口16,081人、65歳以上6,067人）。最小世帯数100でも44.1%。
  - 流山市（増加市）: 建物51,110棟、比の中央値0.71、比≥1.5の割合 **14.7%**。仮説の主条件（2割超・2倍以上）は支持（約4.5倍）。
  - 副予測「市集計では差が1.5倍未満に薄まる」は**外れた**（市集計の比は銚子1.466 対 流山0.610で約2.4倍）。候補の根拠は市内優先順位付けに置き直した。留保: 銚子の中心帰属人口は公式値の約89%（沿岸メッシュの取りこぼし）。
- 形式検査: **reject（理由1件のみ）**: `unsupported_variable`（T001140034 世帯総数）。同列はデータセットカードの frontmatter に無く、リポジトリ内に evidence_file にできる既存コードも無いため。列の存在と意味は HF の columns.json と実 parquet で直接確認済みで、pilot は同列で集計している。それ以外の全項目は通過。proposal 化の前にカードへの列追記か再現コードのリポジトリ内配置が要る。
- ファイル: `building-census/building-census-mismatch.json` / `.md`、pilot.py、pilot_results.json、predictions-fixed-before-run.md。

## 候補3: 土砂災害向け指定の欠落と高齢者居住の重なり（exploration）

- 経緯: 当初案の国土数値情報「土砂災害警戒区域データ（A33）」は STAC 目録 mlit-nlftp に実在する（2026-10-25に collections 110件中で確認）が、dataset-discovery の索引にカードが無く、版と列を固定できないため断念した。目録内データで成立する「災害種別ごとの指定の欠落 × 地形起伏 × 高齢人口」に切り替えた。失ったのは公式区域との照合で、候補の中心は「公表登録の欠落と実際の指定の欠落の切り分け」に置き直してある。
- 社会課題: 急傾斜地や谷沿いに住む高齢者は土砂災害で避難が遅れやすく、熱海の土石流のような被害を受けやすい。市町の防災・福祉担当と県の防災担当が個別避難計画や現地確認の優先順位を付ける際、土砂災害向けに指定された避難場所が公表登録に欠けている地域では、優先付けの出発点自体が地図に現れない。
- 作業仮説: 標高差の大きい1kmメッシュに高齢者が住む市町の中には、種別不問の最寄りの指定緊急避難場所は近いのに、土砂災害向け指定の場所が公表登録に無いか遠いメッシュがまとまって存在し、高齢人口で万人単位になりうる。土砂向け指定が最寄り場所と同程度に届く市町が大半なら棄却する。
- pilot（国勢調査2020 6c486c8、指定緊急避難場所 d8ad216（2026-10-06取得）、GSI標高タイル z14、jp-admin e6c87b1。対象は熱海市の高齢居住メッシュ44件、65歳以上15,411人）:
  - **熱海市の指定緊急避難場所の公表登録は市全体で6件のみ、全て津波専用で土砂災害向けは0件**（洪水・地震向けも0件、指定避難所は12件）。対照: 伊東市37件（土砂向け28件）、伊豆の国市86件（同66件）、湯河原町60件（同22件）。全国115,872件中、土砂向けは67,444件（58.2%）。
  - 最寄り距離の中央値は種別不問で約1,456m、土砂向け指定では約3,532m。土砂向けまで2km超は36/44件（65歳以上14,378人）。
  - 予測照合: 「種別不問1km以内だが土砂向け1km超が20%以上」は実測22.7%（10件、高齢7,263人）で支持（800m閾値では18.2%と敏感）。「欠落メッシュの高齢人口1,000人以上」は支持。**「標高差100m以上で欠落率が高い」は外れた**: 熱海は43/44メッシュが標高差100m以上（中央値293m）で対照群が作れず、標高差の判別力の弱さが判明した。
  - 注意: 測ったのは公表登録上の欠落であり、熱海に実際の避難先が無いことの証明ではない。静岡県の国勢調査行では65歳以上が秘匿の行が509/4,165件あり、0として数えない扱いが必須。
- 形式検査: critic_review を通過（棄却理由なし）。
- ファイル: `landslide-elderly-overlap.json` / `.md`、再現コードと結果は `landslide-pilot/`。

## 候補4: GTFS等の公開が確認できないバス事業者と自治体の偏り（exploration）

- 社会課題: バスが運行していても、GTFS等の機械可読な運行データが公開されていない地域では、住民が経路検索や MaaS アプリでバスを調べられず、バスが事実上の移動手段として不可視になる。高齢化した地方では、検索できないことがそのまま利用の断念につながりうる。判断は、国・都道府県・自治体の交通担当が、データ整備支援（共同整備の働きかけ、県プラットフォーム化、整備補助）の優先順位を決める場面にある。
- 作業仮説: バス停台帳（P11）に載る事業者のうち、主要な公開台帳で GTFS 等の公開が確認できる停留所の割合は都道府県で大きく割れ、県主導の共同整備がある地域では高く、事業者任せの地域では2割未満の県が広く分布する。台帳の union を広げ、照合規則を緩めても県間格差がほぼ消えるなら棄却される。対象量は「未公開」ではなく「主要台帳での確認可能性」と定義した（理由は下記の pilot の発見）。
- pilot（台帳は Transitland Atlas の DMFR 2ファイル: gtfs-data.jp 612フィード、ODPT 141フィード。P11 は `yuiseki/ksj-p11-bus-stop-jp@442223b`、自治体・人口は `yuiseki/jp-admin-2026-09@e6c87b1`）:
  - 全国: 厳密な名称照合では事業者の5.7%（82/1,445）、停留所の10.1%が確認可能。部分一致まで認めた緩い照合では事業者22.1%、停留所25.0%（照合規則だけで2.5倍動く）。
  - 県別（停留所ベース、緩い照合）: 山形98.4%、富山96.0%、三重85.9%。佐賀・長崎・宮崎は0.0%。20%未満は24県。東京34.2%、大阪26.1%、愛知49.6%。区分別では公営57.2%、コミュニティバス32.5%、民間路線バス18.1%。
  - **最大の発見**: 県主導で県内全事業者の GTFS-JP 整備が国交省の事例資料に載る佐賀県が、この台帳では0%になった。都営バスも名称照合で取りこぼした。台帳の完全性と照合規則が結果を支配することが実測できたため、対象量を「確認可能性」に定義し直し、これを候補の中心的な方法論判断に据えた。
  - 事前予測の照合: 都市圏60%超は**外れ**、事業者ベースと停留所ベースの15ポイント差も**外れ**（実測2.9ポイント）、コミュニティバスが民間より低いは**逆転**。20%未満10県以上のみ支持（24県）。
  - 自治体集計（停留所のある1,647自治体のうち確認できる事業者が無いのは983、人口51,505,558人）は札幌市・さいたま市・広島市を含むため上限値であり、対象量の実測ではないことも明記されている。
- 形式検査: critic_review を通過。ただし dataset-discovery の目録に GTFS 台帳のカードが無いため、正式な proposal 化の前には台帳の目録化が別途必要（候補 JSON の datasets は目録にある P11 と jp-admin のみで構成し、台帳は対象量の定義と pilot の側に置いた）。
- ファイル: `gtfs-coverage-gap.json` / `.md`、再現コードは `~/workspace/.cache-geoai/gtfs-pilot/`。

## 候補5: 都市縁辺部での農地の転用パターン — 転用先の構成と駅距離・自治体による違い（exploration）

- 社会課題: 都市縁辺部の農地は開発圧と農地保全の板挟みにある。転用が実際にどこで、農地が何に変わって起きているかが見えないと、自治体の農業・都市計画担当は、保全と開発の線引きや現地確認の優先順位を、印象や単年の衛星差分で決めることになる。
- 作業仮説: 前期（2017〜2019年）に農地だった場所の持続的な喪失は、転用先の過半が人工面（built）であり、その人工面化は駅から近いほど・自治体によって構成が異なる。駅距離で差が無く、自治体間の構成差も小さければ棄却される。農地総面積の純変化には仮説を置かない（pilot の予測照合を受けて弱めた探索扱いの変更で、経緯は JSON に記録済み）。
- pilot（IO LULC annual v02、Planetary Computer STAC、タイル 54S、2017〜2023。駅は `yuiseki/ekidata-jp` 2026-07-31、自治体は `yuiseki/jp-admin-2026-09`。範囲は入間・狭山・所沢・瑞穂付近の一区画、2,896,642画素、雲の除外0）:
  - 予測は4件固定し、2件支持・2件外れ。
  - 「農地の純減少」は**外れた**: crops は 15.67 → 17.45 km²（+1.78 km²）。単年面積が 14.60〜17.45 km² と振れ、純変化は分類ノイズに支配される。
  - 「持続的喪失の過半が built」は支持: 前期 crops 16.05 km² のうち持続的喪失 2.13 km²、転用先は built 76.4%、rangeland 14.4%、trees 5.3%。
  - 「駅近傍への集中（1km以内シェア比1.5倍以上）」は基準未達: 比は1.18倍、中央値 2,099m 対 2,239m と勾配は弱い。
  - 「自治体間の built 構成差20ポイント以上」は支持: 入間市 97.8% 〜 三芳町 61.7% で36.1ポイント差。
  - pilot で測った量は対象量そのもので、代理指標の飛躍はない。
- 形式検査: critic_review を通過（理由・警告なし）。
- 注意: IO LULC の dataset カードは未レビューの下書きであり、クラス定義の原典照合（特に crops と rangeland の境界）は未実施。駅距離は現況版の駅で測った代理指標で、因果の主張はしない。
- ファイル: `cropland-conversion-fringe.json` / `.md`、pilot スクリプト `pilot_cropland.py`。

## まとめ

- 形式検査: 4件が critic_review 通過、1件（候補2）が列の目録未記載による reject 1件のみ（列の実在は一次資料で確認済み）。
- 5件とも「採用」を意味しない。次に進めるなら、各候補の JSON を evals/curriculum/proposals/ に置く正式 proposal 化が手順になる。
- データ側の宿題が2件残った: 候補2の世帯総数列の目録追記、候補4の GTFS 台帳の目録化。候補3で使えなかった A33（土砂災害警戒区域）のカード化も、目録側の欠けとして記録に値する。
