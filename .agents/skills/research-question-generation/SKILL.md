# research-question-generation

答えられる問いを量産するのではなく、社会的な使い道があり、分析者の重要な判断が答えを左右する問いを少数だけ残す。候補は研究提案であり、結果でも正式課題でもない。

## 入力を集める

1. `dataset-discovery/references/` の索引と、使いそうなデータの frontmatter と本文を読む。範囲、時点、粒度、結合キー、CRS、欠測、既知の罠を短い証拠表にする。記載が無い列は、実データか再現可能な既存の分析コードで確かめるまで「未確認」とする。更新されるデータは版を固定できるかも確認する。
2. `.agents/skills/*/SKILL.md` の name と description から、この問いを解くときに必要そうな能力を探す。関連する本文を読み、仮定と検査できる failure mode を控える。必要な能力が見つからなければ「未実装」と記録し、できる前提にしない。候補を作るこのスキル自体は、別のスキルを前提にしない。
3. `evals/tasks/hard-tasks.md` と `evals/tasks/hard-rubric.md` を確認する。`projects/*/report.md` と実行記録も見て、解いた問いの型、順位が変わった設定、接続失敗、データ品質の問題をメモする。人間側の採点資料の答えや採点項目を、候補の問い本文へ写さない。

## 候補を作る

- `exploration`: まだ結んでいないデータ、対象、単位、使い道から、現実の意思決定に自然な組を少数選ぶ。対象・量・使い道・罠の機械的な全組合せは作らない。
- `digging`: 過去の分析の予想外の結果、頑健性の崩れ、残差や結合の失敗を出発点に、何を区別したいかを問い直す。元の結果の場所や数値を引用し、単なる同じ問いの再実行を避ける。
- どちらも先に、誰のどの不利益を減らしたいかという社会課題、誰の判断を変えるか、反証可能な作業仮説を書く。その後に対象量、単位、データで言えないことを定める。作業仮説は観測できる差や方向と、退ける条件を含め、実測結果と混同しない。予想する結果、難所、壊れそうな仮定、必要な能力も記録する。予想は結果を見て書き直さない。手法は問いから必要になったときだけ提案する。

## 棄却を優先する

候補ごとに[候補の形式](references/candidate.md)で JSON を書き、`scripts/validate_candidate.py` を実行する。この検査は列の証拠、複数データの接続（単一データの観測監査には条件付き例外あり）、単純集計、既存課題への表面上の近さ、因果の設計の欠落などを止める。合格は採用ではなく、批評に進めるだけ。詳細は[批評と pilot](references/critic.md)。

最も単純な合理的方法で一度解くとどうなるかを考え、そこで使い道に十分なら棄却する。必要なら小さい pilot で、単位や閾値などの妥当な選択を変えたときに結論が動くかを調べる。pilot で測った量が課題の対象量と違う場合、その数字を高価値の裏付けに使わない。結果を見て候補の閾値や対象を有利に書き換えた場合は新しい探索候補として履歴に残し、元の予想を消さない。

硬い棄却を通った候補にも、データ統合、方法上の判断、新規性、意思決定、評価可能性、非自明さ、実行可能性、認識上の正直さを個別に評点し、理由を書く。点数の合計だけで採用しない。必要変数が無い、同型の焼き直し、方法を使うことが目的、実際には単純集計で十分、因果の識別に必要な情報が無い、と判断した候補は落とす。良い候補が無いときは proposal 0 件で止める。

## 出力と境界

候補数、棄却数と理由、残す候補の根拠を dry-run 記録に残し、残すなら `evals/curriculum/proposals/` に proposal を 1 件だけ書く。問い、使い道、量、単位、データと版、結合、必要な判断、最小解法と不足、既存課題との差、予想、データで言えないこと、想定 rubric、未確認事項を含める。正式な `hard-tasks.md` と採点資料は編集しない。候補を解く計画、実際の分析、因果効果の推定、報告書の作成はこのスキルの仕事ではない。

タスクカードを求められたら、`evals/curriculum/task-cards/README.md` の定義に従い、候補の短い検討記録を `evals/curriculum/task-cards/` に置く。提供された pilot の数字は再現できるまで未再検証と記す。カードも正式課題ではなく、形式検査の通過を実データでの検証完了と取り違えない。

検査の実行例（リポジトリ直下から）:

```sh
uvx --with pyyaml python .agents/skills/research-question-generation/scripts/validate_candidate.py evals/curriculum/proposals/candidate.json
```

検査結果の `critic_review` は、人が正式課題として採用した状態ではない。
