# 棄却のための Critic と小さい pilot

## Hard gate

1. 社会的な対象量と利用者が言える。ID の最大値や手法の実演は落とす。
2. 必要な変数が利用可能な版にあり、空間・時間の共通範囲が非空と考えられる。未確認の点は pilot に残し、必須変数が無いなら落とす。
3. 複数データを本当に結ぶ必要がある。データの名前だけを付け足した候補は落とす。
4. 最小解法が単純な集計で意思決定に十分なら落とす。複雑な手法が要る理由を後付けしない。
5. 既存課題と対象名・地名だけの差なら落とす。表面の類似検査で通っても、問いの構造を人が比べる。
6. 因果を問うなら、処置時点、結果、対象、反事実、識別仮定を置けるか。置けなければ因果課題としては落とす。
7. 予想される失敗と「分からないこと」を課題が隠していない。

## Soft score

Hard gate 通過後に、次の各観点を 0（弱い）、1（要検証）、2（強い）で採点し、各点に理由と証拠の位置を付ける。重み付き合計では採用しない。弱い観点が意思決定を変えるなら、その候補を残さない。

| 観点 | 2 の目安 |
|---|---|
| data integration depth | 複数の粒度や CRS を整合しないと対象量が作れない |
| methodological depth | 妥当な複数の設計選択で順位や解釈が変わりうる |
| novelty | 既存課題から測る量か意思決定が実質的に進んでいる |
| decision relevance | 誰の具体的な判断に答えるかが書ける |
| evaluability | 基準、失敗、頑健性を後から同じデータで採点できる |
| non-triviality | 最小解法では答えにならない理由が具体的 |
| feasibility | 必須列と十分な範囲があり、限定した答えへ到達可能 |
| epistemic honesty | 不明な量や因果の識別限界を問いの段階から明示 |

## Pilot と surprise

pilot は実データを使う場合でも小さい範囲・件数から始め、対象レコードの有無、結合率、0 と欠測、時点のずれ、単純な基準を数える。次に重要な設定を一つだけ変える。結果が変わらないことも価値があるが、複雑さの必要性が消えたなら候補を落とす。変わった結果を見て閾値や問いを書き換えた場合は、その変更を記録して探索扱いにする。

予想した主結果と実際の答え、予想した破綻と実際の破綻を別々に照合する。予想外の失敗は次の digging の材料にする。驚きの大きさだけを報酬にしない。極端な値、データ破損、観測の偏りが「驚き」を作ることがあるからである。

検査スクリプトは、JSON の形式、列の根拠、入力の接続、明白な単純解法、表面上の重複、因果設計の欄だけを見る。意味の適切さ、真の新規性、実際の政策価値、可否の最終判断は Critic が担う。embedding は必要としない。
