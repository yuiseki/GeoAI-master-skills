# barrier、NoData、届かない cell

## cell の状態

| 状態 | 何か | 入力での表し方 | 出力 |
|---|---|---|---|
| 通れる | 正の有限のコストを持つ cell | 値 > 0 | 届けば状態 1 (累積コスト)、届かなければ状態 2 |
| barrier | 通れないと宣言した cell | `--barrier-value` の値 | 状態 3、累積コストは NaN |
| NoData | 値の無い cell | ラスタの NoData の値か NaN | 状態 4、累積コストは NaN |
| 範囲外 | ラスタの外 | | 出られない (cell ではないので出力に無い) |
| 届かない | 通れるが、どの destination からも閉じ込められている | | 状態 2、累積コストは NaN、最寄りは -1 |

0、負、無限大のコストを持つ通れる cell があると止まる。コストが 0 の cell はただで進めることになり、意味を確かめずに通すと最寄りの選び方が壊れる。無限大を通れない印にしているなら、`--barrier-value inf` と書く。

届かない cell を大きな有限の数で埋めない。平均や閾値 (2 時間以内か) の計算に紛れ込む。

## NoData を通れない cell にする理由

既定では、NoData は通れない cell として扱い、barrier とは別の状態で数える。

- NoData を 0 と読むと、ただで進める穴になり、累積コストが小さく出る。平均の値で埋めると、根拠の無い値で経路が決まる。どちらも黙って楽観的な答えを出す。
- 通れないとすると、NoData の向こうの cell は遠回りか、届かないになる。答えは悲観的になりうるが、届かない cell と NoData の数として表に出る。
- NoData を埋めるかどうかは、値の意味を知っている側 (cost raster を作る段階) で決めて書く。決まっていないなら `--nodata stop` で止める。

## ラスタの外

ラスタの外へは出られない。本当は外を回るほうが早い経路も、ラスタの中だけで探す。destination や問いの範囲の近くでラスタを切ると、端の cell のコストが大きく出る。問いの範囲より広く切り、端の近くの値は分けて読む。

## 対角の移動で角を抜ける

8 近傍では、対角の移動は 2 つの cell の角を通る。

```text
S X
X T
```

S から T への対角の移動は、通れない 2 つの X の角の 1 点を通る。`--corner-rule` で決める。

| 規則 | 対角の移動を取らないとき | 使いどころ |
|---|---|---|
| both (既定) | 共有する 2 つの隣が、両方とも通れない | 1 cell 幅の斜めの壁 (川、柵、崖の線を cell ごとに焼いたもの) を抜けない |
| either | 共有する 2 つの隣の、どちらかが通れない | 通れない cell の角をかすめることも許さない |
| allow | 取らないことは無い | GRASS の `r.cost` と scikit-image の `MCP_Geometric` と同じ |

斜めの線を cell ごとに焼くと、cell は角だけでつながる (8 連結)。allow では、その線の角を対角に抜けて向こう側へ出る。テストの 6 × 6 の対角線の壁では、allow と GRASS の `r.cost` は壁の向こうの 15 cell 全てに届き、both では全て届かなかった。

both では、片側だけが通れないとき (壁の端の角) は抜ける。そのとき、移動のコストは出発側と到着側の 2 cell だけで決まり、かすめた cell のコストは入らない。either は、この角も回り込ませる (S . / X T の対角が 2 歩になる)。

通れない cell のつながり方に合わせて選ぶ。線を 4 連結で焼いた (角でなく辺でつながる) 壁なら、どの規則でも抜けない。
