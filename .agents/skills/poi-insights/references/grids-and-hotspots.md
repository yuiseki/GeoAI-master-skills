# 格子と集積の判定

## 格子

- H3 は六角形の格子で、隣り合うセルとの距離がどの向きでもほぼ同じ。集積の判定 (隣を数える) に向く。解像度 8 のセルの面積は約 0.74 km²、9 は約 0.11 km²、10 は約 0.015 km² (H3 の公式の表の平均)。
- S2 は四角形の階層の格子。`grid_hotspots.py` は S2 のセル (トークン) ごとに数えるが、Gi* は H3 だけで計算する (S2 の範囲のセルと隣の組み立てを入れていない)。
- 点のセルは `h3.latlng_to_cell` と、s2sphere の `CellId.from_lat_lng(...).parent(level)` で決める。どちらも点を含むセルになることをテストで確かめた。

## Gi*

範囲の全てのセル (セルの中心が範囲に入るもの、と範囲の点を含むもの。空のセルを含む) を n 個、セル i の数を x_i とする。重みは、自分と k 環 (既定 k = 1、自分と隣の 6 セル) を 1、それ以外を 0 とする。

    z_i = (Σ_j w_ij x_j − x̄ Σ_j w_ij) / (s √((n Σ_j w_ij² − (Σ_j w_ij)²) / (n − 1)))
    x̄ = Σ x / n,  s = √(Σ x² / n − x̄²)

- 空のセルを入れないと、平均が上がり、集積が少なく出る。範囲の外の点は数えて (outside)、使わない。
- 片側 (多い向き) の p 値を正規分布で出し、全てのセルにまとめて Benjamini-Hochberg (既定 0.05) をかける。セルが数万あるので、補正しないと偶然の集積が多数出る。
- 一様に置いた点 2,000 個 (解像度 8) では、集積は高々 1 つだった (テスト)。
- esda の `G_Local(star=True, transform="B")` と z が一致する (`test_grid_hotspots_crosscheck.py`、2026-11-12)。
- 正規近似は、数の少ないセルが多いと粗い。p 値は順位をつける目安で、正確な有意確率ではない。並べ替え検定は入れていない。

## クラスター

集積と判定され、点を 1 つ以上含むセルのうち、隣り合う (1 環) ものを 1 つのクラスターにつなぎ、含む点の数で並べる。

- つなぎ方のために、密な地域では大きな 1 つのかたまりになる。ロンドンのコーヒーショップ (Overture 2026-10-21.0、5,080 店) では、解像度 9 で中心部が 328 セル、1,456 店の 1 つのクラスターになり、解像度 10 では 804 店に分かれた (projects/_playground/london-coffee-places)。
- 「上位 N の集積」は解像度で変わる。少なくとも 3 段の解像度で、クラスターの数と最大の集積を並べて書く。使い道に合う解像度 (歩いて回れる範囲なら 9、地区なら 8) を、結果を見る前に決める。
