# 属性の扱いと、商用の POI との差

## 属性

| 属性 | 扱い |
|---|---|
| カテゴリ | 1 つの基本カテゴリと、階層 (例 food_and_drink > non_alcoholic_beverage_venue > coffee_shop > coffee_roastery) を持つデータでは、階層のどこかに含むかで取る。基本カテゴリだけで取ると、下位の種類 (焙煎所) が落ちる |
| ブランド | 欠けている店が多い (チェーンでない店)。ブランドの割合や HHI では、ブランドの無い店をそれぞれ 1 社として数える。表記の揺れ (Costa と Costa Coffee) は、データの値のまま数え、揺れがあることを書く |
| 営業状態 | 営業中、一時休業、閉業、欠け。欠けは「不明」で、営業中と数えない。閉業を除くときは、除いた数を書く |
| 信頼度 | 0〜1 の値。出どころが存在を確かめた度合いで、位置の精度ではない。絞るなら、絞らない場合と並べる |
| 出どころ | 1 つの POI が複数の出どころ (データセットとライセンス) を持つ。ライセンスは出どころごとに違うので、使った POI の出どころの数を書く |

## 取り出した後に数え直すもの

複数の出どころを合わせた POI には、同じ店の重複と、店でない行が混じる。どちらも、集積の上位と人口あたりの数を押し上げる。結果を見る前に規則を決めるか、決めずに見たなら、規則を入れる前と後の両方を並べる。

- 同じ店の重複: 出どころの違う行が、同じ店を少し離れた位置に別の行として持つ。東京 23 区のコンビニ (Overture 2026-10-21.0、7,582 行) では、同じチェーンで 25 m 以内の行が 770 あり、1 店にまとめると 572 行が減った (Overture 2026-10-21.0 を使ったエージェントの分析で、2026-11-12 に測った)。
- 店でない行: 同じカテゴリに、店の中の ATM などの記録が入る。同じ実行で、名前に「銀行 ATM」「共同出張所」を含む行が 313 あった。
- ブランドの値に店名が入る: ブランドの列に「ファミリーマート サンシャイン通り南店」のような店名がそのまま入る行があり、そのまま数えるとチェーンが分かれる。HHI は、ブランドの列のままか、店名からチェーンを割り当てるかで大きく変わった (区の中央値 0.065 と 0.253)。割り当ての規則と、割り当てられない行の数を書く。
- 営業状態の欠けは国で違う。ロンドンのコーヒーショップでは 5,333 店中 2,818 が欠け、東京 23 区のコンビニでは 7,582 行の全てが欠けだった。

## 商用の POI にあって、オープンな POI に無いもの

Google の Places Insights (2026-11 時点の公開情報) が使う属性のうち、Overture の places と OpenStreetMap に無いか、限られるもの。

| 属性 | オープンな POI での状況 | 答えへの影響 |
|---|---|---|
| 評価 (rating)、口コミの数 | 無い | 評価で絞る、評価の高い店の集積、といった問いには答えられない (データの欠落) |
| 営業時間 | OSM の opening_hours はタグのある店だけ。Overture には無い | 時間帯ごとの営業の分析は、タグのある店に限られる |
| 価格帯 | 無いか、限られる | 答えられない |
| 混雑 (人の多さ) | 無い | 答えられない。人の多さの代わりに人口を使うのは、別の量 (住む人) |
| 営業状態の鮮度 | Overture は月ごとの版だが、出どころの更新日は行ごとに違う。欠けが多い (ロンドンのコーヒーショップで 5,333 店中 2,818) | 閉業の見落としが残る。不明を営業中と数えない |

Google の集計は、少ない数のセルを出さない (プライバシーのための下限) とされる。オープンな POI は個々の店をそのまま扱えるので、この制約は無い。ただし、店の数がどれだけ実際の店を拾っているか (網羅率) は、データの集め方に左右され、地域で違う。別のデータとの照合で、少なくとも順位の一致を確かめる。
