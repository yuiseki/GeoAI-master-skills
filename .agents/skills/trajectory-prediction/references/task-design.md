# 問いの形と試験の作り方

## 問いの形

| 問い | 答え | 基準 |
|---|---|---|
| 行き先 | 軌跡の最後の点 (経緯度) | 接頭の最後の点、学習の行き先の中央値 |
| n 分後の位置 | 接頭の終わりから n 分後の点 | 接頭の最後の点、最後の速度で n 分進めた点 |
| 到着の時刻 (残りの時間) | 軌跡の終わりの時刻 | 学習の所要時間の中央値から、経過時間を引いたもの |

このスキルの手順とスクリプトは、行き先で確かめた。ほかの 2 つは同じ試験の作り方が使えるが、モデルは確かめていない。

## 時刻で切る試験

ECML/PKDD 2015 の課題の試験は、5 つの時刻に走っていたタクシーを、その時刻までの点で切って作られた。論文の著者の自前の試験も同じ作り方で、学習の期間から一様に引いた 500 の時刻で切った。

この作り方には 2 つの性質がある。

- 長い軌跡ほど試験に入りやすい (走っている時間が長いので、時刻に当たりやすい)。
- 1 本の軌跡の中では、どこで切られるかが一様になる。

学習の接頭を「全ての軌跡の全ての切り方から一様に」引くと、この分布と同じになる (`sample_prefixes`)。軌跡を一様に選んでから長さを一様に選ぶと、短い軌跡が多すぎる。

`snapshot_cut` は、時刻を小さい順に見て、その時刻に走っている軌跡 (始まり ≤ 時刻 ≤ 終わり) を取り、取った軌跡を次の時刻では取らない。知っている点の数は (時刻 − 始まり) // 間隔 + 1。時刻がちょうど最後の点に当たると、接頭が軌跡の全体になり、最後の点の基準の誤差が 0 になる。Porto の検証では 0.2% だった。

## 分け方

- 試験と検証の軌跡は学習から除く。同じ軌跡の別の切り方が学習に入ると、行き先がそのまま漏れる。
- 時刻を期間の全体から引いた試験 (S_rand) では、同じ日の別の軌跡が学習に入っている。その日の混み方や催しを学習が知っている。
- 学習を期間の前の部分に限り、後の部分の時刻で切った試験 (S_late) と、前の部分の時刻で切った試験 (S_early) を並べると、その近さの効きを分けられる。比べるのは誤差そのものより、基準との差。誤差の水準は時期の性質 (季節、行事) でも動く。

## 漏れの確かめ

- 接頭の点と行き先が同じ点になる割合 (ちょうど終わりで切った軌跡)。
- 付随情報 (客の ID、タクシーの ID) は、試験でも使ってよい情報か。課題の定義で、乗った時点に分かる情報だけを使う。降りた時刻や所要時間を入れない。
- 時刻の特徴量は、現地の時間帯で作る (`time_features`)。Porto は Europe/Lisbon。

## Porto の本数

学習の期間 2013-07-01〜2014-06-30、1,710,670 本のうち点の無い 5,901 本を除いた。500 の時刻 (種 42) で 19,711 本、別の 500 の時刻 (種 1337) で 19,023 本。論文は 19,770 本と 19,427 本。2014-04-01 で区切ると、学習 1,218,003 本、S_early 18,852 本、S_late 19,902 本。
