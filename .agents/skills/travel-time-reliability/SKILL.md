# travel-time-reliability

「どの道が、いつ、どれだけ遅く、どれだけ読めないか」に、観測した旅行時間で答える。平均の速さだけでは、毎日同じだけ遅い道と、日によって大きく遅れる道が区別できない。遅さ (TTI) と読めなさ (LOTTR、PTI) を分けて出し、時間帯の差は日ごとの値の引き直しで不確かさを付ける。

別の問いとの境界:
- 先の時刻の速度を当てるのは、時系列の予測の問い。ここでは過去の観測を要約する。
- 道のりの距離や到達圏は、ネットワークの問い。ここでは観測した時間だけを使う。
- 交通量が無いので、台時間の遅延 (vehicle hours of delay) と、PHED (人あたりの遅延) は出さない。

|---|---|---|

## 手順

1. 問いを 1 行で書く。どの道 (区間、路線) の、どの時間帯を、どの期間で、何のために比べるか。
2. 期間と祝日を決める。少なくとも 4 週間 (1 時間帯に 20 日ほど) を取る。祝日は週末として扱う。
3. 観測を、区間、時刻 (その道の地方時)、旅行時間 (秒) の表にする。速度しか無ければ、区間の長さ / 速度で旅行時間にする。
4. データを確かめる ([data-checks](references/data-checks.md))。状態の符号ごとの行数と速度、区間ごとの報告の間隔、同じ値の繰り返しの割合、時刻ごとの速度の形 (朝と夕に遅くなるか)。疑わしい状態の行を外した場合と外さない場合の両方で流す。
5. `scripts/ttr_metrics.py` で、15 分ごとの平均にし、区間と時間帯ごとの LOTTR、TTI、PTI、遅延と、2 つの時間帯の差 (日の引き直しの 95% 区間) を出す ([definitions](references/definitions.md))。日数が少ない区間と時間帯は印を付ける。
6. 路線 (つながった区間の組) で見るなら、15 分ごとに区間の旅行時間を足して路線の旅行時間にし (全ての区間がそろった区切りだけ)、同じ指標を出す。
7. ボトルネックを並べる。混雑 (夕の TTI の高い区間) と、読めなさ (いずれかの時間帯の LOTTR が 1.5 以上) を別の表にする。
8. 地図 (PNG) と表を書き出す。

```sh
uvx --with pandas --with numpy --with pyarrow python scripts/ttr_metrics.py obs.parquet tmp/ttr \
  --compare AM PM --holidays 2026-10-12 --min-days 10
```

## 書き出すもの

- 問い、データの出どころ、ライセンス、期間、祝日、区間の数
- データの確かめ (状態の符号、間隔、繰り返し、時計) と、外した行の数
- 区間と時間帯ごとの LOTTR、TTI、PTI、遅延、日数
- 時間帯の差と、その区間
- 路線ごとの指標 (足し方を添えて)
- ボトルネックの表と地図
- 自由流の決め方と、それで TTI がどう変わるか
- 確かめていないこと (感知器の位置の精度、区間の長さ、交通量が無いこと)
