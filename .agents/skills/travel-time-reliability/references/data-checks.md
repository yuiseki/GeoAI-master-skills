# 読み込んだ直後に確かめること

旅行時間や速度の配信データは、欠けを 0 や同じ値の繰り返しで埋めていることがある。指標を出す前に、次を数える。数えた結果は報告に残す。

| 確かめること | どう測るか | 見つかったら |
|---|---|---|
| 状態の符号 | 符号ごとの行数、速度の中央値、旅行時間が 0 以下の行数 | 「観測なし」を表す符号の行を外す。外した場合と外さない場合の両方で流し、結論が変わるかを見る |
| 報告の間隔 | 区間ごとの、続く 2 行の時刻の差の中央値 | 間隔が区間で違っても、15 分の区切りの平均にすれば重みはそろう |
| 同じ値の繰り返し | 区間ごとに、直前と同じ旅行時間の行の割合 | 割合が極端に高い区間は、感知器が止まって最後の値を出し続けている疑い。結論に使う前に時刻の並びを見る |
| 時計 | 時刻ごとの速度の中央値 | 平日の夕方 (16〜19 時) に遅くならなければ、時刻が UTC か、別の地方時の疑い |
| 日の欠け | 配信元の日ごとの行数 | 行の少ない日は、道が空いていたのではなく配信が止まった。その日の時間帯は日数から外れる |
| 区間の形 | 区間の点の並び | 点の文字列が決まった長さで切れていると、最後の点が壊れている |

## NYC DOT Traffic Speeds で測ったこと (2026-10-01〜31、2026-11-12 に取得)

- 125 区間、1,053,140 行。状態 -101 が 411,724 行で、速度の中央値は 0、そのうち 360,200 行は旅行時間が 0。状態 0 が 641,416 行 (速度の中央値 42.25 mph)。状態 -101 は観測なしの印と読み、状態 0 だけを主に使った。状態 0 の行を 1 つも持たない区間が 31 あり、指標を出せたのは 94 区間。
- 報告の間隔の中央値は 300 秒。直前と同じ旅行時間の行の割合の中央値は 0.1614。
- 時刻ごとの速度の中央値は 4 時台に最も速く (52.81 mph)、17 時台に最も遅い (26.09 mph)。時刻はニューヨークの地方時と読んでよい。
- 2026-10-12 は配信元に 1 行も無く、前後の 10-11 と 10-13 も行が少ない (27,519 と 20,856)。この日は祝日でもあり、週末として扱った。
- `link_points` は決まった長さで切れていて、最後の点が「40.70,-74」のような断片になる。地図では最後の点を捨てた。区間の長さは、速度と旅行時間からは求められるが、点の並びからは正確に出ない。
