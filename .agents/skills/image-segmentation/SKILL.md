# image-segmentation

画像のチップを画素ごとに分ける課題の点数は、何と比べるか、IoU をどう数えるか、試験をどう分けるかで大きく変わる。Sen1Floods11 の Sentinel-1 の水では、FCN の IoU (チップごとの平均) は 0.377 だった。チップごとに作った Otsu のしきい値 (0.228) と比べれば大きく上回るが、場面ごとに作った Otsu (0.347) との差は 0.03 ほどで、学習に入っていない洪水では Otsu の方が上だった。U-Net は FCN を上回らなかった。深層学習のモデルを持ち込む前に、強い単純な基準を同じ試験で出す。

別の問いとの境界:
- 2 つの時点の画像の変化 (出来事の前と後) は、変化の検出の問い。ここでは 1 時点の画像の画素を分ける。
- 意味の決まったラスタ (分類済みの土地被覆など) を単位に集計するのは、ラスタの集計の問い。ここでは画素のクラスそのものを当てる。
- データのライセンスは、学習の前に配布元の原本で確かめる。画像の写しの説明は原本と食い違うことがある (Sen1Floods11 では写しが CC BY 4.0、原本の目録が proprietary)。

## 手順

1. 問いを 1 行で書く。何のクラスを、どの画像 (センサー、バンド、時点) から、何のために分けるか。使う場面が「新しいできごと (洪水、地域)」なら、試験もできごとごとに分ける。
2. データの原本のライセンスを確かめる。確かめられなければ、画像と画像から作った図をリポジトリに入れず、数字だけを報告する。
3. チップと正解を数える。分け方ごとのチップの数、できごと (場面) の数、無効の画素の割合、正のクラスが無いチップの数。
4. 基準を先に出す。場面ごとの Otsu のしきい値を平滑化した画像に当てたもの (`scene_otsu_threshold`、`focal_mean`) と、チップごとの Otsu (`otsu_mask`)。論文が基準の結果を配っているなら、それを自分の指標で採点し、論文の値に戻るかを確かめる (指標の数え方の確かめ) ([baselines](references/baselines.md))。
5. 指標を 2 つとも出す。IoU のチップごとの平均 (`chip_iou` の平均) と、画素をまとめた IoU (`pooled_iou`)。数え方で順位が入れ替わる ([evaluation](references/evaluation.md))。
6. モデルを学習する (`scripts/seg_models.py`)。種を 3 つ以上にし、学習の予算と最良のエポックの選び方は試験を見る前に決める ([training](references/training.md))。
7. モデルと基準の差を、同じチップで対にした差 (`paired_difference`) で出し、区間はできごとごとに引き直す。学習に入っていないできごとがあれば、そこでも並べる。
8. 書き出す。

## 書き出すもの

- 問いと、試験の分け方 (チップの数、できごとの数、学習と同じできごとか)
- データのライセンスの確かめ方と結果
- 基準 (どの Otsu か、平滑化の幅、しきい値の決め方) とモデルの IoU を、チップごとの平均と画素をまとめた値の両方で
- モデル − 基準の対にした差と、できごとごとの区間、種ごとの値
- 学習に入っていないできごとでの順
- 学習の設定、計算の装置と版 (PyTorch と cuDNN)
- 確かめていないこと
