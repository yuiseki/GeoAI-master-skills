# 画素の意味を確かめる

集計の方法は、画素の意味で決まる。処理の前に、次の項目を埋める。データの説明に無い項目は「未確認」と書き、`scripts/inspect_raster.py` の数字から推した理由を添える。

| 項目 | 問い | 例 |
|---|---|---|
| 1 画素 | 何の、どの範囲の値か | 約 100 m 四方に住む人の推計数 |
| 単位 | 値の単位。scale と offset があれば、当てた後の単位 | 人、m、℃、クラスのコード |
| 連続値かクラスか | 値の大小に意味があるか。整数でも、コードなら大小に意味は無い | 標高は連続値。土地被覆の 10、20、30 はクラス |
| 量か水準か | 連続値のとき、面積を 2 倍にすると値も 2 倍になるか | 人口は量。標高、気温、人口密度は水準 |
| NoData | 何を指すか。観測が無い、海、範囲外、人が住んでいない | 人口の格子で、建物の無い画素が NoData のことがある |
| 空間の支持 | 値は画素の面の代表か、中心の点の値か | 標高の DEM は中心の値のことが多い |
| 時点 | ある時点の値か、期間の合計か平均か | 年の 1 月 1 日の人口、年の降水量の合計 |

## 量と水準

足せる量 (extensive) は、面積を分ければ値も分かれ、合わせれば足される。人口、件数、面積、降水量の総量。単位への集計は合計で、粗くするときもブロックの合計。

足せない水準 (intensive) は、面積を変えても値の意味が変わらない。標高、気温、濃度、確率、そして量を面積で割った密度。単位への集計は平均 (面積で重みを付ける) と最小、最大で、粗くするときもブロックの平均。

同じ現象でも、量と水準の両方の形で配られる。人口と人口密度。どちらの形かで方法が変わるので、値の単位 (人か、人 / km² か) を確かめる。人口のラスタを平均すると、画素あたりの人数の平均になり、人口でも密度でもない。

## クラス

値はコードで、大小に意味は無い。平均、補間、合計をしない。単位への集計はクラスごとの面積の割合で、粗くするときはブロックで最も多いクラス。`inspect_raster.py` は整数のラスタで値ごとの画素の数を出すので、数十種類しか値が無い整数のラスタは、クラスの疑いがある。コードの意味 (凡例) はデータの説明から引く。

## NoData、0、範囲外

- NoData は、ファイルが宣言した値 (`nodata_value`) か NaN。宣言が無いラスタでは、全ての画素が有効と読まれる。`inspect_raster.py` が `nodata_value: None` を出したら、NaN 以外の欠損の符号 (-9999 など) が値の中に無いかを、最小値で確かめる。
- 0 は値。`inspect_raster.py` は、有効な値の中の 0 の数を別に出す。0 が多いラスタ (人の住まない画素を 0 にした人口) と、NoData が多いラスタ (同じ画素を NoData にした人口) は、合計は同じでも、平均と密度の分母が違う。
- 範囲外は、ラスタが覆わない場所。0 でも NoData でもなく、値が無い。

## scale と offset

整数で保存して、`値 = 生の値 × scale + offset` で実際の値に戻すラスタがある。rasterio の `read()` は、生の値を返し、scale と offset を当てない (rasterio 1.4.1 で確かめた。2026-10-14)。NoData の判定は生の値で行い、その後で scale と offset を当てる。`inspect_raster.py` と `aggregate_raster.py` は、そうしている。

## 読むときの環境の落とし穴

GDAL を同梱した rasterio が、別の GDAL の環境変数 (`GDAL_DATA`、`GDAL_DRIVER_PATH`、`PROJ_DATA`、`PROJ_LIB`) を拾うと、NoData の値が読めず None になることがある。そのとき NoData の画素は有効な値として足される。`inspect_raster.py` で `nodata_value` が期待どおりかを最初に確かめる。外すときは `env -u GDAL_DRIVER_PATH -u GDAL_DATA -u PROJ_DATA -u PROJ_LIB uvx ...`。
