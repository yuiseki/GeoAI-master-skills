# 確かめ方と、確かめられないこと

## 目で確かめる

モデルの試験の数字 (別の国の損傷データでの AUC など) は、当てる地域の画像での当たり外れを保証しない。当てる地域の画像から一様な無作為で標本を取り、結果を重ねた画像を見て、正しいかを記録する。

- 標本は結果を見る前に、種を決めて取る。確率の高いものだけを見ると、適合率しか分からない。
- 1 枚の画像に、番号と結果 (損傷のパッチの枠と確率、柱の傾きと植生の割合) を描いた一覧を作り、番号ごとの判定を CSV に書く (`run.py review_sample` の形)。
- 誰が見たかを書く。人が見たか、AI (画像を読めるモデル) が見たかで、記録の重みが違う。AI が見た判定は、人の判定の代わりにはならない。一覧の画像と CSV を残せば、人が後から同じ標本を見直せる。

## 確かめられないこと

| 値 | 確かめるのに要るもの | オープンデータの状況 (2026-11) |
|---|---|---|
| PCI | 同じ場所で現地で測った PCI と画像の組 | 見つけていない。パリのオープンデータに路面の状態は無かった。米国の一部の市が区間ごとの PCI を公開しているとされるが、その市の Panoramax の画像の量は確かめていない (未確認) |
| 柱の傾きの角度 | 現地で測った傾き (傾斜計) | 見つけていない。描いた画像と、目で見た「傾いて見えるか」の判定までで確かめる |
| 柱の位置 | 柱の台帳の位置 | フランスの電力網の柱の台帳は一般に公開されていない (未確認)。OSM の power=pole は場所によって描かれている |
| 植生が柱に触れているか | 現地の確認 | 画像の上の重なりは、奥行きを持たない。手前の木が柱に重なって見えるだけのことがある |

## 商用のサービスとの差

Google の Imagery Insights は、Street View の画像とメタデータを BigQuery で引き、Gemini で画像を見て報告を作る。ここでは、オープンな画像と公開の重みのモデルで、決まった手順を流して数える。

- 違い 1: 画像の網羅。Street View はほぼ全ての道を撮っている。Panoramax は撮った人のいる所だけ。
- 違い 2: 画像を読むモデル。大きな多目的のモデルに自由に尋ねる代わりに、検出 (OWLv2) と線形のプローブと幾何の計算で、数えられる量にしている。数えられる量なので、標本で当たり外れを測れる。
- 違い 3: ライセンス。Street View の画像は Google の規約のもとで使う。Panoramax の画像は etalab-2.0 や CC-BY-SA-4.0 で、結果を再配布できる (表示と継承の条件に従う)。
