# 分類

目的変数がカテゴリ (紛争があったか、どの区分か) のときに、どのモデルにも加わる論点。`scripts/compare_models.py` は、目的変数が 0/1 なら二値、それ以外のラベル (3 クラス以上、文字列) なら多クラスとして扱う。

## 基準

学習側のクラスの割合をそのまま確率として出す (`prior`)。これより log loss が小さくならないモデルは、特徴量から何も学んでいない。`prior` の log loss は、クラスの割合 p の 2 値エントロピー -(p log p + (1 - p) log(1 - p)) になる。

正解率は基準にしない。陽性が 5% なら、全部を陰性と言うだけで正解率は 95%。

## 指標

| 指標 | 測るもの | 使う場面 |
|---|---|---|
| log loss | 確率の当たり方。自信を持って外すと大きく罰する | 確率をそのまま使うとき。主な指標にする |
| Brier | 確率と 0/1 の差の 2 乗の平均 | log loss より外れ値に穏やか |
| AUC | 陽性を陰性より上に並べられるか。しきい値によらない | 順位だけを使うとき。確率の当たり方は測らない |
| 正解率 | しきい値 0.5 で分けたときの当たり | しきい値を決めた後の説明 |

## クラスの偏り

- 分割は層化する (各分割でクラスの割合を揃える)。`compare_models.py` は行の分割では `StratifiedKFold` を使う。グループごとの分割では層化しないので、分割ごとの陽性の数を確かめる。陽性が 1 つも無い分割があると AUC が測れない。
- 陽性が少ないとき、重みを付けたり行を間引いたりすると、出てくる確率が実際の割合からずれる。確率を使うなら較正し直す。

## 確率の較正

モデルが 0.3 と言った行のうち、本当に 3 割が陽性か。モデルによって確率はずれる。ランダムフォレストの確率は 0 と 1 から離れる向きにずれやすいと報告されている (Niculescu-Mizil and Caruana 2005、ここでは未実測)。確率を使うなら、試験側の予測で較正の図を描き、必要なら学習側の中で較正する。

## しきい値

0/1 を決めるしきい値は、誤りの重さ (見逃しと空振りのどちらが重いか) で決める。0.5 に意味は無い。しきい値も学習側の中で決める。

## 多クラス

二値では「陽性の確率」1 つで足りたが、多クラスでは行ごとにクラスの数だけ確率があり、和が 1 になる。予測するクラスは、最も確率の高いクラス (argmax)。

### argmax で決めるときの注意

- 二値のしきい値のように、誤りの重さで調整する場所が無い。稀なクラスは、確率が他より高くならない限り、一度も予測されない。確率が 0.3 でも、他のクラスが 0.7 なら予測されない。
- 稀なクラスを見逃す損が大きいなら、argmax でなく、クラスごとの確率を見る (one-vs-rest)。「この行が稀なクラスである確率」を並べ、上位から調べる、確率がある値を超えたら印を付ける、と決める。その値も学習側の中で決める。
- 確率の当たり方 (較正) もクラスごとに見る。「クラス k の確率 0.2 と言った行のうち、2 割が本当に k か」を、one-vs-rest で描く。

### 基準

`prior` は学習側のクラスの割合を確率として出す。その argmax は最も多いクラスなので、`prior` の正解率は「全部を最も多いクラスと言う」基準 (majority-class baseline) の正解率になる。log loss の基準は、クラスの割合のエントロピー −Σ p_k log p_k。

### 指標

| 指標 | 測るもの | 稀なクラスの失敗が見えるか |
|---|---|---|
| 正解率 (accuracy) | 当たった行の割合 | 見えない。多いクラスに支配される |
| 混同行列 | 真のクラス × 予測したクラスの数 | 見える。まずこれを見る |
| クラスごとの precision | そのクラスと予測した行のうち、本当にそのクラスの割合 | 見える |
| クラスごとの recall | そのクラスの行のうち、そう予測できた割合 | 見える |
| クラスごとの F1 | precision と recall の調和平均 | 見える |
| macro F1 | クラスごとの F1 の単純平均。どのクラスも同じ重さ | 見える |
| weighted F1 | クラスごとの F1 を行の数で重み付けた平均 | ほとんど見えない。正解率に近い |
| balanced accuracy | クラスごとの recall の単純平均 | 見える |
| 多クラスの log loss | 真のクラスに付けた確率の対数の平均 (の符号を反転) | 確率の当たり方として見える |

`compare_models.py` は多クラスで、log_loss、accuracy、balanced_accuracy、macro_f1、weighted_f1 と、クラスごとの precision[c]、recall[c]、f1[c] を出す。学習側に無かったクラスは、その fold で確率 0 (log loss では 1e-15 に切る) として扱い、列は消さない。

### 正解率が稀なクラスの失敗を隠す (合成、`scripts/test_compare_models.py`)

90 / 9 / 1 の 100 行で、全部を最も多いクラスと言うと、正解率 0.90、macro F1 0.316、balanced accuracy 0.333、weighted F1 0.853。

2 つのモデルを比べる。A は多いクラスを全部当て、中くらいのクラスを 9 のうち 5 当て、稀なクラスを一度も当てない。B は多いクラスを 90 のうち 85、中くらいを 7、稀なクラスの 1 行を当てる。

| | 正解率 | macro F1 | balanced accuracy |
|---|---:|---:|---:|
| A | 0.95 | 0.562 | 0.519 |
| B | 0.93 | 0.876 | 0.907 |

正解率だけで選ぶと、稀なクラスを全く当てない A を選ぶ。稀なクラスが問いの中心 (災害、紛争、希少な土地被覆) なら、macro F1、balanced accuracy、そのクラスの recall で選び、混同行列を書く。

### 分割の層化

分割は、クラスの割合を各 fold でそろえる (層化)。稀なクラスが数行しか無いと、層化しない分割では、ある fold の学習側にそのクラスが 1 行も無いことがある。そのとき、そのクラスは予測されようがない。分割表を作るときに、fold ごとのクラスの数を数える。グループや地域で分けるときは層化できないことが多いので、なおさら数える。

### 空間的に固まったクラスと、ランダムな分割

稀なクラスが特定の地域に固まっているとき、ランダムな分割では、同じ地域の行が学習側にもあり、座標や地域の特徴でそのクラスを覚えられる。新しい地域で使うなら、その覚え方は役に立たない。

合成の例: 40 の地域 × 50 行。稀なクラス (3.9%) は 2 つの地域にだけあり、特徴量は座標 2 つと弱い信号 1 つ。ランダムフォレストを 5 分割、3 回で比べた (2026-10-15)。

| 分け方 | 正解率 | macro F1 | 稀なクラスの recall | log loss |
|---|---:|---:|---:|---:|
| 行のランダムな層化 | 0.852 | 0.609 | 0.397 | 0.388 |
| 地域ごと (地域を丸ごと試験側へ) | 0.823 | 0.423 | 0.000 | 1.451 |

正解率は 0.03 しか違わないが、稀なクラスの recall は 0.40 から 0 になった。ランダムな分割での 0.40 は、同じ地域の隣の行を覚えた分。地域ごとの分割の log loss は、`prior` の 0.569 より悪かった。新しい地域で稀なクラスを当てられるかを問うなら、地域で分け、地域ごと、クラスごとの誤差を並べる。

### 地域ごと、クラスごとの誤差

全体の指標が良くても、ある地域では稀なクラスを全部外していることがある。`--predictions-out` で行ごとの確率 (多クラスでは 1 行 × 1 クラスに 1 つ) を書き出し、地域 × 真のクラスごとに recall を数える。
