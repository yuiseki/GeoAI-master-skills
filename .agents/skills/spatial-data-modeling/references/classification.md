# 分類

目的変数がカテゴリ (紛争があったか、どの区分か) のときに、どのモデルにも加わる論点。`scripts/compare_models.py` は 0/1 の 2 クラスだけを扱う。

## 基準

学習側のクラスの割合をそのまま確率として出す (`prior`)。これより log loss が小さくならないモデルは、特徴量から何も学んでいない。`prior` の log loss は、クラスの割合 p の 2 値エントロピー -(p log p + (1 - p) log(1 - p)) になる。

正解率は基準にしない。陽性が 5% なら、全部を陰性と言うだけで正解率は 95%。

## 指標

| 指標 | 測るもの | 使う場面 |
|---|---|---|
| log loss | 確率の当たり方。自信を持って外すと大きく罰する | 確率をそのまま使うとき。主な指標にする |
| Brier | 確率と 0/1 の差の 2 乗の平均 | log loss より外れ値に穏やか |
| AUC | 陽性を陰性より上に並べられるか。しきい値によらない | 順位だけを使うとき。確率の当たり方は測らない |
| 正解率 | しきい値 0.5 で分けたときの当たり | しきい値を決めた後の説明 |

## クラスの偏り

- 分割は層化する (各分割でクラスの割合を揃える)。`compare_models.py` は行の分割では `StratifiedKFold` を使う。グループごとの分割では層化しないので、分割ごとの陽性の数を確かめる。陽性が 1 つも無い分割があると AUC が測れない。
- 陽性が少ないとき、重みを付けたり行を間引いたりすると、出てくる確率が実際の割合からずれる。確率を使うなら較正し直す。

## 確率の較正

モデルが 0.3 と言った行のうち、本当に 3 割が陽性か。モデルによって確率はずれる。ランダムフォレストの確率は 0 と 1 から離れる向きにずれやすいと報告されている (Niculescu-Mizil and Caruana 2005、ここでは未実測)。確率を使うなら、試験側の予測で較正の図を描き、必要なら学習側の中で較正する。

## しきい値

0/1 を決めるしきい値は、誤りの重さ (見逃しと空振りのどちらが重いか) で決める。0.5 に意味は無い。しきい値も学習側の中で決める。
