# ブースティング

浅い木を順に足し、前の木までの誤差を次の木が学ぶ。表形式のデータで予測の精度が高いことが多いが、行が少ないと線形に負けることもある (SKILL.md の例)。

## 実装

| 実装 | 特徴 (各実装の文書による) | 入れ方 |
|---|---|---|
| scikit-learn `HistGradientBoosting` | 特徴量をヒストグラムにまとめて速い。欠損をそのまま扱う | scikit-learn に入っている |
| XGBoost | 正則化の選択肢が多い | `uvx --with xgboost` |
| LightGBM | 葉ごとに木を伸ばして速い。カテゴリを扱える | `uvx --with lightgbm` |
| CatBoost | カテゴリをそのまま扱い、目的変数による符号化をリークしないように行う。左右対称な木 | `uvx --with catboost` |

`scripts/compare_models.py` に入っているのは `HistGradientBoosting` だけ。ほかの実装を比べるなら、同じ分割と同じ種で足す。

欠損: scikit-learn 1.9.1 の `HistGradientBoostingRegressor` は NaN を含む入力をそのまま学習した (2026-10-10 実測)。

## 早期打ち切り

木を何本まで足すかは、検証用の行の点数が良くならなくなったところで止めて決める。

- 検証用の行は学習側から取り分ける。試験側の行で止めると、試験側を見て木の本数を選んだことになり、評価が甘くなる。
- scikit-learn の `HistGradientBoosting` は既定 (`early_stopping='auto'`) では、行が 10,000 を超えるか、`fit` に検証用の行 (`X_val`、`y_val`) を渡したときだけ早期打ち切りをする (scikit-learn 1.9.1 の docstring)。打ち切るときの検証用の行は、学習側から無作為に取る (`validation_fraction`)。
- 空間データで学習側の行を無作為に取ると、検証用の行が学習用の行と同じ地域にあり、地域の特徴を覚えるほど検証の点数が良くなるので、止めるのが遅れる。グループの特徴を覚えれば当たる合成データ (40 群) で、内側をグループで分けると木の数は 1、行で無作為に分けると 59〜97 に選ばれた (テストの `_grouped_world`、種 5 つ、2026-10-16)。
- `compare_models.py` の `hgb` は、木の数を 100 まで、分割表から作った内側の分割 (外側と同じくグループやブロックを伏せ、時間は過去だけ) で、検証の損失の合計が最も小さい数に選び、学習側の全ての行で当て直す。

## 調整するもの

| 項目 | 効き方 |
|---|---|
| 学習率 | 小さいほど木が多く要り、安定する |
| 木の深さ、葉の数 | 大きいほど相互作用を拾い、合わせすぎやすい |
| 葉の最小の行数 | 大きいほど滑らか |
| 行と列の抜き取り | 木ごとのばらつきを増やし、合わせすぎを抑える |

調整は学習側の中の交差検証で行う。内側の分け方は外側と同じ依存の構造に合わせる。調整の範囲と、試した組み合わせの数を書く。多く試すほど、内側の交差検証の点数は楽観的になる。

## 学習範囲の外

木の和なので外挿しない。scikit-learn 1.9.1 の `HistGradientBoostingRegressor` は、x を 0 から 1 で学習した y = x を、x = 2 で 0.984、x = -1 で 0.026 と予測した (2026-10-10 実測)。
