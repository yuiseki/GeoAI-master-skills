# spatial-optimization

ソルバーが「最適」と言うのは、与えたモデルの中での最適でしかない。モデルが問いと違えば、最適な答えは間違った答え。解いたら、選んだ解から目的を計算し直し、手で組める解と比べる。最適解が手で組んだ解より悪ければ、モデルが間違っている。

| reference | 問題 |
|---|---|
| [p-median](references/p-median.md) | p か所を選び、需要から最寄りの施設までの重み付きの距離の合計を最小にする |
| [coverage](references/coverage.md) | p か所を選び、一定の距離以内に入る需要の重みを最大にする |
| [transport](references/transport.md) | 需要を容量のある施設へ、総コスト最小で割り当てる (輸送問題)。容量と需要の双対の値段、退化した問題での値段の幅 (`scripts/transport.py`) |

割当、輸送、LP の双対、CP-SAT、多目的はまだ書いていない (TODO.md)。

## 手順

1. 問いを、決定変数 (何を選ぶか)、目的 (何を良くするか)、制約 (何を守るか) で書く。言葉の問いと式がずれていないかを、小さな例で手で確かめる。
2. 入力を作る。需要の点と重み (WorldPop の人口など)、候補地、距離行列 (出発地、目的地、道のりの表。道路網から作るなら、最短経路の距離を全ての組について計算する)。たどり着けない組があれば先に扱う。
3. `scripts/facility_location.py` で、MILP と発見的な解の両方で解く。スクリプトは、選んだ施設から目的を計算し直し、ソルバーの値と食い違うか、最適解が発見的な解より悪ければ止まる。
4. 設定を変えて解き直す。p、半径、距離の測り方 (道のりか直線か)、需要の重み。答え (目的の値と選ぶ場所) がどう変わるかを書く。
5. 目的を変えて、同じ p で解き直し、選ぶ場所を並べる。被覆 (一定の距離以内の需要の重み) を最大にする解と、p-median (需要から最寄りの施設までの距離の合計) を最小にする解は、同じ場所を選ぶとは限らない。2 つの解で、共通する場所の数、それぞれの目的の値 (自分の目的と、相手の目的で測った値) を表にする。どちらの目的が問いの言葉に合うかを、使い道から書く。1 つの目的だけで解いて「最適な配置」と言わない。
6. 解の意味を確かめる。選んだ場所を地図で見る。目的の値を、1 単位の需要あたりの距離のような分かる量に直す。
7. 書き出す。

```sh
uvx --with numpy --with scipy --with duckdb python scripts/facility_location.py \
  tmp/matrix.parquet tmp/demand.parquet --problem p-median --p 1 3 5 10
uvx --with numpy --with scipy --with duckdb python scripts/facility_location.py \
  tmp/matrix.parquet tmp/demand.parquet --problem coverage --radius 500 --p 3 5 10
```

テストは `uvx --with numpy --with scipy --with duckdb --with pytest pytest scripts/test_facility_location.py`。小さな問題で、MILP が全ての組み合わせの総当たりと同じ最適値を出し、発見的な解はそれより悪くないこと、目的を計算し直すこと、どの候補にも届かない需要で止まること、施設の選び方が悪いのに自分の値は正しく報告する「最適解」を、発見的な解との比較で捕まえることを確かめている。割当の制約を外す、被覆の制約を外す、発見的な解との比較を外す、目的を計算し直さない、のそれぞれで落ちることを確かめてある。

## 目的が違えば、選ぶ場所が違う

日本の市区町村 1,741 (政令指定都市の区を除く、人口は 2020 年国勢調査、距離は代表点どうしの球面の距離、需要も候補地も同じ 1,741 か所、2026-10-14) から p=10 を選んだ。

| 解く問題 | 選んだ 10 か所 | 平均距離 (人口で重み付け) | 50 km 以内の人口の割合 |
|---|---|---:|---:|
| p-median (距離の合計を最小) | code5 01100、03214、04302、13114、16323、23100、27100、34205、40544、47208 | 52.2 km | 58.9% |
| coverage (50 km 以内の人口を最大) | code5 01429、10522、12231、14211、22461、23235、27100、33211、34431、40421 | 77.3 km | 68.2% |

- 2 つの解で共通するのは、大阪市 (27100) の 1 か所だけ。
- どちらの目的でも、自分の解が最良で、相手の解は劣る。p-median の解は平均距離が 1.5 倍短く、被覆の解は 50 km 以内が 9.3 ポイント多い。
- 問いが「近くに人がいる拠点」なら被覆、「平均的に近い拠点」なら p-median。1 つの目的だけで解いて「最適な配置」とは言えない。
- `facility_location.py` の p-median の MILP は、1,741 x 1,741 で 720 秒かかった (被覆は 2.7 秒)。発見的な解は 2.0 秒で、MILP の最適値より 1.7% 悪かった。p-median は、行数が千を超えると MILP が重いので、先に発見的な解を出し、時間を測ってから MILP に進む。

## 書き出すもの

- 問いの言葉と、決定変数、目的、制約
- 需要、候補地、距離の作り方と数
- 設定ごとの MILP の状態と値、発見的な解の値、解くのにかかった時間
- 被覆と p-median の 2 つの目的での解の比較 (共通の場所の数、互いの目的で測った値)
- 選んだ場所と、設定を変えたときの変わり方
- 目的を分かる量に直したもの (1 人あたりの距離、被覆の割合)
