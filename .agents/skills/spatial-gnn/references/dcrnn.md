# DCRNN の設定と計算

## モデル

拡散畳み込み (`DiffusionConv`):

  Z = Σ_{k=0}^{K} (θ_{k,f} P_fᵏ + θ_{k,b} P_bᵏ) X

K 段で K 歩先の感知器まで届く (テスト)。P X、P² X、… は T_k = 2 P T_{k−1} − T_{k−2} の漸化式で作る (著者の実装と同じ。厳密な P² ではないが、同じ数の行列の積で K 歩先まで届く)。GRU のゲートと候補の行列の積を、この畳み込みに置き換える (`DCGRUCell`)。符号化器が 12 時刻の入力を読み、復号器が 12 時刻を順に出す (`DCRNN`)。K = 0 では P⁰ = I だけが残り、隣を見ない (テスト)。

## 学習の設定 (著者の `dcrnn_bay.yaml`)

| 項目 | 値 |
|---|---|
| 入力 | 値と 1 日の中の時刻の割合。値は学習の平均と標準偏差で標準化 |
| 層、単位 | 符号化器と復号器に 2 層、64 単位、K = 2、前向きと後ろ向きの 2 つの酔歩 |
| 最適化 | Adam (eps 1e-3)、学習率 0.01 をエポック 20、30、40、50 で 0.1 倍、下限 2e-6、batch 64、勾配のノルムの上限 5 |
| 損失 | 標準化を戻した値の、欠けを除いた MAE (`masked_mae`) |
| 計画的なサンプリング | 復号器の入力を、確率 τ/(τ + exp(step/τ)) (τ = 2000、`teacher_prob`) で正解に、残りで前の時刻の予測に。評価のときは常に予測 (テスト) |
| エポック | 著者は 100、検証の MAE が 50 エポック良くならなければ止める。ここでは 60 (エポック 50 で学習率が下限に達し、以後ほとんど動かない)。最良の検証のエポックを使う |

PEMS-BAY の最良のエポックは K = 2 で 44 (検証の MAE 1.6160、12 の先の平均)、K = 0 で 54 (1.9557)。計画的なサンプリングの確率は、約 27 エポック (15,200 step) で 0.5、約 43 エポック (24,400 step) で 0.01 を下回る。学習率を下げる時期 (20〜50) と重なるので、エポックの上限を縮めると、正解を入れて学ぶ期間の割合が変わる。

## 計算の時間とメモリ

RTX 3060 (12 GB)、PyTorch 2.14.1、325 感知器、学習 36,465 試料 (batch 64 で 570 step):

| モデル | 1 エポック (検証を含む) | 60 エポック | GPU のメモリ |
|---|---|---|---|
| K = 2 | 約 275 秒 | 約 4.6 時間 | 2.5〜3 GB |
| K = 0 | 約 62 秒 | 約 1 時間 | |

学習の予算は、50 バッチの試走で 1 エポックの時間を測ってから、試験の点を見る前に決めて書く。2 本を同じ GPU に同時に載せると、他のサービスと合わせてメモリが足りなくなった。順に流す。

## データの読み方の落とし穴

- 著者の `pems-bay.h5` は Python 2 の pandas の HDF5 で、今の pandas では読めないことがある。h5py で `block0_values` (値)、`axis1` (時刻、ns)、`axis0` (感知器の ID) を直接読める。
- 隣接行列の pickle は読まず、距離の CSV から作り直す (グラフの reference)。
- numpy の 0 次元の配列 (npz から読んだ平均と標準偏差) を GPU のテンソルに掛けると型でつまずく。`float()` にしておく。

## 再現した値と、していないこと

- 再現した: PEMS-BAY の試験の MAE 1.3133、1.6583、1.9813 (論文 1.38、1.74、2.07、比 0.95 前後)。種 1 つ、60 エポック。
- 論文より少し良い理由 (PyTorch の実装、エポックの上限、種) は分けていない。
- 試していない: METR-LA (元の条件を確かめられない)、ほかの空間グラフのモデル (Graph WaveNet、STGCN、GMAN)、感知器の無い地点への予測、別の都市への持ち出し。
