# analysis-unit-design

分析の単位は、問いが何について答えを求めているかと、各データがどの細かさまで届いているかで決まる。
単位を決めずに結合を始めると、細かいデータを粗い単位に、粗いデータを細かい単位に、その場しのぎで合わせることになる。

## 手順

1. 問いの答えの 1 行が何かを書く。「国ごとの難民の数」なら国 × 年、「紛争の起きやすい場所」なら格子か行政区 × 期間。
2. 使うデータセットごとに、元の単位 (1 行が何か) と、その空間と時間の細かさを書き出す。dataset-discovery の reference の「粒度と範囲」を使う。
3. 候補の単位を 2〜3 個挙げ、各データをその単位にどう寄せるかを書く。細かいものを粗い単位に集めるのは集計で済む。粗いものを細かい単位に配るには仮定が要る (面積按分、人口按分など)。配るなら、その仮定を書く。
4. 候補ごとに実データで数える。
   - 単位の数 (標本の大きさ)。国なら 200 前後しかない
   - 単位あたりの件数の分布。0 の単位の割合、上位の単位への偏り
   - 単位の大きさのばらつき。国の面積は何桁も違うので、件数は人口や面積で割るかどうかを決める
   - 各データの位置の精度で、その単位に正しく入る件数
5. 1 つを主の単位に選び、残りを頑健性の確認用に残す。単位で結論が変わるかは maup-sensitivity で確かめる。

## 位置の精度と単位

点の座標がその単位より粗い精度で付いているなら、その点はその単位に正しく入らない。

UCDP GED の `where_prec` と、正しく入る単位 (コードブック 26.1 の定義から):

| `where_prec` | 座標が表すもの | 入る単位 |
|---:|---|---|
| 1, 2 | 正確な場所か 25km 以内 | 0.5 度格子、第 1 階層の行政区、国 |
| 3 | 第 2 階層の行政区の代表点 | 第 1 階層の行政区、国 (0.5 度格子は行政区の大きさ次第) |
| 4 | 第 1 階層の行政区の代表点 | 第 1 階層の行政区、国 |
| 5 | 線や曖昧な範囲の代表点 | 国 (範囲次第) |
| 6 | 国しか分からない | 国 |
| 7 | 公海か国際空域 | どの国にも入らない |

細かい単位を選ぶほど、使える件数が減るか、精度の粗い点が偽の集積を作る。どちらを取ったかを書く。

## このリポジトリのデータで取れる単位

| 単位 | 作り方 | 元から持つデータ | 寄せられるデータ |
|---|---|---|---|
| 国 × 年 | Natural Earth の `ne_10m_admin_0_countries` | WDI、UNHCR (庇護国か出身国) | 空港、UCDP の点を国の面で集計 |
| 国の組 × 年 | 出身国と庇護国の組 | UNHCR | 国 × 年の属性を両端に付ける |
| 第 1 階層の行政区 | Natural Earth の `ne_10m_admin_1_states_provinces` (4,596 区) | なし | 空港、UCDP の点 (`where_prec` 4 以下) |
| 0.5 度格子 × 年 | UCDP の `priogrid_gid` | UCDP | 空港の点。国の属性は格子に配ることになる |
| 点 | 元の点 | 空港、UCDP | 周りの密度や距離を特徴量にする |

UCDP の `priogrid_gid` は PRIO-GRID の 0.5 度格子の番号で、`floor((緯度 + 90) / 0.5) * 720 + floor((経度 + 180) / 0.5) + 1` と一致する (26.1 で 417,968 件中 417,920 件、2026-10-10 実測)。事件のある格子は 8,003 個で、事件の無い格子は行として存在しない。格子を単位にするなら、陸の格子を全部作ってから 0 を埋める。

## 書き出すもの

- 主の単位と、1 行が何を表すか
- 単位の数と、期間
- データセットごとに、どうその単位に寄せたか (集計、按分、そのまま) と、寄せられずに落ちた件数
- 0 の単位の割合と、件数を何で割るか
- 頑健性の確認に使う別の単位
