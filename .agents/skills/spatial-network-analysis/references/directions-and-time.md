# 向き、曲がれる交差点、時間

向きの無いグラフで測った車の道のりは、実際に走れない経路を含む。距離で選んだ経路は、時間で選んだ経路と違う。`scripts/routing.py` は、向きのある辺 (arc)、曲がれない交差点、U ターン、速度からの時間を、小さなグラフで確かめるための道具で、経路探索のエンジンではない。広い範囲で時間の経路を大量に求めるなら、自前の経路探索のサービス (dataset-discovery の references/services/) を使い、その設定 (モード、速度の表) を書く。

## 向きのあるグラフ

| 道 | arc |
|---|---|
| 両方向 | u → v と v → u の 2 本 |
| 一方通行 (`oneway=yes`) | u → v の 1 本 |
| 逆向きの一方通行 (`oneway=-1`) | v → u の 1 本 |

一方通行を無視すると、走れない向きの経路を数える。`routing.py` のテストでは、A → B だけが通れる道で C から A へは車でたどり着けない (無限大) が、向きを無視すると 200 m の経路ができた。歩行者は一方通行の逆向きにも歩ける。

`oneway` の他にも向きを決めるタグがある (環状交差点の `junction=roundabout` は一方通行を含意する、自転車だけ逆向きに通れる `oneway:bicycle=no`)。使ったタグと、使わなかったタグを書く。

### 実データ: 台東区の車の道

osm-tokyo23-src-2026-08 の台東区の道路 (区の境界で切ったもの) から、歩道、階段、通路、工事中などを除いた車の道 11,532 本を、頂点を共有する所でつないだ (頂点 51,113、区間 60,618、うち一方通行 45.9%。2026-10-15)。

| 項目 | 値 |
|---|---:|
| 向きを無視したときの最大の連結成分 | 50,837 頂点 |
| 向きを入れたときの最大の強連結成分 (互いに行き来できる) | 48,791 頂点 (96.0%) |
| 無作為な 300 組のうち、向きを入れると届かない組 | 14 (4.7%) |
| 強連結成分の中の 272 組: 向きあり ÷ 向きなしの道のり | 中央値 1.024、90% 点 1.110、最大 2.14 |
| 5% より長くなった組 | 25.7% |
| 道のりが変わらなかった組 | 7.7% |
| 長くなった距離 | 中央値 76 m、90% 点 270 m (向きなしの道のりの中央値 3,727 m) |

向きを無視すると、4 組に 1 組で道のりを 5% 以上短く測り、20 組に 1 組は走れない組を走れると数えた。届かない組の多くは、区の境界で切ったために、外へ出て戻る道が無くなった組と考えられる (推測。範囲の端の効果は building-the-graph.md)。曲がれない交差点はこのデータに無い (osm2pgsql の道路の表は relation の turn restriction を持たない) ので、実際の差はこれより大きいはず。

## 曲がれない交差点と U ターン

曲がれない交差点は、「この辺から、この節点で、この辺へは進めない」という 3 つ組 (OSM の `restriction=no_left_turn` などの relation、Overture の `prohibited_transitions`)。節点だけを状態にした Dijkstra では表せない。`routing.py` は、直前に通った arc を状態にして探索する。

テストのグラフ (A → B → C が左折禁止、B → E → F → C の迂回あり) では、禁止を無視すると 200 m、守ると 400 m だった。迂回路の無いグラフでは、守ると届かず、U ターンを許すと B → E で折り返して 400 m になった。U ターンを許すかは、モードと道の種類で決まる仮定。`routing.py` の既定は許さない。

`only_straight_on` などの「これしか進めない」形は、他の全ての向きの禁止に展開してから渡す。

## 速度から時間

時間 = 長さ ÷ 速度。長さを m、速度を km/h で持つなら、時間 (秒) = 長さ ÷ (速度 ÷ 3.6)。

- `maxspeed` は文字列。`50` と `50 km/h` は km/h、`30 mph` は 48.3 km/h。`none`、`signals`、`walk` などは速度でないので None にする。
- `maxspeed` は上限で、実際の速さではない。混雑、信号、曲がる時間は入らない。時間の結論は「上限の速さで走ったとき」の値と書く。
- 速度の無い道に、道の種類から速度を仮定するなら、仮定の表を書き、仮定した arc の数を数える (`travel_times` が返す)。仮定の無い種類の道があれば、`routing.py` は止まる。黙って速度を埋めない。
- 歩行は一律の速さ (4〜5 km/h。不動産の表示は分速 80 m) を仮定することが多い。坂、階段、信号の待ちは入らない。

最短の道のりと、最短の時間の経路は違う。テストのグラフで、住宅地の道を真っすぐ 1,000 m (20 km/h で 180 秒) と、幹線道路を回る 1,500 m (60 km/h で 90 秒) では、道のりは前者、時間は後者が短い。問いが「どれだけ遠いか」か「何分かかるか」かを先に書き、重み (`length_m` か `time_s`) をそれに合わせる。

## 歩行、自転車、車で違うグラフ

| モード | 入れない道 (`routing.py` の仮定) | 一方通行 |
|---|---|---|
| 車 | 歩道、階段、通路、歩行者専用、自転車道、乗馬道、林道 | 守る |
| 自転車 | 自動車専用道とその出入口、階段 | 守る (`oneway:bicycle=no` は未対応) |
| 歩行 | 自動車専用道とその出入口 | 守らない |

この表は仮定で、国と道ごとの規則 (日本の自転車の歩道の通行、歩行者の通れない高架道路など) を全部は表さない。同じ 2 点の間でも、モードで道のりも届く範囲も変わる。モードを問いの言葉から決め、入れた道の種類を書く。

## 点を寄せる

出発地と目的地を、最寄りの節点に寄せる (`snap`)。寄せた距離を必ず書き、上限 (`max_m`) を超えた点を数える。上限は問いで決める (歩いて駅まで、なら数十 m)。寄せた先が小さな孤立した成分なら、どこにも届かない (measures.md の上野駅の例)。向きのあるグラフでは、寄せた節点が強連結成分の外 (行けるが戻れない袋小路) にあることもある。寄せた節点が、出発と到着の両方の向きで届くかを確かめる。

## 届かない組

届かない組は無限大のまま数え、0 や大きな数で埋めない。向きを入れると、向きなしでは届いた組が届かなくなる (台東区で 4.7%)。届かない理由 (範囲の端、一方通行の袋小路、孤立した成分) を分けて書く。
