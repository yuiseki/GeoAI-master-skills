# location-privacy

位置は、名前が無くても人を指す。自宅の点は世帯を、夜と昼の点の組は個人を、珍しい場所への訪問は病気や信仰を指しうる。処理をしたから安全、とは言えない。ずらした点も、住宅の位置、道路、別の公開データと突き合わせれば、元の場所に戻せることがある。処理の後で攻撃を模擬し、残る危険と、失われた分析の精度を、両方とも数えて書く。

扱うのは、研究や分析で位置のデータを使い、共有し、公開する前の判断。データの正しさ (位置の誤差、欠落) は、このスキルの外。法律の解釈は扱わない。判断に迷うものは、所属の研究倫理の窓口に相談する。

## 手順

1. 何をするかを書く。手元での分析だけか、共同研究者への共有か、論文の図か、データの公開か。公開の範囲が広いほど、取り消せない。同じデータでも、段ごとに判断が違う。
2. 位置が何を、誰を指すかを書く。人、世帯、建物、施設、生物の生息地。直接の識別子 (名前、住所、電話) と、間接に指しうるもの (正確な座標、時刻の列、年齢と性別、珍しい属性) を分けて並べる ([risks](references/risks.md))。
3. 配慮の要る場所と人を洗い出す。医療、精神科、依存症の施設、犯罪の被害の場所、子ども、難民と移民、家庭内暴力の避難所、信仰の場所、性的少数者の集まる場所、希少な生物の生息地。ここに当たるものは、集計した値でも、少ない数のセルから辿れないかを確かめる。
4. 結合の相手を想定する。住所や建物の点、道路網、地図の写真、公開されている別の統計、同じデータの別の版や別の切り口。攻撃する側が何を持っているかで、危険が決まる。
5. 使ってよいかの根拠を、別々に確かめる。データの利用規約とライセンス (再配布してよいか)、同意 (何に使うと説明して集めたか)、研究倫理 (審査、対象者への害)。規約が許しても、倫理の上で公開してよいとは限らない。公開されているデータも、集めて結合し再公開すれば、新しい危険を作りうる。
6. 守り方を選ぶ ([protections](references/protections.md))。分析に要る細かさまで粗くする、集計して少ない数を秘匿する、点をずらす、時刻を粗くする、アクセスを制限して公開しない。分析は細かい元のデータで手元で行い、公開は結果だけ、という分け方も選べる。
7. 攻撃を模擬する (`scripts/privacy_check.py`)。ずらした点から最寄りの住宅を当てる、セルに 1 件しかない数を探す、同じ点の別のずらし方を平均する、軌跡の夜の点から自宅を当てる。密な所と疎な所で分けて数える。処理の前と後を並べる。
8. 分析の結論が変わらないかを確かめる。処理した後のデータで同じ分析をして、元のデータの結果と並べる。比、境界の近くの割当、距離、少ない数の地域の値は、処理で動きやすい。秘匿したセルは 0 でなく、値の幅として扱う。
9. 決めたことを書き、残る危険を書く。

## 書き出すもの

- 使い方の段 (手元、共有、公開) と、それぞれで渡すもの
- 位置が指すもの、直接と間接の識別子、配慮の要る場所と人
- 規約、ライセンス、同意、倫理の審査を、それぞれ何で確かめたか
- 選んだ守り方と、その値 (セルの大きさ、最小の数、ずらす距離、時刻の細かさ、アクセスできる人)
- 模擬した攻撃と、前後の再識別のしやすさ (密な所と疎な所で分けて)
- 守り方で分析の結論がどれだけ動いたか、秘匿したセルの扱い
- 残る危険と、守れないと判断して公開しなかったもの
