# point-pattern-analysis

点が集まっているかどうかは、何と比べるかで決まる。一様な配置と比べると、ほとんどの点は「集まっている」。人は一様に住んでいないので、人に関わる点は人の住む所に集まるのが当たり前だからだ。比べる基準の分布を先に決め、それを書く。

このスキルは、集まっているか、どの距離でかを測る。点がどんな確率過程から生まれたか (強度が説明変数でどう変わるか、残った集まりは環境か引き合いか) をパラメータの推定と模擬で比べるのは、別の問い。

| reference | 中身 |
|---|---|
| [ripley](references/ripley.md) | 距離ごとの点の組の数 (Ripley の K) と、無作為な配置との比べ方 |
| [baselines](references/baselines.md) | 比べる基準の分布の選び方 |
| [kernel-density](references/kernel-density.md) | 点の強度の地図。帯域の交差検証、端の補正、帯域で山の数が変わること (`scripts/kernel_density.py`) |
| [cross](references/cross.md) | 2 種類の点の間の組の数を、種類だけを入れ替えた配置と比べる (クロス K と random labelling) |

## 手順

1. 問いを書く。「ヘリポートは、人の住む所に沿う以上に集まっているか」。
2. 比べる基準を決める (references/baselines.md)。少なくとも 2 つ (一様と、問いに合った分布) で比べる。
3. 点の位置の精度を確かめる (データの説明か、実データの座標の桁数と重なり具合で)。精度が粗い点 (行政区の代表点) は、その大きさより短い距離で偽の集まりを作る。
4. `scripts/point_pattern.py` で、距離ごとに観測した点の組の数を、基準から無作為に置いた点の組の数と比べる。
5. 基準の外にある点 (基準の分布で置けない場所の点) の数を書く。
6. 集まっている距離と、その倍率を書く。どこが集まりを作っているかを、点の中身 (名前、種類、地域) で確かめる。

```sh
env -u GDAL_DRIVER_PATH -u GDAL_DATA -u PROJ_DATA -u PROJ_LIB \
  uvx --with numpy --with scipy --with rasterio --with duckdb python scripts/point_pattern.py \
  hf://datasets/yuiseki/ourairports-2026-08/parquet/airports.parquet tmp/jpn_pop_2020_1km.tif \
  --where "iso_country = 'JP' and type = 'heliport'" --baseline values --radii 1 2 5 10 25 50
```

基準のラスタは EPSG:4326 の GeoTIFF。WorldPop の人口 (dataset-discovery の references/worldpop/) がそのまま使える。anaconda の GDAL の環境変数を外す理由も、そこに書いてある。

テストは `env -u GDAL_DRIVER_PATH -u GDAL_DATA -u PROJ_DATA -u PROJ_LIB uvx --with numpy --with scipy --with rasterio --with duckdb --with pytest pytest scripts/test_point_pattern.py`。距離が大円距離であること、基準から置いた点は集まって見えないこと、人口に沿って置いた点は一様な基準と比べると集まって見え、人口の基準と比べると見えないこと、面積の基準が緯度による面積の違いを入れていること、基準の外の点を数えることを確かめている。面積の重みから緯度を外す、自分自身との組を数える、基準の重みを無視する、のそれぞれで落ちることを確かめてある。2 種類の点の組の数が総当たりと一致すること、引き寄せられた種類を random labelling が見つけ独立な種類を見つけないこと、共通の背景にだまされないこと、間隔を保った点が散らばって見えることも確かめ、組の片方を同じ種類にする、入れ替えをしない、のそれぞれで落ちる。

## 基準、境界、包絡線

- 一様な基準 (`area`) との比較は、完全な空間的ランダム (CSR、一様ポアソン過程) との比較。点が人の住む所や道路に沿って起きるなら、集まって見えるのは当然で、問いの答えにならない。背景の密度 (人口、建物、道路) に比例して点を置く基準 (`values`) が、非一様ポアソン過程との比較になる。別の種類の点 (対照、たとえば全ての施設) を基準にする比較 (ケースと対照) も、同じ考え方。
- 境界の近くの点は、境界の外に相手を持てないので、組の数が少なく出る (エッジ効果)。`point_pattern.py` は、比べる点を観測と同じ範囲 (基準のラスタの値のある範囲) に置くので、エッジ効果は両側に同じく入り、補正は要らない。ただし、範囲が点の起きうる範囲より狭い (国境の外にも点が起きる) と、外の相手を数え落とす。範囲を書き、範囲の端から距離 r 以内の点の割合を書く。
- 95% の包絡線は、距離ごとの判定。距離を多く並べると、どこかで偶然はみ出す。はみ出した距離を有意な集まりと言うなら、事前に決めた 1〜2 の距離に絞るか、距離全体で 1 回だけ判定する方法 (global envelope test) を使う。それ以外は記述として書く。

## 書き出すもの

- 問いと、比べた基準 (少なくとも 2 つ)
- 点の数、基準の外の点の数、位置の精度の扱い
- 距離ごとの観測、無作為な配置の中央値と 95% の範囲、倍率
- 集まりを作っている場所と点の中身
