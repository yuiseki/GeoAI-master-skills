# spatial-feature-engineering

空間特徴量は、何を測るつもりかを先に書いてから作る。半径や近傍の数を、モデルの点数が良くなるように後から選ぶと、評価が実力より良く見える。

## 手順

1. 特徴量ごとに、何を測るつもりか (仮説) を 1 行で書く。「空港が近い場所ほど事件の報告が多い」なら、事件から最寄りの空港までの距離。
2. 種類 (下の表)、参照するデータ、尺度 (半径、近傍の数、期間) を決める。尺度は 2〜3 個を先に決めて全部作る。
3. 作る。距離はメートルかキロメートルで測る (距離関数の座標の順と単位はツールごとに違う。小さな例で、既知の 2 点の距離と合うかを確かめる)。
4. 分布を見る。0 の割合、上限で打ち切られた割合、外れ値、尺度の違う特徴量どうしの相関。
5. 下の「気をつけること」を 1 つずつ確かめる。
6. 書き出す。

## 特徴量の種類

| 種類 | 例 | 作り方 |
|---|---|---|
| 半径内の数、密度 | 50 km 以内の空港の数 | `scripts/point_neighbors.py`。密度にするなら円の面積で割る |
| 最寄りまでの距離 | 最寄りの空港までの km | `scripts/point_neighbors.py` の `nearest_km` |
| 線や面までの距離 | 海岸線、国境までの km | 線との最近点を取り、球面の距離で測る |
| 面との重なり | 単位の中の市街地の割合 | 単位と面の交差の面積を、投影してから測る |
| 近傍の値の集計 | 周りの単位の目的変数の平均 (空間ラグ) | 下の「リーク」を必ず読む |
| 過去の値 | 前年の件数 | 予測する時点より前の期間だけから作る |

## 点の周りを数える

`scripts/point_neighbors.py` は、問い合わせの点ごとに、参照の点が各半径の中にいくつあるかと、最寄りの参照点までの距離を出す。点を単位球の 3 次元座標に置き、最大半径の弦の幅の立方体で候補を絞り、弦の長さで判定するので、高緯度でも日付変更線をまたいでも正しい大円距離 (半径 6,371 km の球) になる。

```sh
uvx --from 'duckdb>=1.5.5' python scripts/point_neighbors.py \
  hf://datasets/yuiseki/ucdp-ged/parquet/26.1/ged.parquet id \
  hf://datasets/yuiseki/ourairports-2026-08/parquet/airports.parquet id \
  --radii-km 50 200 --query-where "where_prec <= 2" \
  --reference-where "type in ('large_airport', 'medium_airport') and scheduled_service = 'yes'" \
  --out tmp/ged_airports.parquet
```

- 問い合わせと参照が同じデータなら `--exclude-self` で自分自身を数えない。
- 最大半径の中に参照点が 1 つも無ければ `nearest_km` は NULL。0 で埋めない (下の「打ち切り」)。
- 上の例は問い合わせ 295,780 点、参照 3,268 点で、約 11 秒、メモリ 320 MB だった (2026-10-10)。無作為の 221 点を総当たりの haversine と比べ、件数は全て一致し、距離の相対誤差は 1e-12 未満だった。
- テストは `uvx --from 'duckdb>=1.5.5' --with pytest pytest scripts/test_point_neighbors.py`。

## 過去の値の特徴量

時間のある単位 (国 × 年、格子 × 月) では、前の期間の値、直近の平均、それまでの累積が強い特徴量になる。どれも、各行の時点より前の値だけから作る。今の時点の値を混ぜると、答えの言い換えになる。

`scripts/lag_features.py` は、単位 × 期間の表から、各行について `lag{k}` (k 期間前の値)、`mean{w}` (直前の w 期間の平均)、`total_before` (それより前の合計) を作る。

```sh
uvx --with numpy --with duckdb --with pyarrow python scripts/lag_features.py tmp/table.parquet UNIT TIME VALUE \
  --lags 1 12 --windows 3 12 --cumulative --out tmp/lags.parquet
```

- 期間は整数 (年、または起点から数えた月)。欠けた期間は 0 ではなく欠け。k 期間前が欠けていれば `lag{k}` は NaN、直前の w 期間のどれかが欠けていれば `mean{w}` は NaN。
- 行の並びではなく期間で数える。表の行が期間の順に並んでいなくても、期間が飛んでいても正しい。
- 1 つの単位に同じ期間の行が 2 つあると止まる。
- 例: UCDP の国 × 月 (20 か国 × 444 か月、`tmp/ucdp_country_month.parquet`) から作ると、`lag12` と `mean12` は各国の最初の 12 か月が NaN (240 行)。
- 予測の時点より先を当てるなら (h 期間先)、`lag1` ではなく `lag{h}` 以上だけを使う。予測を使う時点で分かっている値だけを入れる。

テストは `uvx --with numpy --with duckdb --with pytest pytest scripts/test_lag_features.py`。ラグと平均と累積が前の期間だけを使うこと、単位をまたがないこと、行の順と期間の欠けに正しく従うこと、白色雑音の今の値と相関しないことを確かめている。平均に今の値を入れる、累積に今の値を入れる、行の順で数える、のそれぞれで落ちることを確かめてある。

## 分母の小さい割合

単位の中の割合 (POI のうち宿泊の割合、空港のうちヘリポートの割合) は、分母が小さいと偶然で大きく振れる。以前の分析では、POI が数件の 1 km 格子が「宿泊 20%」の外れ値になり、k-means の型を 1 つ使った。

`scripts/shrink_rates.py` は、各単位の割合 x / n を (x + a) / (n + a + b) に置き換える (経験ベイズ、ベータ二項分布)。a / (a + b) は全体の割合、a + b (事前の強さ) は、割合のばらつきのうち二項分布の偶然では説明できない分から、モーメント法で求める。分母が a + b ほどの単位は、自分の割合を半分残す。割合のばらつきが偶然と変わらなければ、全ての単位が全体の割合になる。

```sh
uvx --with numpy --with duckdb --with pyarrow python scripts/shrink_rates.py tmp/table.parquet ID COUNT DENOMINATOR --out tmp/rates.parquet
```

例: 国ごとの、空港のうちヘリポートの割合 (OurAirports 2026-08、247 か国、全体 0.270、2026-10-10)。事前の強さは 4.8。バチカン (1 / 1) は 1.000 から 0.395 に、モナコ (3 / 3) は 0.550 に縮む。国の間の本当のばらつきが大きいので、縮め方は弱い。

テストは `uvx --with numpy --with duckdb --with pytest pytest scripts/test_shrink_rates.py`。分母の小さい単位が全体の方へ動き大きい単位は動かないこと、縮めた割合が本当の割合に近いこと、本当のばらつきが無ければ全体の割合になること、分母 0 の単位の扱いを確かめている。偶然の分を引かない、縮めない、のそれぞれで落ちることを確かめてある。

## 気をつけること

自分自身を数える。 同じデータの点どうしで数えると、各点が自分を 1 と数える。`--exclude-self` を使うか、1 を引く。

リーク。 近傍の目的変数を特徴量にすると、試験に使う単位の答えが学習の単位の特徴量に入る。交差検証の分割ごとに、学習側の単位だけから近傍の値を作り直す。同じ源から目的変数と特徴量を作ると (事件の数を目的変数にし、半径内の事件の数を特徴量にする)、答えの言い換えになる。疑わしいものは、特徴量を 1 つずつ外して点数の落ち方を見る、目的変数と特徴量の相関が高すぎないかを見る、などで監査する。

未来の値。 時間のある単位では、特徴量は予測する時点より前のデータだけから作る。参照データ自体が後の時点のもの (2026 年の空港の一覧を 1990 年の事件に使う) なら、そう書く。

端の効果。 参照データの範囲の端 (1 国だけのデータの国境、海岸) の近くでは、外にある参照点が数えられず、数が小さく、距離が大きく出る。それが実際の少なさか、データの切れ目かを区別する。端からの距離を一緒に記録するか、端の近くを除いて結論が変わらないかを見る。

打ち切り。 最大半径の外は「この距離より遠い」としか分からない。NULL を 0 や平均で埋めない。上限の値で埋めて、打ち切ったかどうかの 0/1 の列を足す。

尺度。 半径を 1 つに決め打ちしない。先に決めた 2〜3 個の尺度で結論が変わるかを見る。尺度は試験の点数で選ばない。

分布の偏り。 件数は右に長く裾を引き、0 が多い。線形のモデルに入れるなら `log1p` を検討する。

## 書き出すもの

特徴量ごとに 1 行。

|---|---|---|---|---|---|---|
