# sar-change-detection

SAR の変化は、比べる 2 つの時点と、比べる相手の場所で意味が決まる。「浸水した所は暗くなる」は開けた水面の話で、市街地の浸水はむしろ明るくなることがある。どちら向きの変化を数えるかを先に決め、両方を測る。

## 扱う範囲

扱うのは、同じ軌道から撮った線形の後方散乱 (γ0 か σ0) の、前と後の比。1 つの出来事について、決まった組 (記録の面、河道、想定の区域、対照) の画素の割合を比べる。

扱わないもの: 画像の分類、セグメンテーション、物体検出、深層学習、干渉 (InSAR) と位相、偏波の分解、GRD から RTC を作る処理 (放射量の補正と地形の補正)。データセットの事実 (コレクション、署名、ファイル名、測った位置のずれ) は `dataset-discovery/references/` にある。

| reference | 中身 |
|---|---|
| [scenes](references/scenes.md) | 撮影の選び方。同じ軌道、前の撮影を何枚、出来事の時刻と撮影の時刻、雨の最中と後、衛星の違い、偽の日付と後の撮影 |
| [backscatter](references/backscatter.md) | 変化の向きの読み方。開けた水面は暗く、建物と水の二回反射は明るく、雨の最中は一様に明るい。読みのうち確かめたことと、外の知識による解釈 |
| [controls](references/controls.md) | 比べ方。陽性の対照、土地被覆をそろえた対照、塊とブロックの区間、偽の日付、元に戻るか、場所を知らずに探す、ほかの記録との一致度 |

## 手順

1. 問いを書く。何の出来事の、どの時点の、どの場所の、どちら向きの変化を数えるか。「記録の面は、対照より多く暗くなったか」「記録の面の市街地は、対照より多く明るくなったか」。両方の向きを主張にする。暗くなる向きだけを主張にすると、市街地の浸水を見落とす。
2. 出来事の時刻を、気象庁や国土交通省などの記録で確かめる。記憶で書かない。いつ雨が止み、いつ水位が最大になり、いつ水が引いたか。
3. 撮影を選ぶ ([scenes](references/scenes.md))。同じ相対軌道の、前の撮影を 3 枚以上 (平均して斑点の雑音を減らす)、出来事の後の 1 枚、さらに後の 1〜2 枚 (元に戻るか)。撮影の時刻を出来事の時刻と並べて書き、雨の最中か後かを分ける。衛星 (S1A と S1B) が混ざるかも書く。
4. 計画を固定する。閾値 (±3 dB など)、平滑化の大きさ、偏波、組の定義、対照の取り方、判断の規則を、画像を見る前に書いてコミットする。
5. 同じ格子に、線形の値のまま積む。dB で平均しない (dB の平均は幾何平均で、暗い外れに引かれる)。
6. `scripts/sar_change.py` で、前の平均と後の撮影の差 (dB) を作る。恒常的な水の面 (WorldCover の水など) を `--water` に渡し、前の平均の位置のずれを測る。1 画素を超えるずれは、整数の画素で戻す。後の撮影の前の平均に対するずれ (`post_vs_pre_shift_rows_cols`) が 0 に近いことも確かめる。

   ```sh
   uvx --with numpy --with scipy --with scikit-image --with rasterio python scripts/sar_change.py \
     --pre tmp/pre_*.tif --post tmp/post.tif --water tmp/water.tif --k 3 --threshold 3 --out tmp/delta.tif
   ```

7. 組の格子を作る。整数の符号で、0 は使わない画素、対照にも符号を付ける。陽性の対照 (水が確かに出た所。河川の高水敷、堤防の間) を必ず入れる。対照は、記録の面と想定の区域と河道から離した画素にする ([controls](references/controls.md))。
8. `scripts/change_rates.py` で、組ごとに暗くなった割合と明るくなった割合を、土地被覆をそろえた対照と比べる。区間は、画素ではなく塊 (`--components`) か 1 km のブロック (`--block`) で引き直す。市街地の明るさを問うなら、市街地の画素だけの組の格子でも流す。

   ```sh
   uvx --with numpy --with scipy --with rasterio python scripts/change_rates.py --delta tmp/delta.tif \
     --groups tmp/groups.tif --classes tmp/landcover.tif --control 9 --components 1 --block 1000 --n 2000 > tmp/rates.json
   ```

9. 陽性の対照から読む。陽性の対照で変化が出ないなら、手順か撮影が水を見られていない。その先の「出なかった」を読まない。
10. 頑健性を流す。閾値 (±2、±4 dB)、平滑化 (1、5)、偏波 (VH、VV か VH)、前の撮影 (直前の 1 枚だけ)、位置を戻さない、衛星の違いの補正 (対照の差の中央値を引く)。どれで判断が変わるかを表にする。
11. 結果を見た後の確認を足し、確認と探索を分けて書く。偽の日付 (出来事の前の 2 つの撮影の比)、後の撮影で元に戻るか、場所を知らずに区画を並べて記録の場所が上位に出るか、ほかの記録 (自治体の地図など) との重なり ([controls](references/controls.md))。
12. 書き出す。ほかの記録との一致は、一致度であって真の精度ではないと書く。明るくなった所を「浸水した」と断定しない。

## スクリプト

| スクリプト | 入力 | 出力 |
|---|---|---|
| `sar_change.py` | 前の撮影 (複数) と後の撮影の GeoTIFF (同じ格子、線形)、任意で水の面 | 差の GeoTIFF (dB、float32、欠けは nan) と、画素の数、ずれ、閾値を超えた数の JSON |
| `change_rates.py` | 差、組の符号、土地被覆のクラスの GeoTIFF (同じ格子) | 組ごとの割合、土地被覆をそろえた対照の割合、比、90 % 区間の JSON |

どちらも格子 (CRS、変換、形) が違えば止まる。全ての画素を数え、合わなければ止まる (`sar_change.py` は有効、前が無い、後が無い。`change_rates.py` は欠け、組の外、組ごとの数)。前の撮影の一部だけが欠ける画素は、残りの撮影で平均する。

テストは次のとおり (scripts の中で流す)。

```sh
uvx --with numpy --with scipy --with scikit-image --with rasterio --with pytest pytest -q test_sar_change.py
uvx --with numpy --with scipy --with rasterio --with pytest pytest -q test_change_rates.py
```

前の撮影を線形で平均すること、平滑化してから比をとること、位相相関で既知のずれを戻すこと、格子が違えば止まること、対照を土地被覆の割合で重み付けすること、少ないクラスを落としてその割合を出すこと、画素でなく単位で引き直すことを確かめている。線形の平均を dB の平均に変えると、また重み付けを全体の率に変えると、テストが落ちることを確かめた (2026-11-04)。

## 実データでの確認

2026-11-04 に、台風第 19 号 (2019-10-12〜13) の東京の、Planetary Computer の sentinel-1-rtc の軌道 46 (前 6 枚、後 1 枚、VV) で流した。組は東京都の浸水実績図データの 2019 年の面 (塊で引き直す)、多摩川の河道、対照で、別に書いた分析のコード (リポジトリの `projects/_flood/hagibis-tokyo-sar-flood-record/scripts/03_blocks.py`、`outputs/blocks.json`) の結果と比べた。

| 量 | このスキル | 別の分析のコード |
|---|---|---|
| 位置のずれ (行、列) | 0.35、2.35 | 0.35、2.35 |
| 河道の暗くなった割合、対照、比 | 0.3561、0.0446、7.982 [6.6437, 9.6064] | 0.356、0.0446、7.98 [6.6425, 9.6038] |
| 記録の面の暗くなった割合、対照、比 | 0.0213、0.0184、1.1589 [0.3247, 1.3194] | 0.0213、0.0184、1.159 [0.295, 1.3199] |
| 記録の面の市街地の明るくなった割合、対照、比 | 0.1032、0.0185、5.5828 [3.7531, 7.4051] | 0.1032、0.0185、5.582 [3.7629, 7.419] |

点の値は一致した。区間の端が少し違うのは、乱数の引き方の順が違うため。位置を戻した後に端の 2 列 (4,588 画素) が欠ける。このスキルは差を作ってから戻し、別のコードは積んだ撮影を戻してから差を作るが、ずれが整数なので値は同じになった。`GEOAI_REALDATA=1` で流れる照合のテストは、まだ無い。

## 適用できない条件

- 前と後で軌道 (相対軌道、上りと下り) が違う撮影。見る向きが違うと、変化が無くても値が変わる。
- 線形でない値 (dB の GeoTIFF)。`sar_change.py` は 0 以下を欠けとみなすので、dB を渡すとほとんどが欠ける。
- 格子の合っていない撮影。再投影と再標本化はこのスキルの外。
- 平滑化は k × k の箱だけ。Lee などの適応型のフィルタは無い。
- 閾値で 2 値にした割合だけを比べる。差の分布そのものの比べや、閾値を自動で決める方法 (Otsu など) は無い。
- 位置のずれは、画像全体で 1 つの平行移動とみなす。場所で変わるずれは測らない。
