# 形と位相

数字は 2026-10-14 に shapely 2.2.0 で測り、`scripts/test_geometry_facts.py` に残した。DuckDB spatial の述語も同じ定義 (DE-9IM) に従う。

## 述語の違い

1 × 1 の正方形と点で測った。

| 点 | contains | covers | intersects | touches | within |
|---|---|---|---|---|---|
| 内側 | 真 | 真 | 真 | 偽 | 真 |
| 辺の上 | 偽 | 真 | 真 | 真 | 偽 |
| 角の上 | 偽 | 真 | 真 | 真 | 偽 |
| 外側 | 偽 | 偽 | 偽 | 偽 | 偽 |

- `contains` は、境界の上の点を含まない。点を面に数えるとき、境界の上の点は `contains` ではどの面にも入らず、`intersects` や `covers` では隣り合う 2 つの面に入る。どれを使ったかと、境界の上の点の数を書く。
- `touches` は、境界だけを共有し、内側が重ならないとき真。2 つの面が少しでも重なると偽になる (1e-4 の重なりで偽)。隣接を `touches` で取ると、重なる境界を持つデータでは隣接を落とす。

## 重心と、面の中の点

- 重心 (centroid) は面の外に出ることがある。C の字の面の重心は外にあり、2 つに分かれた面 (マルチポリゴン) の重心は部品の間の空白にある。
- 面の中に必ず入る点が要るなら、`representative_point` (shapely) か `ST_PointOnSurface` (DuckDB) を使う。

## 有効な形

- 自分と交わる輪 (蝶ネクタイ形) は無効。shapely ではその面積は 0 (2 つの部分の符号が打ち消す)。`make_valid` で直すと、2 つの三角形のマルチポリゴン (面積 2) になる。直すと形と面積が変わる。直した数と、直す前後の面積を書く。
- 穴の中の点は、面に含まれない。穴を持つ面の面積は、外の輪の面積から穴を引いたもの (4 × 4 から 2 × 2 の穴で 12)。
- マルチパートの面 (島を持つ市区町村など) は、1 行で複数の部品を持つ。部品ごとの行に分かれているデータもある (OSM の osm2pgsql の出力など)。数える前にまとめる。

## 輪の向き

shapely では、時計回りと反時計回りの輪で、面積も述語も変わらない (`is_ccw` だけが違う)。GeoJSON (RFC 7946) は外の輪を反時計回りにすると決めている。球面の上で面を扱う道具 (球面の地理型) では、輪の向きが面の内側を決めることがある。その道具では向きを確かめる (このリポジトリでは測っていない、未確認)。

## 浮動小数と、隙間と重なり

- 0.1 + 0.2 は 0.30000000000000004 で、0.3 ではない。計算で作った点は、境界の上にあるはずでも、外に出ることがある (`box(0, 0, 0.3, 1)` は `Point(0.1 + 0.2, 0.5)` を覆わない)。
- 隣り合うはずの面の間に 1e-9 の隙間があると、`touches` も `intersects` も偽になる。座標の精度を揃える (`set_precision(1e-6)`) と、隣接が戻る。揃える精度 (snapping の許容幅) は、データの位置の正確さより小さく、浮動小数の誤差より大きくとる。
- 細い隙間や重なり (sliver) は、境界を別々に描いたデータを重ねると必ずできる。重なりの面積と隙間の面積を数え、それが分析の結論 (面積、隣接、按分) に効くかを確かめる。
- 境界が一致するはずの 2 つのデータ (都道府県と市区町村) でも、座標が完全に一致するとは限らない。一致を前提にした操作 (境界の共有、差分) は、許容幅を決めてから行う。
