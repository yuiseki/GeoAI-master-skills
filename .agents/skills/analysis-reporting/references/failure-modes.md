# 失敗の型

できのよい報告に見えるのに結論が間違っている、という失敗には決まった型がある。重い分析の報告は、型ごとに「確かめた」「当てはまらない」「確かめていない」のどれかを、根拠とともに書く。名前が付いていれば、確かめ忘れが見える。

| ID | 型 | どう見えるか | 確かめ方 |
|---|---|---|---|
| F1 | もっともらしい数字を出すバグ | 結合で行が黙って落ちる、単位や座標の順を取り違える、欠けを 0 として数える。数字は桁も向きもそれらしい | 段ごとに行の数と総量を数えて照合する。答えの分かる小さな例 (合成のデータ、手で数えた区画) で同じ手順を流す。ログに警告とエラーが無いかを見る |
| F2 | 弱い基準 | モデルが基準を大きく上回るが、基準の作り方が雑だった (チップごとのしきい値、平均だけ) | 強い単純な基準 (最後の値、場面ごとのしきい値、近い地点の値) を同じ試験で自分で出す。論文の基準の表だけに頼らない |
| F3 | 漏れ | 試験に、学習と同じ場所、同じ日、同じ個体、答えの言い換えが入っている | 使う場面に合わせて分ける (場所、時刻、できごと)。特徴量が答えの後に決まる値でないかを見る |
| F4 | 近道 | 点は本物だが、意図した仕組みでなく、偽の手がかり (観測の努力、人口、撮影の条件、地点の識別子) で当てている | 近道を断った条件 (努力をそろえる、学習に無い場所やできごと) でも差が残るかを見る |
| F5 | 想定外の結果を発見として語る | 論文や常識と違う結果を、新しい発見として書く。実はバグか手順の違い | 想定外の結果は、まず F1 と、手順の違い (版、設定、指標の数え方) を疑う。分けられなければ「理由は分けていない」と書く |
| F6 | 書いた方法と流した方法の食い違い | 報告の設定 (半径、期間、エポック、種の数) が、流したコードや記録と違う | 報告の方法の節を、コード、設定、実行の記録と突き合わせる |
| F7 | 早い段階の枠の固定 | 単位、問いの読み方、手法を最初に決め、後の段で疑わない。よくできた分析が別の問いに答えている | 単位の大きさや区切り、問いの読み方を変えたときに答えが変わるかを並べる |
| F8 | 出どころの無い数字 | 報告の数字が出力に無い、または別の表の値と偶然に合っている | 数字ごとに出力のファイルへリンクし、リンク先で照合する (check_project.py) |
| F9 | データの取り違え | 版、範囲、切り出しの境界、条件が、思っていたものと違う | 版と取得日を書き、件数を配布元の値と照合する。切り出しの境界は同じ版のものを使う。公開の前に条件を原本で読む |

## 報告への書き方

重い報告 (`--level full`) に「失敗の型」の節を置く。「方法」の後、「確かめていないこと」の前。1 つの型に 1 行の表にする。

```markdown
## 失敗の型

| ID | 判定 | 根拠 |
|---|---|---|
| F1 | 確かめた | 結合の前後で 4,232 件が保たれた ([counts.csv](outputs/counts.csv)) |
| F2 | 確かめた | 最後の値と過去の平均を同じ試験で出した |
| F3 | 当てはまらない | 予測をしていない |
| F4 | 確かめていない | 努力をそろえた比較はしていない |
...
```

- 判定は 3 つのどれか。確かめた: 何をして、何が分かったかを根拠に書く。当てはまらない: なぜ当てはまらないか (予測をしていない、外部のデータを使っていない)。確かめていない: 「確かめていないこと」の節に、同じ ID を付けて書く。
- F1 から F9 の全てを書く。書いていない型は、確かめ忘れと区別できない。
- 「確かめた」は、確かめた範囲を書く。全体の一部だけを見たなら、そう書く (「100 件を手で見た」)。一部を見たことを全体を確かめたと書かない。
- check_project.py は、節があること、全ての ID があること、判定が 3 つのどれかであること、根拠が空でないこと、「確かめていない」の ID が「確かめていないこと」の節にあることを確かめる。根拠の中身が正しいかは確かめられない。

## この型の出どころ

このリポジトリの分析で実際に起きたことから選んだ。F2 は Sen1Floods11 (チップごとと場面ごとの Otsu で IoU が 0.228 と 0.347) と PEMS-BAY (最後の値が論文の FC-LSTM を 15 分と 30 分で上回った)、F5 は Sen1Floods11 の FCN が論文より高かったこと、F9 は別の時点の境界で切り出してデータが黙って減ったことから。新しい型を見つけたら、事例とともに足す。
