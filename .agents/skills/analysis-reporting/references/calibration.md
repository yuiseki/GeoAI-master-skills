# 検査の較正: check_project.py は何をどれだけ拾うか

check_project.py の ok は、どの間違いがあり得ないことを意味するのか。答えの分かる壊し方で測った。`scripts/calibrate_checks.py` が、追跡しているプロジェクトの報告を一時的な場所に写し、1 か所だけ壊して検査を流し、壊す前に無かった問題が出たら「拾った」と数える。リポジトリの報告には触れない。

## 2026-11-09 の結果

72 の報告、壊し方ごとに 1 回 (数字は 1 報告につき 3 回)、種 0。結果の行は `docs/harness-audits/check-calibration-2026-11-09.csv`。

| 壊し方 | 検査の役目 | 拾った |
|---|---|---|
| データの節を消す | 拾う | 72 / 72 |
| 出力へのリンクを無いファイルに向ける | 拾う | 72 / 72 |
| 失敗の型の表から 1 行消す (表のある 3 報告) | 拾う | 3 / 3 |
| 結論の数字を 1 つ、形を保って変える | 拾う | 115 / 216 |
| 結論の km を m に書き換える (数字はそのまま) | 拾わない (言葉) | 0 / 44 |
| 結論に、数字の無い因果の主張を足す | 拾わない (言葉) | 0 / 72 |

数字を変えたときの内訳:

| その行が出力のファイルへリンクしているか | 有効数字 2 桁以下 (23、0.67) | 3 桁以上 (4,232、0.105) |
|---|---|---|
| リンクしている | 15 / 32 | 46 / 50 |
| リンクしていない | 9 / 55 | 45 / 79 |

## 読み方

- 節の欠けとリンクの切れは、測った範囲では全て拾う。
- 数字の誤りは半分ほどしか拾わない。拾い損ねの多くは、変えた後の値が、証拠のどこかの別の値と、結論の桁で偶然に合ったもの。リンクの無い行は、プロジェクトの全ての出力と照合するので、偶然に合いやすい (40%)。リンクのある行で 3 桁以上の数字なら 46 / 50 (92%) を拾う。
- 2 桁以下の数字 (件数 23、割合 0.67) は、リンクしていても半分しか拾わない。大きな表には、たいていどこかに同じ 2 桁の値がある。
- 単位の書き換えと、言葉の主張は拾わない。検査の役目の外で、人が読むしかない。

## 書き手への助言

- 結論の数字は、行ごとに出力のファイルへリンクする。リンクの無い数字は、検査がほとんど守らない。
- 結論の鍵になる数字は、3 桁以上で書く (0.67 より 0.672)。丸めた 2 桁の値は、別の値と偶然に合う。
- 件数のような小さな整数は、検査が守らないと考えて、自分で出力と見比べる。

## 確かめていないこと

- 数字を変える幅は 1 通り (末尾の桁を 3 ずらす、または 7% 増やす)。大きく外れた数字の方が拾いやすいはずだが、幅ごとには測っていない。
- 壊したのは結論だけ。方法の設定の書き間違い (F6) は、検査の役目の外で、測っていない。
