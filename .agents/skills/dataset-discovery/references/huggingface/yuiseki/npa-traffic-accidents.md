# 交通事故統計情報のオープンデータ (npa-traffic-accidents)

警察庁 交通局が公開している、警察が扱った人身事故の個票。本票 (`honhyo`) が事故 1 件 1 行で、発生日時、都道府県と警察署と市区町村、路線、座標、道路や天候の状態、事故類型、当事者 A と B の種別と年齢層と損傷程度、死者数と負傷者数を持つ。補充票 (`hojuhyo`) は A と B 以外の 1 人 1 行、高速票 (`kosokuhyo`) は高速道路の事故の追加の情報。2019 年から 2025 年の 7 年分。
分析では、事故の地点を行政区や格子に集計する、道路や時間帯や当事者の種別で絞り込む、といった使い方をする。

## どこから読むか

Hugging Face の `yuiseki/npa-traffic-accidents`。版を固定して読む。

```
hf://datasets/yuiseki/npa-traffic-accidents@389500aae5cec45f1311163f70db6a5f05867838/parquet/<year>/honhyo.parquet
hf://datasets/yuiseki/npa-traffic-accidents@389500aae5cec45f1311163f70db6a5f05867838/parquet/<year>/hojuhyo.parquet
hf://datasets/yuiseki/npa-traffic-accidents@389500aae5cec45f1311163f70db6a5f05867838/parquet/<year>/kosokuhyo.parquet
hf://datasets/yuiseki/npa-traffic-accidents@389500aae5cec45f1311163f70db6a5f05867838/raw/<year>/          配布元の CSV、ファイル定義書、コード表
```

`<year>` は 2019 から 2025。

- カード: <https://huggingface.co/datasets/yuiseki/npa-traffic-accidents>
- 取得と検査と変換のコード: <https://github.com/yuiseki/npa-traffic-accidents>
- 配布元: <https://www.npa.go.jp/publications/statistics/koutsuu/opendata/index_opendata.html> (2026-10-02 に取得、`provenance.yaml` による)
- 出典の表示: 出典：警察庁ウェブサイト（https://www.npa.go.jp/publications/statistics/koutsuu/opendata/index_opendata.html）を加工して作成。政府が作ったように見せない。

コードの意味は、Parquet には入っていない。データセットの `raw/<year>/` にある、その年のコード表 (`codebook_<year>.pdf`、2022 年からは `codebook_<year>.xlsx` も) とファイル定義書 (`filedefinition_2019.pdf`、`fileteigisyo_<year>.pdf` など) で引く。2020 年には、2022 年の定義との対応表 (`seigohyou_fileteigisyo2022.pdf`) もある。警察署の名前、高速道路の路線の名前、トンネルの名前もコード表のシートにある。

## 実測

2026-10-23 に、版 389500a の 21 ファイルを DuckDB 1.5 (Python パッケージ 2.0.0) で読んで数えた。

### 列

全ての元の列は文字列 (VARCHAR) で、先頭の 0 に意味がある。本票だけに `latitude`、`longitude` (DOUBLE) と `geometry` が加えてある。

| 票 | 2019〜2021 | 2022〜2025 | 変わった列 |
|---|---:|---:|---|
| `honhyo` | 61 (元の 58 と加えた 3) | 71 (元の 68 と加えた 3) | 2022 年に 上下線、環状交差点の直径、車両形状（当事者A/B） が無くなり、日の出時刻と日の入り時刻の時と分、車両形状等、オートマチック車、サポカー、認知機能検査経過日数、運転練習の方法 (それぞれ A と B) が加わった |
| `hojuhyo` | 15 | 16 | 車両形状 が無くなり、車両形状等 と サポカー が加わった |
| `kosokuhyo` | 17 | 16 | 道路構造 が無くなった |

年をまたいで読むときは `union_by_name = true` で読み、無い年の列は NULL になる。コードの体系も 2022 年で変わった列がある (車両形状と車両形状等など)。対応は 2020 年の対応表で引く。

列名に全角の空白が入る。`発生日時　　年` (全角の空白 2 つ)、`地点　緯度（北緯）` (1 つ)、`一時停止規制　標識（当事者A）` (1 つ) など。括弧も全角。`曜日(発生年月日)` と `祝日(発生年月日)` の括弧だけが半角。

### 1 行が表すもの

- 本票の 1 行は 1 件の人身事故。当事者 A と B の 2 人分の列を横に持つ。当事者 C 以降や同乗者の列は無い。
- 補充票の 1 行は、A と B 以外の 1 人。`乗車別` は、2 (同乗者) が 370,284 行、1 (運転者) が 76,304、5 (歩行者等) が 12,725、0 (不明) が 2,053。`人身損傷程度` が 4 (損傷なし) の行は 856 行だけで、全て運転者。同乗者と歩行者等は死傷者だけが載る。同乗者が A と B のどちらの車に乗っていたかは分からない。
- 補充票を持つ事故は、年に 43,173 件 (2025) から 64,857 件 (2019)。
- 本票の A と B と、補充票の、`人身損傷程度` が 1 (死亡) と 2 (負傷) の人を事故ごとに数えると、本票の `死者数` と `負傷者数` に、2,182,298 件のうち 2,182,297 件で一致した。合わないのは 2022 年の東京の 1 件 (警察署 773、本票番号 0274) で、`死者数` 001 と `負傷者数` 003 に対し、人の行は負傷 2 人だけ。
- 高速票は、本票の `路線コード` の上 4 桁が 4000 から 5499 (高速自動車国道と、指定の自動車専用道) の事故と 1 対 1 で、それ以外の事故には無い。5500 から 5999 (その他の自動車専用道) の 1,369 件には無い。

### 鍵

- 本票は、`都道府県コード`、`警察署等コード`、`本票番号` の 3 つで、どの年のファイルの中でも重複が無い。補充票は、それに `補充票番号` を加えて重複が無い。高速票は 3 つで重複が無い。
- 補充票と高速票の全ての行が、同じ年の本票の行に結べた (結べない行は 0)。
- 7 年を合わせると、3 つの組は 420,501 種類しか無い。本票番号は年ごとに振り直されるので、年をまたいで結ぶときはファイルの年も鍵に入れる。発生日の年ではなく、ファイルの年を使う。

### 発生日時と年

- 年のファイルには、その年より前に起きた事故が入る (上の表)。大半は前の年の分で、2019 年のファイルには 2016 年の 9 件、2020 年のファイルには 2015 年の 1 件もある。発生日は 2015-12-12 から 2025-12-31。
- 発生日の年で数えるなら、翌年のファイルにも同じ年の事故がある。2025 年に起きた事故は、2026 年のファイル (まだ無い) に追加される分が欠けている。2018 年以前に起きた事故は、このデータセットに一部しか無い。
- 年、月、日、時、分は別の列。日付として無効な組は 0。時は 00 から 23、分は 00 から 59。`曜日(発生年月日)` (1 が日曜から 7 が土曜) は、発生日から計算した曜日と全行で一致した。

### 座標

本票の `地点　緯度（北緯）` は 9 桁の DDMMSSsss、`地点　経度（東経）` は 10 桁の DDDMMSSsss で、度、分、秒 (小数点以下 3 桁) を詰めた文字列。数として読むと緯度が 4 億になる。

```
緯度 = DD + MM / 60 + SSsss / 1000 / 3600
経度 = DDD + MM / 60 + SSsss / 1000 / 3600
```

`431412959` は 43 度 14 分 12.959 秒で 43.2369331、`1414947029` は 141 度 49 分 47.029 秒で 141.8297303。全ての位置のある行で、この式の値と `latitude`、`longitude` の差は 0 だった。分と秒の値は 59 以下。

位置の範囲、欠け、面との照合は次のとおり。

- 範囲は、緯度 24.281〜45.518、経度 122.941〜145.803。
- `latitude` が NULL の行は、2019 年 74、2020 年 41、2021 年 33、2022 年 20、2023 年 0、2024 年 0、2025 年 3。多くは緯度と経度が全て 0。2021 年の 1 行は緯度だけが 0 (高知県)。2020 年の 20 行は神奈川県の `000016566` と `0000036144` (北緯 0 度 0 分 16.566 秒) で、日本の外になるので NULL にしてある。
- 7 年から無作為に 30,000 点を取り、`jp-admin-2026-09` の都道府県の面に入れると、29,989 点がどれかの面に入った。下の対応表で置き換えた都道府県と違う面に入ったのは 3 点 (県境の近く)。面に入らなかった 7 点は海岸の近く。
- 測地系は、コード表に「世界測地系 (度分秒)」とだけある。JGD2000 か JGD2011 か WGS 84 かは書かれていない。`geometry` は `GEOMETRY('OGC:CRS84')`。`jp-admin-2026-09` (`EPSG:4612`) と空間結合するときは、`ST_SetCRS(geometry, 'EPSG:4612')` で名前を揃える。
- 位置の精度を表す列は無い。

### 市区町村コード

`市区町村コード` は 3 桁で、5 桁の市区町村コードの下 3 桁。JIS の都道府県コード 2 桁と連結すると、`jp-admin-2026-09` の `municipalities.code5` になる。政令指定都市は区のコードで、親の市のコード (`geometry_source` が `union of its wards` の 20 市) に当たる行は 0。

| ファイルの年 | code5 に一致 |
|---|---:|
| 2019 | 98.25% |
| 2020 | 98.18% |
| 2021 | 98.22% |
| 2022 | 98.29% |
| 2023 | 98.35% |
| 2024 | 100% |
| 2025 | 100% |

一致しない行のコードは、次の 3 種類だった。

- 浜松市の 2024 年の再編より前の 7 区 (22131〜22137)。2019 年から 2023 年に年 5,025〜6,628 件。`jp-admin-2026-09` は再編後の 3 区 (22138〜22140) だけを持ち、その 3 区は面が空。2024 年以降の浜松市の事故は区のコードで結べるが、面は無い。
- 沖縄県の 995 と 996 (47995、47996)。2019 年から 2023 年に年 42〜55 件。点は 995 が久米島町、996 が八重瀬町の面に入った。2024 年からは 361 (久米島町) と 362 (八重瀬町) になった。
- 福岡県の 305 (40305)。2019 年の 5 件。

コード表には「年の途中で合併などでコードが変わったら、その年の中は前のコードを使う」とある。2025 年のファイルから無作為に 20,000 点を取って市区町村の面に入れると、19,496 点 (97.5%) が自分のコードの面に入った。浜松市の新しい区の 357 点は面が無く、139 点 (0.7%) は別の市区町村の面に入り、8 点はどの面にも入らなかった。

## 気をつけること

- 人身事故だけ。物損だけの事故は入っていない。死者は 24 時間以内に亡くなった人で、30 日以内の死者の統計とは数が違う。
- 1 行は事故で、人ではない。人で数えるなら、本票の A と B の 2 つの列の組と、補充票の行を縦に並べる。損傷の無い同乗者や歩行者は載らないので、人の行は「当事者 A と B の全員と、それ以外の死傷者」になる。
- 自転車の事故を数えるときは、A と B の両方の列と、`51` と `52` の両方を見る。補充票にも自転車の行がある。
- 年のファイルの年と、事故が起きた年は違う。年のファイルで数えるのか、発生日で数えるのかを決めて書く。カードの年ごとの件数はファイルの年で数えたもの。
- 全ての元の列は文字列。`死者数` などの数は整数にしてから比べ、足す。コードは先頭の 0 を含めて文字列で比べる (`'01'` と `'1'` は違う)。
- 2022 年に列とコードの体系が変わった。2019 年から 2021 年と 2022 年以降を並べるときは、同じ名前の列でも意味が同じかをコード表で確かめる。
- カードの「2022 年に変わった列」の説明は本票の分だけで、補充票と高速票の列の入れ替え (上の表) は書いていない。
- 位置が NULL の行は、点の集計から黙って落ちる (7 年で 191 行)。
- 配布元のページは、公開したデータを後から直さないとしている。2019 年から 2021 年のファイルの最終更新日は公開より後 (2025-04-18、2026-04-06) で、差し替えか変更かは分からない (カードによる)。この版は 2026-10-02 の取得。

2025 年の本票で、市区町村ごとの件数を `jp-admin-2026-09` の名前と並べる例。都道府県コードは JIS に置き換えてから連結する。

with pm(police, jis) as (values

  ('51','17'),('52','18'),('53','21'),('54','23'),('55','24'),('60','25'),

  ('82','38'),('83','39'),('90','40'),('91','41'),('92','42'),('93','43'),
  ('94','44'),('95','45'),('96','46'),('97','47'))
select pm.jis || h."市区町村コード" as code5, m.name, count(*) as accidents,
       sum(cast(h."死者数" as integer)) as died
from 'hf://datasets/yuiseki/npa-traffic-accidents@389500aae5cec45f1311163f70db6a5f05867838/parquet/2025/honhyo.parquet' h
