# スキルの書き方

このディレクトリのスキルを書く、直すときの決まり。分析の流れ全体の指示はリポジトリ直下の AGENTS.md にある。

## 置き場所

1 スキル 1 ディレクトリ。名前は TODO.md の名前と同じにする。

```
<skill>/
  SKILL.md       手順。frontmatter に name と description
  references/    手順の中で必要になったときに読む資料
  scripts/       手順で使うスクリプトと、そのテスト
  assets/        出力のひな形など
```

TODO.md は入れ子のリスト。1 段目は分析の段階で、括弧に済んだスキルの数と全体の数を書く。2 段目はスキル、3 段目はその reference と節、目録のディレクトリならその下の 4 段目にファイル。書いたものにチェックを付け、段階の数も直す。スキルを足す、消す、名前を変えるときも TODO.md を直す。

## スキルを分けるか、reference にまとめるか

- 答える問いが違うものは、別のスキルにする (値が固まっているか、群があるか、外れたものがあるか)。
- 同じ問いに答える手法の違いは、そのスキルの reference にする (k-means と HDBSCAN、線形と木)。
- 手法を 1 つのスキルの reference にまとめてよいのは、全ての手法が同じ仕組み (同じ入力、同じ分割表、同じ採点のスクリプト) を通るときだけ。spatial-data-modeling のモデルの種類はこれに当たる。入力も出力も確かめ方も違う手法を、共通の心得だけを理由にまとめない。

## SKILL.md には一般的な手順だけを書く

SKILL.md は、データが増えても書き直さずに済むように書く。特定のデータセットについての事実は SKILL.md に書かない。

| 事実の種類 | 書く場所 |
|---|---|
| データセットの事実 (列、粒度、位置の精度、結合キーの一致、既知の注意点) | `dataset-discovery/references/<データセット>.md`。1 データセット 1 ファイル。多数のデータセットを束ねた目録 (STAC など) は `dataset-discovery/references/<目録>/` に、目録の引き方を `README.md`、データセットやテーマごとの中身を別のファイルで |
| ツールやライブラリの挙動 (DuckDB の関数の癖など) | そのツールを使うスキルの `references/` |
| データセットを使って分かったこと (結合した結果、精度ごとに入る単位) | そのデータセットの reference。分かったスキルの側ではない |

SKILL.md で観点を説明するために実例を挙げるのはよい。ただし、データセットの一覧や、データセットごとの表は書かない。データセットが 1 つ増えるたびに行が増える表は、reference に置くべきものだと考える。

## 事実は測ってから書く

- reference に書く数字や挙動は、実データを読んで確かめたもの。カードや説明文を写さない。確かめた日と、版 (データセットの版、ツールの版) を書く。
- 確かめていないことは「未確認」と書く。推測なら推測と書く。
- 「以前の分析」「以前の調査」と書いた数字は、このリポジトリで測り直していない。出典を外部のリポジトリ名で示さず、再現できる手順 (データ、日付、コマンド) を書ける形に置き換えていく。
- 測った結果がカードや既存の reference と食い違ったら、測った結果を書き、食い違ったことも書く。

## スクリプト

- `uvx --from 'duckdb>=1.5.5' python scripts/<name>.py` のように、環境を用意せずに動かせるようにする。
- テストを付ける。答えの分かっている小さな合成データで書き、`uvx --from 'duckdb>=1.5.5' --with pytest pytest scripts/` で通す。
- テストが間違いを見抜けるかを確かめる。実装の要の部分を外すと落ちることを一度は試す。たとえば経度と緯度の取り違えは、赤道上のデータでは距離にほとんど表れないので、高緯度で試す。
- 入力の全ての行がどうなったかを数え、合わなければ止まるようにする。
- 実行で生まれる中間ファイルは `tmp/` か `data/` に置く。どちらも git に入らない。
- 実データでの実行とテストは、メモリと CPU に上限を掛けて流す。このマシンは swap が無く、メモリが尽きると OOM で落ちるのではなく機械ごと止まる。ほかのサービスも同じ機械で動いている。

  ```sh
  systemd-run --user --scope -q -p MemoryMax=8G -p MemorySwapMax=0 -p CPUQuota=400% -- uvx ... python scripts/<name>.py ...
  ```

  scikit-learn の `n_jobs=-1` や HistGradientBoosting の OpenMP は、上限が無いと全コアを使う。DuckDB の `memory_limit` は scikit-learn には効かない。
