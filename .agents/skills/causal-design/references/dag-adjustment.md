# DAG と調整の集合

DAG (directed acyclic graph) は、変数を点、直接の因果を矢印で描いた、巡回の無いグラフ。描いた矢印より、描かなかった矢印 (直接の因果は無い、という主張) のほうが強い仮定になる。どちらもデータでは確かめられない。

## 変数の役割

処置 T から結果 Y への効果を考えるとき、他の変数は次のどれかになる (`scripts/dag_check.py` の `roles`)。

| 役割 | 形 | 総効果のために調整するか |
|---|---|---|
| 交絡 (confounder) | T ← L → Y | する (測っていれば) |
| 中間変数 (mediator) | T → M → Y | しない。効果の一部を消す |
| 合流点 (collider) | T → C ← Y、または経路の上で 2 つの矢印が入る点 | しない。閉じた経路を開く |
| 合流点の子孫 | C → D | しない。合流点と同じく経路を開く |
| 処置の子孫、結果の子孫 | T → D、Y → E | しない |
| 処置だけの原因 | A → T | 要らない。未観測の交絡が残るとき、その偏りを大きくすることがあると知られている (ここでは未実測) |
| 結果だけの原因 | B → Y | 要らないが害は無い。区間を狭めることが多い |

## バックドアの経路と調整の集合

T と Y の間の経路のうち、T に入る矢印で始まるもの (T ← ...) がバックドアの経路。処置の効果でない関連を運ぶ。経路は、次のとき閉じる (Z は調整する変数の集合)。
- 合流点でない点が Z に入っている
- 合流点が、それ自身もその子孫も Z に入っていない

Z が正しい調整の集合 (バックドア基準) になるのは、Z に T の子孫が無く、全てのバックドアの経路を閉じるとき。`dag_check.py` は、選んだ Z が基準を満たすか、まだ開いている経路、調整で新しく開いた経路を出す。測った変数だけで作れる最小の集合も挙げる。1 つも無ければ、調整では識別できない。

```sh
python scripts/dag_check.py graph.txt station price --adjust density footfall news
```

駅の新設と地価の例 (未観測の需要が駅と地価の両方に効く) では、どの集合も正しくならず、「調整では識別できない」と出た。

### 外部の実装との照合

`scripts/test_dag_check_crosscheck.py` で、8 変数の無作為な DAG 300 個 (処置と結果は因果の順の任意の組、残りの約 2 割を未観測) について照合した (networkx 3.7、pgmpy 1.1.2、2026-10-15)。
- 測った変数の全ての部分集合 8,314 通りで、`check` の判定が、networkx の d 分離 (処置から出る矢印を除いたグラフで、処置と結果を分けるか、かつ処置の子孫を含まない) と一致した。
- 最小の調整の集合は、networkx の判定で数え上げた最小の集合と 300 個全てで、pgmpy の `get_all_backdoor_adjustment_sets` と未観測の変数の無い 150 個で一致した。
- 最初の照合は、処置と結果が直接つながる 7 変数の DAG だけで作り、合流点の子孫を調整したときの規則を壊しても落ちなかった。その形が 1 度も現れなかった。処置と結果の組を広げると、8,314 通りのうち 5 通りでその規則が判定を分け、壊すと落ちるようになった。無作為なグラフでの照合は、出てこない形を確かめない。

## 数で見る (`scripts/test_design_checks.py`)

雑音の無い、数えて作った母集団。手計算と一致する。

| 構造 | 調整しない | 調整する | 真の値 |
|---|---:|---:|---:|
| 交絡 L (T ← L → Y) | 1.2 | 0 (L の層で標準化) | 0 |
| 中間変数 M (T → M → Y、M が結果の全て) | 0.6 | 0 (M の層で標準化) | 総効果 0.6、直接の効果 0 |
| 合流点 C = T + Y (T と Y は独立) | 0 | -1 (回帰で C を入れる) | 0 |
| 合流点の子孫 D (C ≥ 1 なら 1) | 0 | -0.5 | 0 |

合流点を入れた回帰は R2 = 1 で、入れない回帰 (R2 = 0) より当てはまりが良い。当てはまり、予測の精度、特徴量の重要度は、どの変数を調整すべきかを教えない。

## 誤った決め方

- 「相関している変数を全部入れる」: 合流点も中間変数も、処置と相関する。入れると誤る変数がある。
- 「処置の後の変数を入れて、精度を上げる」: 処置の後の変数は、中間変数か、処置と結果の両方の子孫でありうる。総効果のためには入れない。直接の効果を知りたいなら、それは別の推定の対象で、別の仮定 (中間変数と結果の交絡が無い) が要る。
- 「処置の前に測ったから安全」: 前に測った変数も合流点になりうる。T ← U1 → C ← U2 → Y (U1、U2 は未観測) では、C は処置の前に決まり、T とも Y とも相関するが、調整すると経路が開く (M バイアス)。`dag_check.py` のテストで確かめている。
- 「データから DAG を学習する」: 矢印の向きと、未観測の変数は、観測データだけでは決まらない。DAG は、制度、地理、時間の順の知識から書き、書いた根拠を残す。
