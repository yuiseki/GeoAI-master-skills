# research-paper-writing

`projects/<name>/paper.md` を、研究論文を書く依頼があるときだけ作る。本文、見出し、要旨、図表の説明は日本語で書く。GitHub 上で読める Markdown とし、短い最終回答である `report.md` は変更・置換しない。既存の文章を引き伸ばさず、問い、根拠、方法、結果、解釈、別の説明と限界を第三者が辿れる形に組み直す。論文を書く段階では新しい分析や再計算をせず、根拠のない主張を補わない。

| reference | 読むとき |
|---|---|
| [claims-and-evidence](references/claims-and-evidence.md) | 主張や数値の出典を点検するとき |
| [citations](references/citations.md) | 既存研究への言及や参考文献を入れるとき |
| [github-markdown](references/github-markdown.md) | 数式、Mermaid、表、PNG を入れるとき |

ひな形は [paper-template](assets/paper-template.md)。節名や順序は研究の問いに合わせて調整してよい。

## 材料と境界

対象 project の `README.md`、`report.md`、事前計画、実験記録、`outputs/`、必要な場合は `artifacts/<name>/`、実行ログとスクリプトを読む。`report.md` は入口であって最終的な証拠ではない。重要な数字や図は、保存された分析出力、入力版、実行条件まで戻って照合する。データカードより、その project で実際に使った版と取得記録を優先する。資料が無い点は「未確認」と書く。分析そのものが足りなければ、論文内で推測して埋めない。

短い報告には結論と最低限の来歴を置く。論文では、問題設定、研究上の問い・作業仮説、観測単位と変数、方法の仮定、結果の再現条件、頑健性、別の説明、一般化できる範囲を説明する。単に報告を長文化しない。

## 執筆手順

1. 研究上の問い、観測した量、推定対象、主結果、主張できないことを分ける。主要な主張と数字について、[根拠の対応表](references/claims-and-evidence.md)を下書きし、証拠のない主張は削るか弱くする。新規性、因果、有意性、一般化、政策上の含意は特に慎重に扱う。
2. Introduction に現実・研究上の問題、既知のことと未解決のこと、研究の問い、答える範囲、確認できる貢献を書く。「重要」「初めて」などは根拠なく使わない。既存研究を十分に調べていなければ、未調査と書く。
3. Data に名前と版または取得日、時間・空間範囲、観測単位、使用・除外件数、観測値と派生値、測定・選択バイアスを書く。再現を制約するライセンスや再配布条件も書く。
4. Methods に実施した分析単位、変数、モデル・アルゴリズム、評価と分割、閾値・距離などの設定、仮定を再現可能な粒度で書く。事前に決めた比較と、結果を見た後に加えた比較を記録で区別する。記録が無ければ事前仮説だったと推定しない。
5. Results は観測・推定された結果を先に示し、解釈は最小限にする。保存済み出力に無い数字、式、モデルを追加しない。図表は本文で用途を述べ、番号と短い説明、出典となる出力へのリンクを添える。本文に値を不必要に再掲しない。
6. Robustness and Limitations に、結論を保った比較と変えた比較、検討して不要とした確認、実施できなかった確認を区別して書く。MAUP、空間依存、観測・選択バイアス、交絡、時点差、外的妥当性は関係するものだけ扱う。Discussion は Results を繰り返さず、別の説明、既存研究との関係、一般化の限界、次の反証・確認を述べる。関連しか測っていない結果を因果に格上げしない。
7. Conclusion を主結果と限界に合わせる。Abstract は本文を書いた後に、問題、問い、データと方法、主結果、結論または限界を短くまとめる。本文に無い数字や主張を要旨へ足さない。
8. 文献を言及するなら [citations](references/citations.md) に従う。最後に `python3 scripts/check_paper.py projects/<name>/paper.md` を実行する。検査が通っても、主張と証拠の対応や文献の実在は人が点検する。

## 表現

文章で明確なら文章だけにする。少数の値の正確な比較は Markdown 表、実際に使ったモデル・推定量・指標の定義は GitHub の数式、実際の分析設計やデータフローなどの関係は Mermaid、実測値・分布・時系列・残差・地図は既存の PNG を使う。PNG を論文執筆中に作り直さない。Mermaid で測定値の大小を描かない。式で使った記号、単位、パラメータ値、条件を隠さない。HTML や notebook を本体にしない ([github-markdown](references/github-markdown.md))。

## 書き出すもの

- 依頼された project の日本語の `paper.md`。証拠が足りない箇所は「未確認」「関連研究は十分に調査していない」などと明示する。
- checker の結果と、人が点検した主要な主張・文献・図表の来歴。checker は論文の質や結果の真偽を判定しない。
