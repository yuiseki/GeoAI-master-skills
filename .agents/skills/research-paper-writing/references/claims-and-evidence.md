# 主張と根拠の対応

論文の下書き中、主要な主張ごとに次を控える。対応表は作業メモでよく、論文本文へ無理に全件載せない。ただし読者が成果物を辿れるリンクと設定は本文に残す。

| 点検するもの | 確認先 |
|---|---|
| 問いと作業仮説 | 事前計画、作業記録。記録が無ければ探索と記す |
| データの件数・欠損・除外 | project の集計ログ、監査 JSON、入力版 |
| 結果の数字・順位・区間 | 結果 CSV・JSON、実行ログ。報告文の転記だけでは足りない |
| 方法の設定・モデル | 実行コマンド、スクリプト、設定、実験記録 |
| 頑健性と失敗 | 設定ごとの出力、実験記録。実施していない確認は結果にしない |
| 図表 | 元の分析出力、PNG、図の来歴・凡例。画像だけから結果を推測しない |
| 外部知識・新規性 | 実際に読んだ一次資料・論文。未調査なら未調査と書く |

確認した比較と探索的な比較を区別する。結果を見て主の定義や比較を変更した場合は、その順序と理由を書く。同じデータで見つけた仮説を、同じデータで独立に確認したとは書かない。

数字が保存済み出力と合わない場合は論文側で計算し直さず、元の分析記録を調べる。版、時点、空間単位、分母、除外規則が異なる可能性を点検する。根拠が回収できなければ、数字を削るか、再現できない旨を明示する。主張が結論を左右するほど強いのに根拠がない場合は、完成した論文として出さない。
