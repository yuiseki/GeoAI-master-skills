# やらないこと

このリポジトリのスキルとエージェントが、できるとしてもやらないことを、理由とともに残す。README の「扱わない範囲」は手法の範囲の話で、いつか足すかもしれない。ここに書くのは、手法が増えても変えない線である。変えるなら、機能を足すのではなく、この文書を書き換え、理由を残す。

## 拒むこと

| やらないこと | 理由 | 代わりにすること |
|---|---|---|
| 計算せずに答える。検索で見つけた数字、論文やデータのカードの数字を、分析の答えとして写す | このリポジトリの趣旨は再現と反証で、答えの出どころが手順でなければ確かめられない。評価でも、検索の答えは失敗に数える | データを読み、手順を流し、出力から答える。外の数字は比べる相手として出典つきで並べる |
| 出力に無い数字を報告に書く | 書いた数字と出した数字の食い違いは、読み手には見分けられない | 数字は出力のファイルから写し、リンクを付ける。足りなければ分析に戻って出す |
| 結果を見てから比較の設定 (分け方、基準、閾値、単位) を変え、それを先に決めた確認として報告する | 結果に合わせて選んだ設定は、偶然の差を主張に変える | 流す前に計画を書く。変えたら、何を見た後に、何を、なぜ変えたかを記録し、探索と書く |
| 多くの変種を流し、最良のものだけを報告する | 選んだ回数が見えないと、最良の点は楽観に偏る | 流した変種の全てと、選び方を書く。選んだ後の点は、選ぶのに使っていない試験で測る |
| 基準を出さずにモデルの点を報告する。弱い基準だけと比べる | 何と比べたかで、同じ点の意味が変わる。最後の値や場面ごとのしきい値が、論文の深層学習の基準を上回ることがあった | 強い単純な基準を、同じ試験で、自分で出す |
| 予測のモデルの係数や重要度を、因果の効果として読む | 予測の精度は識別を保証しない | 因果を言うなら、識別の設計と仮定を先に書く |
| 想定外の結果を、確かめずに新しい発見として書く | 想定外の結果の多くは、バグか手順の違いから来る。その方が話としては面白く見える | まずバグと手順の違いを疑う。分けられなければ「理由は分けていない」と書く |
| 条件を確かめていないデータや画像を公開する。人や世帯を指しうる位置を、守り方を決めずに公開する | 公開は取り消せない | 確かめるまでは手元に置き、数字だけを報告する |
| 読むとコードが動きうる外部のファイル (pickle など) を開く | 中身を確かめる前に、手元で任意のコードが動く | 同じものを、読むだけで済む形式 (CSV、HDF5) から作り直す |
| エラーや欠けを既定値で埋めて先へ進む | 失敗が成功の顔をすると、後の段では見つからない | 止めて、何が欠けたかを書く |

## 検査が保証しないこと

このリポジトリの検査 (スクリプトのテスト、スキルの検査、報告の検査) が通っても、次のことは保証されない。

- 報告の数字が、正しい計算から出たこと。報告の検査が確かめるのは、数字が出力のファイルにあることまでで、出力が正しいかではない。
- 手順が書いたとおりに流れたこと。計画と記録は、書いた人の申告である。
- データが本物で、欠けが無いこと。
- 言葉の主張 (「渋滞が始まる点で効く」) が正しいこと。数字として照合できない。
- スクリプトの正しさが、分析の正しさになること。スクリプトが正しくても、エージェントがそれを正しく使ったかは別に評価する。

検査ごとに、どの間違いをどれだけ拾うかを、答えの分かる例で測る。測っていない検査は、測っていないと書く。

## 変えるとき

この文書の行を消す、弱めるときは、どの事例でその線が要らなくなったか、または害になったかを書く。モデルが賢くなったことは、それだけでは理由にならない。測って示す。
