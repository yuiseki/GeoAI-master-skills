# 関連するスキル集

GeoAI-master-skills の外にある、地理空間のスキル集。中身は写していない。使うときは、それぞれのライセンスと、測った環境を確かめる。

## isaaccorley/geospatial-skills

- 場所: <https://github.com/isaaccorley/geospatial-skills> (2026-10-14 に a203446 を読んだ)
- ライセンス: このリポジトリで書かれたスキルは Apache-2.0。取り込んだスキルは、元のライセンス (Apache-2.0 の portolan-skills、MIT の opengeos/geoai-skills) のまま。
- 中身: 19 のスキル。GDAL、GeoParquet、GeoZarr、PMTiles、STAC のカタログ、衛星画像の取得など、データを作って配る側の道具が多い。
- GeoAI-master-skills との違い: GeoAI-master-skills は、何を測るか (評価の分け方、リーク、空間の自己相関) と、データの罠が中心。向こうは、大きなジョブを壊さずに流す技術が中心。特に `parallel-geospatial`、`planet-bulk-download`、`pmtiles-pipeline` に、実際のジョブの失敗から書いた、次のような知見がある。
  - 独立に分けられる軸 (地域、タイル、ヒルベルト順) で分けて、プロセスプールで流す。
  - 1 行ずつ追記する JSONL に完了を記録して、途中から再開できるようにする。
  - 一時ファイルに書いてから置き換える。ラッパーから `--force` を渡さない。
  - exit 139 (segfault) と exit 137 (メモリ不足で強制終了) の読み方。
- 数字は向こうの環境 (96 コアのノード、DuckDB spatial 1.5.0 のころ) のもの。版が違うと当てはまらないことがある。例: 向こうは「1,500 万行の `ST_Touches` の自己結合は segfault する」と書く。こちらで DuckDB 1.5.6 (CPU 8、メモリ 16 GB の Docker) で測ると、OSM の建物 2,990 万行 (osm-japan-src-2026-08) の自己結合が 50 秒で終わり、segfault しなかった (2026-10-14)。

## GRIND-Lab-Core/night_owl_research_agent (NORA)

- 場所: <https://github.com/GRIND-Lab-Core/night_owl_research_agent> (2026-10-16 に 5f7a246 を読んだ。この commit の日付は 2026-05-05)。論文は arXiv:2605.02092。
- ライセンス: README は MIT と書き、`LICENSE` を見るように言うが、5f7a246 には `LICENSE` のファイルが無く、GitHub もライセンスを検出していない (未確認)。中身は写さない。
- 中身: GIScience の手法の集まりではなく、研究の進め方全体 (文献の調査、着想、実験、査読、報告書と論文) を Claude Code の上で回す research-agent の harness。`skills/` に 22 のスキルと知識のファイル、フック (セッションの終わりに引き継ぎのファイルを書く)、書き手と評価する側を分けるきまり、人の確認で止める印 (`HUMAN_CHECKPOINT`) がある。
- `spatial-analysis` のスキル: 562 行の 1 つのスキルに、問いの分類、データの準備 (CRS、品質、結合)、空間の重み、ESDA、回帰、予測、到達性、内挿、時空間、診断と頑健性、地図、報告をまとめている。手順ではなく、判断の表とガードレールとして書かれている。
- GeoAI-master-skills との共通点: 問いから手法を決める。経緯度で距離を測らない。原因を言うのに相関を使わない。値の意味が違うもの (件数と率) を混ぜない。数字は実行した結果から書く。
- GeoAI-master-skills との違い: GeoAI-master-skills は、答える問いごとに小さなスキルに分け、全体の流れはリポジトリ直下の AGENTS.md が受け持つ。NORA は 1 つの大きなスキルに空間の分析をまとめ、論文までの流れは別のスキルと harness が受け持つ。数字の扱いも違う。NORA の表は既定の閾値 (特徴量の数、標本の数の上限、p 値の区切り) を置くが、GeoAI-master-skills は、手法ごとに小さな既知解と仮定を崩した合成データで振る舞いを測り、その結果を reference に書く。
- 参考にする点:
  - 個別の空間手法に進む前に、そもそも空間の手法が要るかを判定する。座標を持つことは理由にならない。
  - 診断は、全てを流す checklist ではなく、問い、手法、データに応じて選ぶ。
  - 問いに答えられる最も軽い分析を選ぶ。
  - 行った診断と頑健性の確認に加えて、検討したが行わなかったものと、その理由を残す。
  - 内挿面、予測の地図、補完、模擬、生成した背景点などの派生物を、観測と区別する。後段がそれを観測と取り違えないように、作り方を残す。
  - 報告の数字を、それを出した実行に結び付ける。
- そのまま取り込まない点 (NORA の固定の規則と、GeoAI-master-skills の決め方):
  - 特徴量は 15 まで、GWR は 5,000、MGWR は 3,000 件まで、のような固定の閾値。計算の上限は環境の事情で、手法の決まりではない。
  - 結合するデータの時点の差が 2 年を超えたら印を付ける、という固定の線。差が効くかは、現象がその間に変わるかで決まる。
  - VIF が 10 を超えたら落とす、という一律の規則。共線性が問題かは、係数を説明に使うか、予測に使うかで変わる。
  - 点の重みは k = 5〜8 の最近傍、という固定の選び方。重みは、相互作用の届く範囲の仮定から決め、変えて結論が保たれるかを見る。
  - Moran's I を p 値だけで強い、中程度と分けること。大きさと、重みの選び方による変わり方を並べる。
  - 空間データなら行の無作為な交差検証は禁止、という一律の規則。評価の分け方は、予測する場所と観測の離れ方 (使い道) から決める。
  - 件数は必ず人口で割る、という一律の規則。割る分母は、問い (率か量か) と、記録の過程 (観測の努力) から決める。人口で割ることは観測の偏りの補正ではない。
  - 空間の重みは常に行で標準化する、という規則。標準化は統計量の意味を変える (隣の数が違う単位の扱い) ので、選んだ理由を書く。
  - 来歴を記録する `.meta.json` の形式そのもの。GeoAI-master-skills は、まず記録すべき項目をきまりとして置き、形式は既存の成果物に合わせて決める。
