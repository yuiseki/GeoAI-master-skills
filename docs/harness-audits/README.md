# 足場の監査

スキルとエージェントの周りには、間違いを止めるための足場がある。報告の検査、スキルの検査、手順の中の「必ず」、[やらないこと](../boundaries.md)。足場は、あるモデルのある失敗を見て足したものが多い。モデルが変われば、その失敗が起きなくなることも、別の失敗が出ることもある。そこで、モデルが変わったとき、または足場を足した、直したときに、足場を 1 つずつ見直し、残すか外すかを、証拠とともに記録する。

## いつ監査するか

- スキルを使うエージェントのモデルが変わったとき (評価に使うモデルを含む)。
- 足場を足した、直したとき。足した足場の行を、この監査の表に足す。
- 足場が害になった事例 (正しい報告を止めた、手間だけが増えた) を見つけたとき。

## 何を見るか

足場ごとに 1 行。

| 欄 | 書くこと |
|---|---|
| 足場 | 規則と、どこにあるか (ファイルと関数) |
| 防ぐ失敗 | 失敗の型の ID (`.agents/skills/analysis-reporting/references/failure-modes.md`) か、その他の失敗 |
| 由来 | 足すきっかけになった事例と日付、コミット |
| 測った効き | 答えの分かる壊し方で、拾った割合 (検査の較正)。評価の課題で、足場があるときと無いときの差 |
| 外す条件 | どの証拠が出たら外すか。「モデルが賢くなった」は条件にならない。足場を外した条件で、評価の課題を 3 回以上流し、防ぐ失敗が 1 度も起きないこと、のように測れる形で書く |
| 判定 | 残す、外す、直す、保留。理由 |

## 外すときの決まり

- 外すのは、外す条件を測って満たしたときだけ。満たしていなければ、たとえ要らなく見えても残し、保留と書く。
- 外した足場は、行を消さずに「外した」と書き、外した日と証拠を残す。後で同じ失敗が出たら戻す。
- スキルの手順や reference の中身 (分析の教科書の部分) は、この監査で外さない。モデルが既に知っていることでも、人間向けの教科書として残す (評価の決まりと同じ)。この監査が扱うのは、間違いを止めるための検査と「必ず」の規則だけ。
- 足場を外すと失敗が戻るかを確かめずに、まとめて外さない。1 つずつ外して測る。

## 記録

1 回の監査を 1 つのファイルにする (`YYYY-MM-DD.md`)。前の監査の表を引き継ぎ、変わった行だけ理由を書く。

| 日付 | ファイル | きっかけ |
|---|---|---|
| 2026-11-09 | [2026-11-09.md](2026-11-09.md) | 最初の棚卸し。失敗の型の表と、検査の較正を足した |
