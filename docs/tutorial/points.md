# 入門 2: 点のデータから予測まで

最初の入門 ([README](README.md)) は、国ごとの表だった。座標を持つ点のデータでは、投影、格子、空間を考えた評価の分け方が加わる。ここでは、紛争の事件の点 (UCDP GED 26.1) を使って、点から予測までを通す。コードは [points.py](points.py) 1 本で、そのまま写して流せる。

問い: 2022 年に事件のあった 100 km 四方のセルで、2023 年の事件の数を、2022 年の事件から予測する。

```sh
uvx --from 'duckdb>=1.5.5' --with scikit-learn --with pandas --with pyarrow python docs/tutorial/points.py
```

## 1. 点を読む

Hugging Face の Parquet を、URL のまま SQL で読む。位置の精度を表す列 `where_prec` があり、1 と 2 は実際の場所に近く、3 以上は行政区の代表点などの粗い位置 (dataset-discovery の UCDP の reference)。細かい格子に入れるので、精度 1〜2 の事件だけを使う。

```
events 37686, cells with a 2022 event 983
```

2022 年と 2023 年の事件で 37,686 件。

## 2. 等面積の座標に投影する

経度と緯度 (度) のまま格子を切ると、高緯度ほどセルが小さくなる (入門 1 の座標の節)。そこで、面積が保たれる座標系 `EPSG:6933` (単位はメートル) に投影し、100 km 四方のセルに切る。

```sql
ST_Transform(geometry, 'OGC:CRS84', 'EPSG:6933', always_xy := true)
```

`always_xy := true` は、座標を (経度, 緯度) の順で扱う指定。座標の順は、距離を測る関数の一部 (たとえば `ST_Distance_Sphere`) で逆になる。東京から大阪の距離は、緯度と経度の順で渡すと 402 km (実際に近い)、経度と緯度の順で渡すと 481 km になり、エラーにならない。

## 3. 特徴量と目的変数

1 行は 1 つのセル (2022 年に事件があった 983 セル)。

- 目的変数: 2023 年の事件の数の log1p (log(1 + n)。0 を含む件数の裾を抑える)。
- 特徴量: 2022 年の事件の数の log1p、周りの 8 セルの 2022 年の事件の数の合計の log1p (空間の特徴量)、セルの座標 (x、y)。

2023 年にだけ事件のあったセルは入っていない。2022 年に事件のあったセルだけに絞った予測なので、新しく事件が起きる場所は予測できない。この絞り込みは、結論に書く。

## 4. 評価の分け方で、結論が変わる

セルを無作為に 5 つに分ける (`KFold`) と、隣のセルが学習側にいる。1,000 km 四方のブロック (85 ブロック) ごと伏せる (`GroupKFold`) と、試験側のブロックの近くは学習側に無い。

| 評価の分け方 | 去年だけ (線形) | 線形 + 隣 | hgb + 隣 | hgb + 隣 + x、y |
|---|---:|---:|---:|---:|
| `KFold` (セルを無作為に) | 0.495 | 0.500 | 0.399 | 0.515 |
| `GroupKFold` (1,000 km のブロック) | 0.490 | 0.496 | 0.419 | 0.398 |

(R2、5 分割、分け方の乱数 1 回、2026-10-11)

- 去年の件数だけの線形が、すでに 0.49 ある。隣のセルの件数を足しても、0.496〜0.500 で、ほとんど変わらない。この問いでは、前の年の自分の値がほとんどを説明する。
- hgb は、線形より悪い。行が 983 しかなく、雑音を覚えたためと考えているが、確かめていない。
- 座標 (x、y) を特徴量に足した hgb は、セルを無作為に分けると 0.515 で、全モデルの中で最良に見える。ブロックで伏せると 0.398 に落ち、座標を足さない hgb (0.419) より悪い。座標は、隣のセルが学習側にいるときだけ、場所を覚えて当てる助けになる。「データの無い場所の予測」には使えない。
- 緯度経度を特徴量にするのは、表データの Kaggle 流のやり方でよく試される。地理の問いでは、評価の分け方を無作為にすると効いたように見え、空間で伏せると効かない。点数が上がったときは、まず分け方を疑う。
