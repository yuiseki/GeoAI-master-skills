# 計画: クマ出没通報の短期予測 (秋田の市町村 × 週)

流す前に書く。流した後に書き直さない。直すなら末尾の「計画の変更」に足す。

## 問いと使い道

- 問い: 秋田県の市町村ごとに、翌週から数週先までのツキノワグマの出没通報件数を、前週値より良く当てられるか。当てられないなら、何が足りないか。
- 使い道: 市町村や県の、パトロールと注意喚起の重点の置き方の参考。評価は使い道を真似て、時間の順 (ローリング起点) で行い、予測する時点より後の値を使わない。対象の市町村は学習の期間にも出てくるので、「既知の市町村の未来」を当てる問い。観測の無い県を埋める問いではない。
- 問いの種類: 予測。因果の主張は書かない。
- 「来秋の出没量を夏までに当てる」問いは扱わない。大量出没の秋は 2023 年と 2025 年の 2 回で、通報の年水準を学習できない (n = 4 年)。ブナの結実などの説明変数もカタログに無い。扱わないことは報告に書く。

## 区画

### B1: 秋田の基準とモデルの初回の比較 (v1)

- claim tested: C1 の予備
- mode: exploratory。結果を見てから層別 (季節、年) にした。
- data / analysis unit: `yuiseki/akita-kumadas-wildlife-sighting` 版 c7047ab (2026-09-30 時点)、市町村 (25) × 週 (233、2022-04-11〜2026-09-21)、5,825 行。クマの通報の全種別 (23,300 件。範囲外 6 件)。
- observable quantity: モデルと基準の MAE、RMSE、ポアソン逸脱度、偏り、重点 5 市町村の捕捉率。
- comparator / control: naive、mean4、muni_mean、seasonal_naive、seasonal3。
- evaluation population / split principle: 起点 52〜228 (2023-04-10〜2026-08-24、177 起点)。起点 o までの週だけを渡し、o + h の週を当てる。h = 1、2、4。全ての基準とモデルが同じ起点を使う。
- primary metric: なし (記述)。探索なので判断の規則は置かない。
- uncertainty: なし。起点は互いに依存する。
- planned settings: GLM (ポアソン、L2 = 0.01)、HGB (ポアソン損失、150 木、深さ 4)。
- decision rule: 規則なし、記述として報告。
- failure interpretation: 規則が無いので退けない。
- alternative explanation being tested: なし。
- falsification / robustness: なし。
- priority / run order: baseline、1

### B2: 秋田の探索 (特徴量の追加と配分の分解)

- claim tested: C2、C3 の候補を作る
- mode: exploratory。B1 の結果を見た後に決めた。確認には数えない。
- data / analysis unit: B1 と同じ表、同じ起点、同じ h。
- observable quantity: B1 と同じ指標。
- comparator / control: B1 のモデルと基準。
- evaluation population / split principle: B1 と同じ。
- primary metric: 3 つの h で平均した MAE (候補の選び方に使う)。
- planned settings: (a) 隣の市町村の直近の件数を足した特徴量 (県内の隣だけ。県境の外の隣は観測が無い)、(b) 県の合計を予測して市町村へ配る 2 段の分解。変えるのは 1 つずつ。
- decision rule: 凍結する候補の選び方だけを決める。ナイーブ以外の候補 (glm、hgb、(a)、(b)) のうち、3 つの h で平均した MAE が最小のもの 1 つを凍結する。同点なら、特徴量の少ない方。
- failure interpretation: どの候補も naive に勝たなくても、凍結する。確認の区画で、勝たないことを確かめる。
- alternative explanation being tested: 手法の設定 (候補の選び方が起点の並びに依存する)。
- falsification / robustness: 凍結する候補を、目的を「目撃のみ」に変えた表でも並べて、順位が保たれるかを見る (補助)。
- priority / run order: optional、2

### B3: 来秋の量 (扱わない)

- claim tested: なし
- mode: なし: 4 年分の年水準は検証できない。
- 夏までの件数と、その年の秋の件数の対を 4 つ並べて、記述として報告するだけにする。推定や予測には使わない。

### B4: 岐阜の再現 (月次、確認)

- claim tested: C1
- mode: confirmatory。確認: 岐阜のデータの表は、カードの数字 (行数、年度ごとの件数、点が県の面に入ること) しか見ていない。基準やモデルの MAE は計算していない。
- data / analysis unit: `yuiseki/gifu-bear-sighting` 版 b7f5947、市町村 × 月、FY2014 の 4 月〜FY2025 の 3 月 (144 か月)。市町村は点を `jp-admin-2026-09` の面に入れて決める (岐阜県の面。県外の面に入る点は件数を数えて除く)。年は年度と月から作る。
- observable quantity: MAE (市町村 × 月の件数)。
- comparator / control: naive (前の月)、seasonal_naive (12 か月前)、muni_mean (過去の平均)、mean_short (直近 3 か月の平均)。
- evaluation population / split principle: 起点は 24 か月目以降 (seasonal_naive が作れ、学習に 1 年以上ある)。h = 1、2、3 か月。起点 o までだけを渡す。秋田と同じコードで、季節の長さ 12 と窓 3、12 だけを変える。
- primary metric: h = 1 の MAE。
- uncertainty: 起点の暦年ごとのかたまり (12 か月) で、差を引き直す (2,000 回、種 0)。
- planned settings: 秋田と同じ。モデルは評価しない (C1 は基準どうしの比較)。
- decision rule: h = 1 で、MAE(seasonal_naive) − MAE(naive) と MAE(muni_mean) − MAE(naive) が、どちらも正で、90% 区間が 0 を含まないとき支持。h = 2、3 は向きだけを補助で報告する。区間が 0 を含む、または片方が負なら、C1 は岐阜では支持されない。
- failure interpretation: 岐阜で支持されなければ、C1 は秋田に固有 (2025 年の大量出没が駆動) かもしれない、と書く。基準 (窓、季節の長さ)、起点の始まり、目的の定義、集計の単位を、結果が悪かったからという理由で変えない。変えた比較は探索として別に残す。
- alternative explanation being tested: 偶然 (起点の少なさ)、単位の選び方 (月の集計)。月で集計して件数が小さい。単位は、週の秋田との比較をそろえるための選択なので、岐阜だけ週に変えない。
- falsification / robustness: 平年値 (muni_mean) を直近 3 年の同じ月の平均に変えた版を補助で並べる。強い季節があっても水準の年差が小さければ、これは前期値に勝つはず。勝つなら、C1 の原因は季節の無視ではなく水準の年差、という読みに合う。
- priority / run order: decisive、3

### B5: 秋田の凍結した予測 (確認)

- claim tested: C2、C3
- mode: confirmatory。確認: 2026-09-28 以降の週の通報は、私はまだ見ていない。データの終わりは 2026-09-30 (最後の完全な週は 2026-09-21〜27)。採点は、配布元が 2026-10 以降の通報を出し、取り直した版で行う。
- data / analysis unit: B1 と同じ表の作り方。凍結する予測は、起点 2026-09-21 までの全ての週を学習に使い、2026-09-28 から 2026-11-16 までの 8 週 (h = 1〜8) の市町村別の件数。
- observable quantity: 8 週 × 25 市町村の MAE と、毎週の捕捉率。
- comparator / control: naive、mean_short (秋田では mean4)、muni_mean、B2 で凍結した候補。
- evaluation population / split principle: 凍結した後に配布された週だけ。凍結した予測のファイルのハッシュを、採点の前に記録に残す。
- primary metric: 8 週ごとの MAE (25 市町村の平均) の、候補 − naive の差。
- uncertainty: 週の単位で差を引き直す (2,000 回、種 0)。8 週しかなく、同じ秋の出来事で互いに依存するので、区間は広い。
- planned settings: B2 で凍結した 1 つのモデルを、h = 1〜8 で直接予測に学習する (h = 5〜8 は B2 では評価していない)。
- decision rule: C2: 差の平均が負で、90% 区間が 0 を含まないとき支持。平均が正で区間が 0 を含まないとき退ける。それ以外は「判断できない」。C3: 8 週の捕捉率の平均が、静的な順位より高く、同じ区間の規則で判断する。
- failure interpretation: 退けられたら、この秋では、学習したモデルは前週値より良くないという意味で、C2 の主張が偽だとまでは言えない。凍結した候補、特徴量、h の範囲、市町村の単位を、結果が悪かったという理由で変えて同じ主張を支持しない。
- alternative explanation being tested: 偶然 (8 週)、リーク (凍結の後に配布された週だけで採点する)、観測の努力 (2026 年の秋の報道や通報の仕方の変化。測れない)。
- falsification / robustness: 凍結の予測を、時間をずらした起点 (起点を 4 週前に戻した予測) で作った版も並べる。ずらした版と凍結の版で順位が大きく違えば、結果は起点の選び方に依存する。
- priority / run order: decisive、4 (採点は配布後)

## 仮定

- 通報の 1 行は 1 件の連絡で、同じ個体の重複がありうる。件数は個体数ではない。
- データの終わりの週 (2026-09-21〜27) まで、通報が出そろっている。配布元は説明していない (未確認)。
- 配布元は毎月ファイルを上書きし、過去の通報を後から消すことがある (欠けた番号 3,297)。版をまたぐ比較は、取った日を書く。
- 通報の数は、現象 (出没) と、通報のしやすさ (関心、報道、投稿の仕組み) の両方を含む。観測の努力は測っていない。

## 反証

| 別の説明 | 区画 | 保つもの | 壊すもの | 別の説明が正しいときの結果 | 主張が正しいときの結果 |
|---|---|---|---|---|---|
| 平年値が悪いのは季節の無視ではなく年の水準差 (C1) | B4 の補助 | 市町村 × 月の件数、起点 | 平年値を直近 3 年の同じ月の平均に変える | 水準差が主因なら、直近の年に合わせた平年値は、全期間の平均より MAE が小さくなる | 季節の無視が主因なら、変えても差は縮まらない |

試さなかった別の説明と理由: 交絡 (予測であり、因果を主張しない)、多く使ったデータ (全ての基準とモデルが同じ表を使う)、モデルの容量 (C2 は、候補の特徴量の効きではなく、前週値より良いかを問う)。
