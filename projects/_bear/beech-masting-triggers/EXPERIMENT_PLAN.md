# 計画: ブナの豊凶のトリガー (東北 5 県 × 年)

流す前に書く。流した後に書き直さない。直すなら末尾の「計画の変更」に足す。

## 問いと使い道

- 問い: 東北 5 県の年ごとのブナの結実の豊凶 (東北森林管理局の豊凶指数 0〜5) は、前の年までの夏の気温、春の気温、前の年の結実、衛星で測った植生と地表の状態で、どこまで先に言い当てられるか。どれが引き金か。
- 使い道: 秋の実りを夏までに見積もり、クマの大量出没の備え (前の年の秋から次の年の夏まで) の材料にする。だから評価は、学習に使っていない後の年を当てる形にする (時間で分ける)。
- 問いの種類: 予測と関連。気象を変える介入は無いので因果の主張はしない。「引き金」は、先に固定した手がかりが、学習に使っていない年で、基準より良く当てるか、という意味に限る。

## データ

- 結果: `outputs/tohoku_beech_index.csv`。東北森林管理局のプレスリリースの表 (1989〜2026 年度、県 × 年 × 開花時と結実時、345 セル) を読み取ったもの。2 つのリリースで重なる 335 セルは全て一致し、2026 年度は箇所数から計算し直した値と一致した。Dryad の地点の評価から作り直した 1989〜2008 年の結実時の指数とは、県ごとの相関 0.95〜0.99 (`outputs/dryad_vs_printed_index.json`)。
- 気象: AgERA5 の月別の平均最高気温と平均最低気温 (`agera5-japan-monthly-temperature-1979-2026` 版 348e459、0.1 度、1979-01〜2026-07)。Dryad の東北 98 地点を含む 0.1 度のセル (行と列は経緯度から決め、geometry の点と照らす) の値を使い、県の値は県内の地点の平均。
- 衛星: MODIS collection 6.1 (Planetary Computer)。MOD11A2 の昼の地表面温度 (1 km、8 日)、MOD17A3HGF の年間の純一次生産量 (500 m)、MOD13A1 の EVI (500 m、16 日)。地点を含む画素の値。2001 年から。
- 地点は Dryad の 98 地点 (秋田 31、青森 28、山形 23、岩手 13、宮城 3)。森林管理局の現在の 145 か所の位置は公表されていないので、県の気象は Dryad の地点で代表させる。

## 手がかり (先に固定)

全て県 × 年の値。気温は、県の地点の平均を、その県の 1981〜2010 年の平均からの差 (°C) にする。

| 名前 | 定義 | 文献上の役割 |
|---|---|---|
| Ts(y) | y 年の 7〜8 月の月平均最高気温の平均 | 夏の高温が翌年の花芽を作る (Masaki ほか 2025 の T.HSM、Kon ほか) |
| ΔT(t) | Ts(t−1) − Ts(t−2) | 前の 2 つの夏の差 (Kelly ほか 2013)。2 つの夏の差が結実を決めるという説 |
| Tsp(t) | t 年の 4〜5 月の月平均最低気温の平均 | 春の低温が花を傷める (T.LSP) |
| F(t−1) | 前の年の結実時の指数 | 資源の枯渇 (豊作の翌年は凶作) |
| S1(t−1) | t−1 年の 7〜8 月の MOD11A2 の昼の地表面温度の平均 (県の 2001〜2010 年の平均からの差) | Ts(t−1) を別の測器で測ったもの |
| S2(t−1) | t−1 年の MOD17A3HGF の純一次生産量 (県の 2001〜2010 年の平均からの差) | 資源の蓄え |
| S3(t) | t 年の EVI が 3〜7 月の最小と最大の中点を初めて越えた日 (展葉の早さ) | 早い展葉は晩霜に当たりやすい |

目的の年 t の秋の結実に対して、全て t 年の 5 月末までに決まる値だけを使う (F(t−1) は前の年の秋、S2 は前の年の値)。

## 区画

### B0: 健全性 (sanity)

- 結果の表: 345 セル、1999 年の秋田と山形の結実時が無い (Dryad の −1 と同じ年と地点)。済み。
- 気象: 98 地点のセルの行と列が geometry の点と一致すること、1979-01〜2026-07 の全月に値があること (NULL を数える)、県の値の作り方の前後で地点数が合うこと。
- 衛星: 地点ごとの画素の品質の旗で除いた数を数える。

### B1: 開発期間でのモデルの選択 (exploratory)

- mode: exploratory。開発期間 (目的の年 1990〜2008 年) の結果だけを使う。
- 候補 (全て県の切片を持つ最小二乗。手がかりは上の表のまま、変換しない):
  - M0 県の切片だけ。M1 + F(t−1)。M2 + Ts(t−1)。M3 + ΔT。M4 + Ts(t−1) + Ts(t−2)。M5 + Ts(t−1) + F(t−1)。M6 + ΔT + F(t−1)。M7 + Ts(t−1) + Ts(t−2) + F(t−1) + Tsp(t)。
- 評価: 年を 1 つずつ伏せる交差検証 (その年の 5 県を全て伏せる)。行は全ての候補で手がかりがそろう行 (F(t−1) の無い 2000 年の秋田と山形を含め、どれかの手がかりが欠ける行は全ての候補から外す)。
- 選び方: M2〜M7 のうち、伏せた年の RMSE が最小のもの。同点 (差 0.001 未満) は手がかりの少ない方。選んだ形を開発期間の全ての行で当て直し、係数を凍結する。
- 補助: 選んだモデルの LOYO の RMSE を M0 と M1 と並べる (判断に使わない)。

### B2: 確認期間での凍結モデル (confirmatory、決め手)

- claim: C1。mode: confirmatory。気象と衛星の値は 1 つも計算していない。確認期間の結果の表は読んだ (下の「流す前に決めたこと」)。
- data: 目的の年 2009〜2026 年 × 5 県のうち、手がかりがそろう行。
- observable quantity: 凍結したモデルと比べる相手の、確認期間の RMSE (結実時の指数)。
- comparator: M0 と M1。どちらも開発期間で当てて凍結する (同じ行、同じ凍結の仕方)。
- uncertainty: 確認期間の 18 年を年ごとに復元抽出する (5 県は一緒に動かす。2,000 回、種 0)。県どうしが同じ年に揃って動くので、県 × 年を独立に扱わない。
- decision rule: RMSE(選んだモデル) − RMSE(M0) と RMSE(選んだモデル) − RMSE(M1) の両方で、90% 区間の上限が 0 より小さければ支持。どちらかの区間が 0 をまたげば「判断できない」。点推定が 0 より大きければ退ける。
- failure interpretation: 退けられたら、開発期間で選んだ夏の気温の手がかりは、後の年の豊凶を前の年の結実より良く当てない。救済に使わない変更: 手がかりの月の範囲、地点の選び方、気温の基準期間、モデルの形、確認期間の行の除き方。
- alternative explanation: 偶然 (年が 18 しかない)、年の傾向 (温暖化と豊凶の頻度の変化が重なっただけ)。B3 で試す。
- 補助 (判断に使わない): 全ての候補の確認期間の RMSE、Spearman の順位相関、5 区分 (大凶作〜豊作) の当たり。年ごとに当て直す版 (その年の前の全ての年で係数を推定し直す) の RMSE。

### B3: 反証 (falsification)

- F1 未来の夏: 選んだモデルの Ts(t−1) を Ts(t+1) に替え、同じ開発期間で当てて凍結し、確認期間 (t ≤ 2025) で M0 と比べる。主張が正しければ M0 より良くならない (90% 区間が 0 をまたぐか、悪い)。年の傾向が効いているだけなら、未来の夏でも良くなる。
- F2 年の並べ替え: 確認期間で、手がかりの年を並べ替える (5 県の値を年ごとにまとめて動かす。2,000 回、種 0)。凍結したモデルの RMSE が、並べ替えた手がかりの RMSE の 5% 点より小さいか。県の間の揃い方と手がかりの分布は保ち、年の対応だけを壊す。
- F3 年の中の県の違い (exploratory): 確認期間で、県の指数の年の平均からのずれを、Ts(t−1) の年の平均からのずれで説明できるか (傾きの符号と、年の復元抽出の区間)。県が 5 つしかなく、検出力は低い。

### B4: 花ができる段階 (C2)

- mode: confirmatory。目的の年 2009〜2026 年の開花時の指数 (5 県とも 2004 年から値がある)。
- observable quantity: Ts(t−1) と開花時の指数の Spearman の順位相関 (県 × 年をまとめて)。
- decision rule: 年の復元抽出の 90% 区間の下限が 0 より大きければ支持。
- 補助: 同じ相関を結実時の指数で。結実時 − 開花時の差 (実るまでに減った分) と Tsp(t) の相関 (探索)。

### B5: 衛星 (C3)

- mode: confirmatory。モデルに当てはめず、向きだけを先に決めた相関。目的の年 2009〜2026 年 (S1 と S2 は t−1 が 2008〜2025 年)。
- S1、S2 の各々と結実時の指数の Spearman の順位相関。2 つあるので、年の復元抽出の 95% 区間を使い、下限が 0 より大きければ支持 (片方ずつ判断)。
- 補助 (探索): S1 と Ts(t−1) の相関 (同じものを測っているか)。B2 の凍結モデルの残差と S1、S2、S3 の相関。S3 と、結実時 − 開花時の差の相関。
- 2001〜2008 年は衛星が 8 年しかないので、衛星の手がかりはモデルの選択に使わない。

### B6: 2027 年度の先の予測 (C4)

- 2026 年 7〜8 月の気温がそろったら (AgERA5 の 8 月の版が出たら)、B1 で凍結したモデルと M1 で 2027 年度の結実時の指数を予測し、ファイルの sha256 を記録して凍結する。2027 年 7 月の開花の公表と 10 月の結実の公表で採点する。

## 仮定

- Dryad の 98 地点の気象が、森林管理局の現在の 145 か所の県の気象を代表する。宮城は 3 地点しかない。
- AgERA5 (再解析、0.1 度) の地点のセルの気温の年ごとの上下は、林の中の気温の上下に沿う。値の水準は合わなくてよい (差を使う)。
- 豊凶指数は目視の 4 段階の平均で、間隔の尺度として扱う (最小二乗)。確かめられない。

## 流す前に決めたこと

- 決めた日時: 2026-10-28
- 読んだ生のデータ: 結果の表 (1989〜2026 年度の開花時と結実時の指数) は全て読んだ。確認期間の大凶作の年 (2023、2025 年など) と豊作の年 (2024、2026 年など) を知っている。Dryad の地点の評価と、そこから作り直した指数を読んだ。気象と衛星の値は 1 つも読んでいない (AgERA5 のカードの列と範囲だけを読んだ)。
- 見ていた結果: なし。手がかりと結果の関係を計算していない。
- 文献から知っていること: Kelly ほか (2013) の ΔT、Masaki ほか (2025) の夏の高温と春の低温、豊作の翌年の凶作。手がかりと候補はこれらから選んだ。
- 確認に使う部分を分けて見ないでおいたか: 確認期間の結果は読んだが、手がかりとの関係は見ていない。手がかりは全ての年をまとめて計算するが、B1 のスクリプトは目的の年 2008 年までの行だけを読み、確認期間の行は B1 の選択と凍結が終わるまで表示も集計もしない。

B5 の細部 (衛星の値を読む前に固定):

- Terra (MOD) だけを使う。Aqua (MYD) は使わない。地点の経緯度を各 COG の座標系に移し、地点を含む画素を読む。
- S1: MOD11A2 の LST_Day_1km。開始日が 7 月 1 日〜8 月 31 日の合成。QC_Day の下位 2 ビットが 0 か 1 (作られた値) で、値が 0 でないものだけ。尺度 0.02 K。地点の年の値は有効な合成が 4 つ以上あるときの平均。県の年の値は有効な地点の平均。
- S2: MOD17A3HGF の Npp_500m。32,700 を超える値 (水域、市街地などの埋め値) は除く。尺度 0.0001 kgC/m²/年。県の年の値は有効な地点の平均。
- S1 と S2 は、県の 2001〜2010 年の平均からの差にする。
- S3 (探索): MOD13A1 の EVI。pixel_reliability が 0 か 1 のもの。合成の日は開始日 + 8 日とする。3〜7 月に有効な合成が 6 つ以上ある地点の年で、EVI が最小と最大の中点を初めて越えた合成の日 (年の通し日)。県の年の値は地点の平均。
- 有効な値が無い県の年は行から外し、数を記録する。
