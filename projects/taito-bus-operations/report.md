# コミュニティバスの車両・乗務員計画

## 問い

公開時刻表だけから、コミュニティバスの全便を回すために最低限必要な車両と乗務員を見積もい、路線変更時の運行計画に使えるか。

## 結論

- 台東区めぐりんの必要資源は次の通りです。折り返し時間の違いで車両数が変わり、乗務員の最適値はまだ確定していません。

| 対象 | 設定・証拠 | 必要数 |
|---|---|---:|
| 車両 | 折り返し0分 | 14台 |
| 車両 | 折り返し3分 | 17台 |
| 乗務員 | 不可能と示せた人数の境界 | 33人以上 |
| 乗務員 | 見つかった実行可能な割当 | 35人 |

- 「最適」という表示はモデルの正しさを保証しません。荒川区の小規模問題では、手作業の4人勤務より悪い5人を最適とした制約の誤りを発見し、回帰テストで修正しました。
- 実運用へ使うには、車庫、道路上の回送時間、路線ごとの車両制約を追加する必要があります。

![めぐりん171便を17台に割り当てた時刻図](outputs/blocks-megurin.png)

各行は1台、青い区間は担当便です。空白は待機または回送可能な時間で、実際の回送ではありません。従来の[資源数の要約図](outputs/resource-bounds.png)も残しています。その乗務員の横線は統計的区間ではなく、下限と実行可能解の幅です。

## データ

- GTFS-JPの荒川区コミュニティバス「さくら」平日28便と、台東区「めぐりん」平日171便を使用しています。
- 両フィードとも `block_id` が空で、車両運用はデータに記録されていません。
- ライセンスはCC BY 4.0です。版は未確認で、実験結果は2026-09-29時点の記録です。データ本体と割当結果はこのプロジェクトへ複製していません。
- 移植元は[`study-geoai-algo-py` 事例005（commit 6880b32）](https://github.com/yuiseki/study-geoai-algo-py/blob/6880b32c097a7c65a6bd72a38682ce1dce1c9a2b/case-studies/005-bus-operations/README.md)です。

## 方法

- 車両計画は、便同士を折り返し時間と回送時間で接続できるか判定し、CP-SATと二部グラフの最大マッチングで最小路被覆を求めました。
- 乗務員計画は、休憩30分、休憩前後の運転4時間以内、拘束9時間以内を制約にしたCP-SATで求めました。
- 同時運行便数と総運転時間から下限を作り、小規模問題の手作業解と別手法の解でモデルを検証しました。
- 車両割当図は固定した元コードの GTFS 読み込みと割当を `scripts/reproduce_blocks.py` で再実行し、`analysis-visualize` の `result_figures.py` で描きました。図は折り返し3分、回送速度15 km/h の171便・17台の解です。割当は `outputs/blocks-data.json`、来歴は `outputs/blocks-megurin.json`、要約図は `scripts/plot.py` にあります。

## 確かめていないこと

- めぐりんの乗務員数は33人から35人までしか絞れておらず、最適値は確定していません。
- 車両割当は再実行しましたが、乗務員計画は再実行していません。GTFS の版は未確認です。
- 乗務員の休憩配置は今回の車両割当図から読めません。元コードの `duties-megurin.png` に相当する図が必要です。
