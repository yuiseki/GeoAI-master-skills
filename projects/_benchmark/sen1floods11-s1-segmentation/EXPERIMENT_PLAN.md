# 計画: Sen1Floods11 の Sentinel-1 の水の切り出しを再現し、U-Net を足す

流す前に書く。流した後に書き直さない。直すなら末尾の「計画の変更」に足す。

## 問いと使い道

- 問い: Sentinel-1 (VV と VH) の 512 × 512 のチップから、画素ごとに水か否かを当てる課題 (Sen1Floods11 の手で描いた正解) で、論文 (Bonafilia ほか 2020) の FCN-ResNet50 と VH の Otsu のしきい値の値を、論文と同じ分け方と指標で再現できるか。再現できたとき、同じ手順の上で U-Net (ResNet34) は FCN より良いか。どちらも、学習に入っていない洪水 (ボリビア) でも同じ順か。
- 使い道: 画像の切り出し (セグメンテーション) のスキルの手順を、答えの分かっている課題で確かめてから書く。のちに、ため池の水面 (Sentinel-1) へ持っていく。
- 問いの種類: 予測。

## データ

- Sen1Floods11 v1.1 (Cloud to Street)。`gs://sen1floods11/v1.1/` を HTTPS で読む。手で描いた正解の 446 チップ (学習 252、検証 89、試験 90、ボリビア 15) の `S1Hand` (VV、VH の dB)、`LabelHand` (−1 無効、0 水でない、1 水)、`JRCWaterHand` (恒常の水)、`S1OtsuLabelHand` (著者の Otsu の結果)。
- ライセンス: 原本のリポジトリと README には記載が無く、バケットの STAC 目録は `proprietary` と書く (STAC の道具の既定値の可能性がある)。写しのデータセットは CC BY 4.0 と書くが、原本で確かめられない。そのため、データと、チップの画像から作った図はリポジトリに入れず、数字だけを報告する。原本は `artifacts/_benchmark/sen1floods11-s1-segmentation/raw/` に置く。

## 論文の値 (比べる相手)

表 1 (試験 90 チップ、10 の洪水、水全体 AW のチップごとの平均 IoU): 手で描いた正解で学習した FCNN 0.3125、VH の Otsu 0.3591。洪水の水 FW 0.2421 と 0.2850、恒常の水 PW 0.2570 と 0.4571。表 2 (ボリビア 15 チップ、AW): FCNN 0.3524、Otsu 0.3862。

論文の手順 (本文と、原本の `Train.ipynb` で確かめた): 入力は dB を −50〜1 で切って (x + 50) / 51 にし、平均 [0.6851, 0.5235]、標準偏差 [0.0820, 0.1102] で標準化。NaN は 0。学習は 256 × 256 の無作為な切り出しと左右上下の反転、batch 16。検証と試験は 512 を 4 つの 256 に分ける。FCN-ResNet50 (事前学習なし、最初の畳み込みを 2 チャンネル、BatchNorm を GroupNorm 16 に)、交差エントロピー (重み 水でない 1、水 8、無効は無視)、AdamW 学習率 5e-4、CosineAnnealingWarmRestarts、100 エポック、検証の平均 IoU が最良のエポックを使う。

## 方法

- 指標: 水の IoU。主はチップごとの IoU の平均 (論文の「全てのチップを等しく重み付けした平均」)。無効の画素を除き、IoU = (交わり + 1e-7) / (和 + 1e-7) (ノートブックと同じ)。副として、全てのチップの画素をまとめた IoU (後の論文の多くの数え方)。洪水の水と恒常の水は、`JRCWaterHand` が 1 の画素を恒常、それ以外の水を洪水として分ける。
- 指標の数え方の確かめ (B0): 著者の Otsu の結果 (`S1OtsuLabelHand`) を、上の 2 つの数え方で採点し、論文の Otsu の値 0.3591 にどちらが合うかを、モデルを学習する前に決める。
- モデル:
  - O: 著者の Otsu の結果 (固定)。
  - F: FCN-ResNet50。上の論文の手順。学習率の予定はノートブックの T0 = 10 エポック、T_mult 2 (本文は T0 = 1 エポックと書く。コードに合わせる)。
  - U: U-Net (ResNet34 の符号化器、事前学習なし、`segmentation-models-pytorch`、BatchNorm を GroupNorm 16 に)。そのほかは F と同じ。
- 種: F と U をそれぞれ 3 つの種 (1、2、3) で学習する。
- 計算: GPU 1 枚 (空いている方)。GPU のメモリが足りなければ、batch 8 を 2 回ためて 16 にする (GroupNorm なので結果は同じ)。

## 区画

### B0: 数え方とデータ (sanity)

- observable quantity: 分け方の枚数 (252、89、90、15)。O の試験の AW を 2 つの数え方で
- decision rule: 枚数が一致し、どちらかの数え方で O が 0.3591 ± 0.02 に入れば、その数え方を主にして先へ進む。どちらも入らなければ、読み方 (無効の扱い、0/0 の扱い) を書いて止める
- priority / run order: 順番 1

### B1: FCN の再現 (decisive)

- observable quantity: 3 つの種の F の試験の AW の平均 IoU。FW と PW。O との差
- uncertainty: 種の幅と、チップごとのブートストラップ (2,000 回) の 95% 区間。同じ洪水のチップは似るので、洪水ごとのブートストラップも並べる
- decision rule: 3 つの種の平均が 0.3125 ± 0.05 に入れば「再現した」。O が F より大きい順 (論文) が、3 つの種の全てで出るかを書く。外れたら、手順の違い (学習率の予定、指標) を書き、スキルの既定にしない
- priority / run order: 順番 2

### B2: U-Net (confirmatory)

- observable quantity: U − F の試験の AW の平均 IoU (同じ種の組で対にした差の平均と、チップごとの対のブートストラップ)
- decision rule: 3 つの種の全てで U > F で、対の差の区間が 0 より上なら「U が良い」。そうでなければ「差は示せない」
- priority / run order: 順番 3

### B3: ボリビア (robustness)

- observable quantity: ボリビアの 15 チップでの O、F、U の AW の平均 IoU (3 つの種)
- decision rule: なし (15 チップなので順を書くだけ。論文は F 0.3524、O 0.3862)
- priority / run order: 順番 4
