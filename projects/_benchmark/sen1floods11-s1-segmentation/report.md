# Sen1Floods11 の Sentinel-1 の水の切り出しの再現

問い: Sentinel-1 (VV と VH) のチップから画素ごとに水を当てる課題 (Sen1Floods11 の手で描いた正解) で、論文 (Bonafilia ほか 2020) の FCN-ResNet50 と VH の Otsu のしきい値の値を、論文と同じ分け方と指標で再現できるか。同じ手順の上で、U-Net は FCN より良いか。

## 結論

FCN の値は再現しなかった。Otsu の値は再現した。論文と同じ手順で学習した FCN の試験の値 (水全体の IoU のチップごとの平均) は、3 つの種の平均で 0.3770 で、論文の 0.3125 より高く、計画の関門 (± 0.05) の外だった。一方、著者が配っている Otsu の結果を同じ数え方で採点すると 0.3573 で、論文の 0.3591 と合った。指標とデータの読み方は論文と同じなので、食い違いは学習の側にある。どの違いが効いたかは分けていない。

U-Net (ResNet34) は、3 つの種の全てで FCN より低かった (差 −0.009〜−0.025)。「U-Net が良い」とは言えない。

大きな結論は、論文と同じ向きだった。手で描いた 252 チップで学習した FCN も U-Net も、VH の Otsu のしきい値との差は −0.04〜+0.03 の範囲で、区間はほぼ 0 をまたぐ。学習に入っていない洪水 (ボリビア) では、Otsu が 3 つの種の全ての FCN と U-Net 以上だった。この課題で深層学習の切り出しを使うなら、まず Otsu と同じ試験に並べ、上回ることを確かめる必要がある。

## 探索: 基準の Otsu の作り方 (主の結果を見た後)

スキルに入れる基準を決めるため、Otsu を自分で作り直した ([otsu_own.csv](outputs/otsu_own.csv)、[otsu_event.csv](outputs/otsu_event.csv)、[otsu_scene.csv](outputs/otsu_scene.csv))。論文の Otsu は、チップごとではなく、洪水ごとに 1 km の格子のうち分散の大きい格子だけでヒストグラムを作ってしきい値を 1 つ決め、平滑化した VH に当てたものだった。

| Otsu の作り方 | 試験の AW | ボリビアの AW |
|---|---|---|
| チップごと、平滑化なし | 0.2284 | 0.3875 |
| 著者のしきい値 (メタデータ) を、5 画素の平均で平滑化した VH に | 0.337 | 0.472 |
| 洪水ごとに自前で決めたしきい値 (格子の標準偏差の上位 10%)、5 画素の平滑化 | 0.3473 | 0.4673 |
| 著者の Otsu の結果 (配布) | 0.3573 | 0.4531 |

5 画素の平滑化で、著者の結果と画素の一致は中央値 0.9899 になった。自前のしきい値と著者のしきい値の差は、中央値 1.1 dB (上位 10%) と 0.62 dB (上位 25%) ([otsu_scene_events.csv](outputs/otsu_scene_events.csv))。

基準の作り方しだいで、深層学習との差の読み方が変わる。チップごとの Otsu (0.2284) と比べれば FCN (0.3770) は大きく上回るが、洪水ごとの Otsu (0.3473) との差は 0.03 ほどで、ボリビアでは洪水ごとの Otsu の方が上だった。平滑化の幅 (1、3、5 画素) と上位の割合 (10%、25%) は、結果を見ながら選んだ値である。

## 方法

計画 ([EXPERIMENT_PLAN.md](EXPERIMENT_PLAN.md)) は流す前にコミットした。

- 前処理: dB の NaN を 0 にし、−50〜1 で切って (x + 50) / 51、論文の平均と標準偏差で標準化 (ノートブックと同じ)。
- 学習: 256 × 256 の無作為な切り出しと左右上下の反転、batch 16、交差エントロピー (水でない 1、水 8、無効は無視)、AdamW 学習率 5e-4、CosineAnnealingWarmRestarts (T0 = 10 エポック、T_mult 2、ノートブックと同じ)、100 エポック、検証のチップごとの平均 IoU が最良のエポックを使う。最良のエポックは 88〜98 だった ([train_fcn_s1.csv](outputs/train_fcn_s1.csv) ほか)。
- FCN: torchvision の FCN-ResNet50、事前学習なし、最初の畳み込みを 2 チャンネル、BatchNorm を GroupNorm 16 に。U-Net: segmentation-models-pytorch の U-Net (ResNet34)、事前学習なし、同じく GroupNorm。
- 評価: 512 のチップを 4 つの 256 に分けて予測し、つなぎ直す。IoU は無効の画素を除き、(交わり + 1e-7) / (和 + 1e-7)。
- 計算: GPU 1 枚 (RTX 3060)、PyTorch 2.14.1。1 本の学習は FCN 約 16 分、U-Net 約 6 分。
- テスト: `scripts/test_s1f11.py` (前処理、IoU の 2 つの数え方、洪水と恒常の水の分け方、切り出しと反転、4 分割) と `scripts/test_models.py` (2 つのモデルの形、BatchNorm が残らないこと、勾配を 2 回に分けたときの損失)。全 10 件が通る。

計画の変更 (どちらも試験の点を見る前):

- PyTorch を 2.12.0 から 2.14.1 にした。2.12.0 に同梱の cuDNN 9.20 には無い部品を、システムの cuDNN 9.27 から読んでしまい、最初の畳み込みで `CUDNN_STATUS_SUBLIBRARY_VERSION_MISMATCH` で止まった。2.14.1 の cuDNN 9.24 は全ての部品を持つ。
- FCN は GPU のメモリのため、8 枚ずつ 2 回に分けて 16 枚の勾配を作った。損失は 16 枚全体の重みの和で割り、一度に流すのと同じ値になる (テスト)。

関門について:

- 座標: チップは EPSG:4326 の 10 m の格子で、画素の数で数える。面積は扱わない。
- 量と水準: IoU は比なので、チップごとの平均と、画素をまとめた値を分けて書いた。
- 空間の依存とリーク: 試験は学習と同じ洪水から無作為に分けられている (論文の分け方)。洪水ごとの区間と、学習に入っていない洪水 (ボリビア) を並べた。
- 基準: Otsu のしきい値を同じ試験で並べた。
- 残差と頑健性: 種を 3 つにした。洪水ごとの誤差の偏りは区間だけで、図にしていない。
- 報告: 水の画素の当たり方の比較で、浸水の深さや被害ではない。

## 確かめていないこと

- FCN が論文より高くなった理由。候補は、学習率の予定 (本文は T0 = 1 エポック、ノートブックは 10 エポック)、論文の検証の数え方 (ノートブックは 16 タイルずつの IoU の平均で最良のエポックを選ぶ)、データの版 (論文は v1.0、ここは v1.1)。分けていない。
- 恒常の水 (PW) の数え方。私の定義では Otsu が 0.2846 で、論文の 0.4571 と合わない。主の指標には使っていない。
- ボリビアの Otsu の値が論文 (0.3862) と合わない理由 (ここでは 0.4531)。
- 事前学習した符号化器、自動で作った正解 (weakly labeled、約 4,400 チップ) での学習、Sentinel-2 の入力。
- ため池のような小さな水面への当てはまり。
