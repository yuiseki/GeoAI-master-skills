# 計画: PEMS-BAY の道路の速度の予測で DCRNN を再現し、グラフの効きを分ける

流す前に書く。流した後に書き直さない。直すなら末尾の「計画の変更」に足す。

## 問いと使い道

- 問い: ベイエリアの 325 の感知器の 5 分ごとの速度から、15 分、30 分、1 時間先の速度を当てる課題 (PEMS-BAY) で、論文 (Li ほか 2018、DCRNN) の値を、論文と同じ分け方と指標で再現できるか。再現できたとき、同じモデルから道路網の拡散 (グラフ) を外すと、どれだけ悪くなるか。最後の値をそのまま答える基準と比べて、グラフのモデルは何を足すか。
- 使い道: グラフのニューラルネットワーク (空間 GNN) のスキルの手順を、答えの分かっている課題で確かめてから書く。
- 問いの種類: 予測。

## データ

- `pems-bay.h5` (DCRNN の著者の Google Drive、2019-01-09 の版。325 × 52,116、2017-01-01〜06-30、5 分ごと)。元は Caltrans PeMS。PeMS のサイトの利用方針は、掲載の情報を原則としてパブリックドメインとし、法の許す範囲で配布、複製してよいとする。それでも、原本は `artifacts/_benchmark/pems-bay-dcrnn/raw/` に置き、リポジトリに入れない。
- 感知器どうしの道のりの距離 `distances_bay_2017.csv` と位置 `graph_sensor_locations_bay.csv` (DCRNN のリポジトリ、MIT)。著者の隣接行列 `adj_mx_bay.pkl` は pickle なので読まない。同じ式で距離から作る。
- METR-LA は元の条件を確かめられないので使わない。

## 論文の値 (比べる相手)

表 1 の PEMS-BAY の MAE (mph): DCRNN 1.38 (15 分)、1.74 (30 分)、2.07 (1 時間)。FC-LSTM 2.05、2.20、2.37。過去の平均 (HA) 2.88。RMSE と MAPE も表にある。欠けた値 (0) は誤差から除く。

## 方法

- 前処理 (著者の `generate_training_data.py` と同じ): 入力は過去 12 時刻 (1 時間) の速度と時刻 (1 日の中の割合)、出力は次の 12 時刻。時刻順に、試料の 70% を学習、10% を検証、20% を試験。速度は学習の平均と標準偏差で標準化 (0 も含めて)。
- 隣接行列 (著者の `gen_adj_mx.py` と同じ式): 感知器の順は h5 の列の順。W_ij = exp(−(d_ij / σ)²)、σ は有限の距離の標準偏差、0.1 未満は 0。向きのあるグラフ。
- 指標: 3 時刻先 (15 分)、6 時刻先 (30 分)、12 時刻先 (1 時間) の MAE、RMSE、MAPE。正解が 0 の点を除く。
- モデル:
  - M0 過去の平均: 同じ曜日、同じ時刻の、直前の 4 週の平均 (論文の付録の説明)。
  - M1 最後の値: 入力の最後の時刻の速度を、全ての先にそのまま答える。
  - M2 DCRNN: 拡散畳み込みの GRU の符号化器と復号器。2 層、64 単位、拡散の段 K = 2、前向きと後ろ向きの 2 つの酔歩の行列。Adam (eps 1e-3)、学習率 0.01 をエポック 20、30、40、50 で 0.1 倍 (下限 2e-6)、batch 64、計画的なサンプリング (逆シグモイド、τ = 2000 step)、勾配のノルムの上限 5、100 エポック、検証の MAE が 50 エポック良くならなければ止め、最良の検証のエポックを使う。著者の設定ファイル `dcrnn_bay.yaml` の値。
  - M3 グラフなし: M2 と同じで、拡散の段 K = 0 (感知器ごとに同じ重みの GRU。隣の感知器を見ない)。
- 計算: GPU 1 枚。試走で 1 エポックの時間を測り、エポックの上限を試験の点を見る前に記録に書いて固定する。種は 1 つ (時間が許せば M2 と M3 を 2 つ目の種で)。

## 区画

### B0: 分け方と指標 (sanity)

- observable quantity: 試料の数 (論文の表 2 の値があれば並べる)、隣接行列の 0 でない要素の数と、ほかの公開の実装の報告値、M0 の MAE (論文 2.88)
- decision rule: M0 の MAE が 2.88 ± 0.3 に入れば先へ進む。入らなければ過去の平均の作り方を見直し、記録に書く (モデルの判定は止めない)
- priority / run order: 順番 1

### B1: 再現 (decisive)

- observable quantity: 15 分、30 分、1 時間先の M2 の MAE。M1、M0 との差
- uncertainty: 試験の期間を 1 日ごとにまとめて引き直すブートストラップ (2,000 回) の 95% 区間。同じ日の時刻どうしは似るので、時刻ごとには振らない
- decision rule: 3 つの先の全てで、M2 の MAE が論文の値の 1.1 倍以下なら「再現した」。1 つでも超えれば「再現しない」とし、予算の不足か手順の違いかを書く
- priority / run order: 順番 2

### B2: グラフの効き (confirmatory)

- observable quantity: M3 − M2 の MAE (3 つの先)。同じ時刻、同じ感知器で対にした差
- uncertainty: 日ごとのブートストラップ
- decision rule: 3 つの先の全てで差の区間が 0 より上なら「グラフが効く」。先が長いほど差が大きいかを書く
- priority / run order: 順番 3
